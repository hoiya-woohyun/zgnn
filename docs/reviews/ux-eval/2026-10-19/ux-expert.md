# UX 전문가 평가 — 2026-10-19 (iPhone 13, 390×844, ko-KR)

계측 방법: Playwright(병렬 평가라 브라우저를 나눠 쓸 수 없음) + 페이지 안 계측 스크립트(`uxe/audit.js` — 컨트롤 크기·이름, 12px 미만 텍스트, 전경/배경 대비, 뷰포트 밖 요소). 화면 8개 + 상세 1개(솔숲펜션)는 신규 사용자 상태와 강아지 등록(두부 · 7kg · 이동 수단 없음) 상태에서 각각 쟀다. 8개 화면 전수 계측에는 goto 를 썼고, 흐름(등록·저장·뒤로)은 화면을 눌러서 따라갔다.

## 1. 첫인상

기본기는 잘 갖췄다. 키보드 포커스 링, 건너뛰기 링크, reduced-motion 대응, 320px 리플로까지 챙긴 앱은 흔하지 않다. 문제는 접근성보다 **일관성(휴리스틱 4)** 쪽에 몰려 있다. 지역을 부르는 말이 화면마다 다르고, 요금을 적는 형식이 같은 가게인데도 카드마다 다르며, 정렬 버튼은 실제로 하지 않는 정렬을 적어 둔다.

## 3. 가장 좋았던 점

1. **reduced-motion 대응이 빠짐없다.** 상세 모프·스와이프·홈 스크롤 연출이 `reduce` 에서 하나도 돌지 않는다(document.getAnimations() 0개).
2. **판정 근거를 화면에 보여 준다(휴리스틱 9·10).** 식당 목록의 "32곳은 같은 이유예요 · 케이지가 필요하다고 적혀 있어요 / 이동가방이 있으면 2곳은 '가능'…" 은 이유와 고치는 길을 함께 준다. 상세에도 "원문" 이 그대로 붙어 있다.
3. **오류 예방과 폼 접근성이 좋다.** 입력칸은 "1번째 강아지 이름/몸무게" 처럼 이름이 붙어 있고, 이동 수단은 radiogroup 이다. 고르지 않고 등록하면 붉은 안내가 두 군데 뜨며, 아무것도 저장되지 않는다.

## 5. 총평

접근성 '위생' 은 상위권이다(이름 없는 컨트롤 0, 12px 미만 0, 누수 0, reduced-motion 완비). 남은 일은 같은 개념을 한 가지 말로 부르는 것이다. 지역 어휘 네 벌과 요금 표기 네 벌이 신뢰를 갉아먹는다.

**점수 7.5 / 10** · 다시 쓸 의향: **조건부**(지역·요금 표기 통일, 정렬 라벨 수정 후 예)

## 6. 평가 한계

- 대비 자동 계측은 배경색 레이어만 따라간다. 그라데이션·이미지·의사 요소 위 텍스트(홈 히어로, 지도 범례)는 눈으로만 봤다. 히어로 두 건은 오탐으로 제외했다. 오류 문구(붉은 글씨)의 대비는 재지 않았다.
- 실제 스크린리더(VoiceOver)는 써 보지 않았다. ariaSnapshot 으로 이름과 역할만 확인했다.
- 지도 그림은 환경상 뜨지 않아 마커의 터치 영역과 대비는 보지 못했다.
- 텍스트 확대 200%(WCAG 1.4.4)와 가로 모드는 재지 않았다. 리플로는 320px 폭으로만 확인했다.
- 카드 표본은 강아지 등록(7kg · 이동 수단 없음) 상태다. '어려움' 으로 접힌 카드(숙소 3 · 식당 35 · 카페 2)는 표본에 없다.
