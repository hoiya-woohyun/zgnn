# ADR-004: 이용 조건은 수동 태깅 대신 규칙 파서 + 원문 병기

> 작성일: 2026-09-15
> 상태: 채택

## 맥락 (Context)

- 반려동물 이용 조건은 장소마다 사람이 쓴 문장이다. 필터와 배지, 그리고 v1 의 판정에는 구조화된 값이 필요하다.
- 선택지는 셋이었다. (a) Notion 에 태그 열을 추가해 작성자가 직접 태깅, (b) 정규화 스크립트에서 한 번 파싱해 JSON 에 박기, (c) 런타임에 규칙 파서로 읽기.
- (a) 는 작성자에게 86건의 재작업을 요구하고 표현이 바뀔 때마다 반복된다. (b) 는 규칙을 고칠 때마다 데이터를 다시 만들어야 한다.

## 결정 (Decision)

- **(c) 런타임 규칙 파서.** `parsePetPolicy(petPolicyText)` 가 정규식 테이블로 `TPetPolicy` 를 만든다. 데이터에는 원문만 둔다.
- **추측 금지.** 원문에 숫자·상한이 없으면 필드를 비운다. 필터 결과가 실제보다 적을 수는 있어도 틀린 "가능" 은 만들지 않는다.
- **원문 병기.** 상세 화면은 파싱 결과 옆에 항상 원문을 보여준다. 파서가 놓친 조건을 사용자가 읽을 수 있어야 한다.
- 규칙은 파일 상단 테이블에 모으고 순서로 우선순위를 표현한다. 새 표현은 정규식 한 줄 + 테스트 한 줄.

## 결과 (Consequences)

- 규칙을 바꾸면 빌드만 다시 하면 된다. 데이터 재생성 불필요.
- 파서 정확도가 곧 판정 정확도다. 테스트(`src/lib/petPolicy.test.ts`, 실제 원문 기반)를 유지한다.
- v1 판정도 같은 원칙을 잇는다: 최악의 결과를 "불가" 가 아니라 "어려움" 이라 부르고 원문·전화 확인을 안내한다(→ [ADR-005](./ADR-005-dog-profile-eligibility.md)).
