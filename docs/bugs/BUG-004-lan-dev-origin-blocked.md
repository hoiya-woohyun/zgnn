# BUG-004 — 폰으로 보면 버튼·스크롤 반응이 죽는다 ("iOS 에서만" 처럼 보인다)

> 최종 수정: 2026-09-17 (v1: 신설)

## 증상

`next dev` 를 LAN 주소(`http://192.168.x.x:7727`)로 폰에서 열면 화면은 다 그려지고 탭·링크도
움직이는데, **손을 대는 것만 조용히 죽는다** — 둘러보기의 필터 버튼을 눌러도 시트가 안 열리고,
준비물·홈을 내려도 접히는 제목 줄이 안 나타난다. 에러 화면도 경고도 없다.

데스크톱(`localhost:7727`)에서는 다 된다. 그래서 **"iOS 사파리 버그" 로 읽힌다.**

## 재현 조건

- `next dev` 를 localhost 가 아닌 출처로 연다 — 폰의 LAN IP, `*.local` mDNS 이름, ngrok 등 터널
- 기기·브라우저는 무관하다. **같은 Chromium 으로 주소만 바꿔도** 그대로 재현된다
- 콘솔에 남는 단서는 이것 하나다:

```
WebSocket connection to 'ws://192.168.20.101:7727/_next/hmr?…' failed:
Error during WebSocket handshake: net::ERR_INVALID_HTTP_RESPONSE
```

## 원인

Next 16 의 개발 서버 출처 보호. localhost 가 아닌 `Origin` 의 `/_next/*` 요청은 **403
`Unauthorized`**, HMR 웹소켓 핸드셰이크도 거절한다(`allowedDevOrigins` 에 없으면). 개발 서버가
소스맵·청크·HMR 채널을 노출하므로, 악성 페이지나 DNS rebinding 이 그걸 읽어가지 못하게 막는
장치다.

이 레포에서 유독 조용한 이유 — 정적 내보내기라 HTML 은 완성돼 내려오고 링크는 `<a href>` 라
JS 없이도 간다. 하지만 시트(`useState`)와 접히는 제목 줄(`useEffect` + IntersectionObserver)은
**하이드레이션이 끝나야 사는 것**이라, 그 단계가 막히면 이 둘만 사라진다. 콘솔의 웹소켓 에러는
"HMR 만 안 되나 보다" 로 넘기기 쉬운데, 같은 게이트가 하이드레이션까지 막는 것이 함정이다.

출처 거부 → 하이드레이션 미완 사이의 Next 내부 고리는 끝까지 추적하지 않았다. 확인한 것은
"허용 전엔 죽고 허용 후엔 살아난다" 는 양 끝이다.

## 수정

`next.config.mjs` 에 사설 대역을 통째로 허용한다.

```js
allowedDevOrigins: ['192.168.*.*', '10.*.*.*'],
```

특정 IP 를 박지 않는 이유 — 공유기가 주소를 다시 나눠 줄 때마다 같은 고장이 돌아오고, 그때
단서가 위 한 줄뿐이라 원인을 다시 찾게 된다. `'*'` 로 뚫지 않는 이유 — 게이트의 의미가
사라진다. `output: 'export'` 산출물에는 이 게이트 자체가 없어 프로덕션은 무관하다.

## 아직 열려 있는 것

| 상황 | 결과 |
|---|---|
| `172.16~31.*.*` 대역(일부 공유기·회사망·Docker) | 다시 막힘 → 대역을 한 줄 더한다 |
| `macbook.local` 같은 mDNS 이름 | 다시 막힘 → 이름을 더한다 |
| ngrok·Cloudflare Tunnel | 다시 막힘 → 터널 도메인을 더한다 |
| Next 메이저 업그레이드로 옵션명 변경 | 조용히 무효화될 수 있다 |

어느 경우든 **증상은 이 문서의 것과 같다.** 폰에서 반응이 죽었는데 콘솔에 `_next/hmr` 웹소켓
에러만 있으면 기기를 의심하기 전에 출처를 본다.
