## 2. 이 앱이 이미 가진 고유한 것 — 지킬 것

스킬은 "한 곳에만 대담하고 나머지는 조용히" 를 권한다. 이 앱에서는 그 한 곳이 이미 정해져 있다.

1. **현무암 질감 잉크 히어로**(`src/styles/globals.css:91` `basalt`, `homePageHero.tsx`). 제주 화산암의 구멍을 CSS 점 네 겹으로 흉내 냈고,
   크림 앱에서 유일한 어두운 면이다. 소재가 이 앱의 주제(제주)에서 나왔다는 점에서 스킬이 말하는 "주제에서 나온 선택" 의 정확한 예다. **[브리프 결정]**(ADR-003 잉크 유지)
2. **종류 3색 + 아이콘 타일**이 사진 자리를 대신한다(ADR-002·ADR-003 v6). 홈·목록·상세·근처·지도 핀이 같은 규칙을 쓴다. **[브리프 결정]**
3. **준비물의 섹션 순서가 실제 순서다** — 오가는 길에 → 어디를 가든 → 식당·카페에서 → 숙소에서(`checklistPage.tsx:105`). 각 섹션의 `0/2` 개수와
   "숙소에 있어요" 흐림은 장식이 아니라 상태다. 스킬의 "번호·구분 장치는 내용이 진짜 순서일 때만" 을 이미 지킨다.
4. **판정 점(●)과 굵기로 색 의존을 줄인 배지**(ADR-003 v10). 색만으로 가르지 않는다.
5. **빈 상태가 다음 행동을 준다** — `EmptyState` 의 주석부터 "다음에 할 일을 하나 제안한다"(`emptyState.tsx:11`). 저장 0곳("하트를 눌러 모아보세요" + 장소 둘러보기),
   404("홈으로 / 둘러보기로"), 검색 0건("띄어쓰기를 바꾸거나 더 짧게"), 오프라인 지도("저장한 곳과 장소 목록은 그대로 볼 수 있어요") 모두 그렇다.
6. **모션이 사람의 동작에 답한다.** 탭 알약 이동·화면 스와이프·접히는 헤더는 모두 사용자의 탭이나 스크롤이 일으킨다. 저절로 일어나는 등장 애니메이션은
   목록의 종류 전환 한 곳(`placesPage.tsx:171`, `fade-in` + 4단 slide)뿐이고, 그것도 탭 전환에 대한 응답이다. 스킬이 꼽는 "섹션마다 fade-up" 은 없다.

## 4. 타이포그래피

**서체 선택.** Pretendard 서브셋 한 벌, 400·600(`src/app/layout.tsx:28`, ADR-006 v6). 한국어 웹에서는 가장 흔한 기본값에 가깝다. 그래도 ADR-006 은
**크기 착시(한글 높이 0.914 → 0.850em)와 오프라인 프리캐시**라는 이 앱의 이유로 이 글꼴을 골랐다. **[브리프 결정]** 디스플레이 서체를 하나 더하면
스킬의 "타입이 인격을 싣는다" 에는 가까워진다. 대신 프리캐시가 지금 1.26MB 에서 늘어나고, 오프라인에서 글꼴이 바뀌는 위험이 생긴다. → 사용자 판단(§10).

  18 다음이 20 인 것은 사실상 같은 단계다. `text-xl` 이 두 번만 쓰이는 것도 그래서다.
- **판정 문장이 가격과 섹션 제목보다 작다(실측).** 숙소 상세에서 h1 24/600, h2 18/600, **가격 `59,000원 ~ 79,000원` 18/600, 판정 "두부는 갈 수 있어요" 16/600**

  이 앱에서 headline 이 되어야 할 문장은 장소 이름 다음의 판정이다. r4 의 "상세 맨 위를 판정 배지 + 가격 + 한 줄 이유로" 와 같은 방향이다.
  이 리뷰가 보태는 근거는 **타입 위계가 판정을 섹션 제목보다 아래에 두고 있다**는 것이다. **[미결정 기본값]** → §10 의 ②.

  **[미결정 기본값]** — `font-normal` 이나 `font-semibold` 중 하나로 정해 의도를 화면과 맞춘다.

## 5. 구조 장치·레이아웃 — "구조는 정보인가"

1. **흰 카드 상자가 위계를 담지 못한다.** `rounded-2xl border border-secondary bg-primary` 가 글자 그대로 19곳에 있다
   (`homePage.tsx:58·74·105·128`, `placeDetailPage.tsx:53·76`, `placeDetailEligibilityCard.tsx:68`, `placeDetailReport.tsx:47`, `placeDetailNearby.tsx:72`,
   `placeDetailHomepage.tsx:26`, `checklistPage.tsx:127`, `checklistPageItemRow.tsx:68`, `settingsPage.tsx:16·51·128`, `dogProfilePage.tsx:230`,
   `dogProfileSizeOverride.tsx:32`, `placeCard.tsx:42`, `emptyState.tsx:14`). 그 결과는 이렇다.
   - 숙소 상세의 "반려동물 이용" 밑에 **같은 모양의 상자 셋**이 쌓인다(판정 / 요금 원문 / 준비물, C-06). 판정이 답이고 나머지 둘은 근거인데, 상자 모양으로는 같은 무게다.
   - 404·저장 0곳의 빈 상태도 같은 상자 안에 들어 있다. 빈 화면 한가운데의 흰 상자는 "내용이 하나 있다" 처럼 보인다.
   - 스킬의 #4 와 정확히 겹치는 지점이다. **[미결정 기본값]** — 제안: 답(판정)만 면을 갖고, 근거는 상자 없이 구분선이나 들여쓰기로 판정 상자에 딸린 것으로 보이게 한다.
     빈 상태는 상자 없이 크림 위에 직접 놓는다. 공용 상자를 `Section`·`Card` 역할로 나누면 19곳이 한 번에 따라온다. → §10 의 ③.
2. **그림자는 인사 카드 하나에만 있다**(`homePage.tsx:58` `shadow-lg`). 다른 카드는 모두 테두리만 쓴다. 그림자가 위계 신호라면
   이 카드가 홈에서 **가장 높이 떠 있는 것**이 된다. r4 가 지적한 "인사 카드가 가장 큰 덩어리" 는 크기만의 문제가 아니라 이 그림자 때문이기도 하다. **[미결정 기본값]** → §10 의 ④.
   인사말의 **내용**은 작성자 원문(`src/data/meta.json`)이라 **[브리프 결정]** 이다. 자리와 무게만 미결정이다.
3. **상세 머리의 `동쪽 구좌읍 | 펜션`** 의 세로 막대(`placeDetailHeader.tsx:171`)는 의미 구분선으로 쓰였다. 정보가 있으니 유지해도 된다. 낮음.
4. **글 끝 화살표 4곳** — `전체 목록 →`(`placeItemsNote.tsx:87`, 아이콘), `우리 강아지 정보 고치기 ›`(`placesPageResults.tsx:124`),
   등록 유도 줄의 `›`(`placeDetailEligibilityCard.tsx:51`), `지도에 없는 5곳 ›`(`mapPage.tsx:360`). 설정 화면의 행 오른쪽 셰브론처럼 **행 전체가 이동 버튼**이면
   플랫폼 관습이라 괜찮다. 문장 끝에 화살표를 덧붙인 것은 스킬 #5 의 그 모양이다. 링크라는 것은 색(brand)이 이미 말하고 있다. **[미결정 기본값]**, 낮음.
5. **홈 종류 카드의 `가능 21 · 확인 1`** 은 숫자를 18px 종류 색으로 키웠다(`homeTypeCard.tsx:67·72`). 정보는 담고 있다. 다만 같은 홈에 히어로 숫자판까지 있어
   "큰 숫자 + 작은 라벨" 이 한 화면에 두 벌이 된다. ①을 정리하면 이쪽이 살아난다.
6. **넓은 화면의 히어로 테두리선(결함).** 768·1280 폭 정지 상태에서 히어로 바깥으로 **가는 사각 선**이 보인다. 위·아래 가로선과 좌우 세로선이 본문 폭을 따라 그어진다(W768-01, W1280-01). 390 폭에서는 보이지 않는다.
   원인은 추정이다. 크림 커튼(`homePageHero.tsx:225-226`, `w-4 md:w-6`)이 `--spacing` 4.25px 에서 25.5px 처럼 **반 픽셀**에 떨어진다.
   그러면 밑에 깔린 잉크 판(`basalt`, 같은 파일 223행)이 경계에서 한 줄 비친다. ADR-006 의 4.25px 단과 접히는 히어로가 만나서 생긴 것이다. 디자인 결정이 아니라 결함이다. → §10 결함 줄.

## 6. 모션

- **절제는 이미 되어 있다**(§2-6). 페이지 로드 때 저절로 움직이는 것은 없다.
- **reduced-motion 실측.**

  | 대상 | 일반 | `reduce` | 판단 |
  |---|---|---|---|
  | 하단 시트(필터) 열림 | 200~250ms slide·fade | `animation-duration`·`transition-duration` **1e-05s**(전역 규칙 `globals.css:79`가 인라인 transition 까지 이긴다) | ✅ 즉시 |
  | 둘러보기 종류 전환 | 300ms fade + slide | `motion-reduce:animate-none`(`placesPage.tsx:171`) + 전역 규칙 | ✅ |
  | 탭 알약 이동 | WAAPI | 시작 전에 `matchMedia` 로 건너뜀(`placesPageTypeTabs.tsx:47`) | ✅ |
  | 화면 간·종류 간 스와이프 정착 | `SETTLE_MS` | `duration: 0`(`appShellSwipe.ts:180`, `placesPageSwipe.ts:129`) | ✅ (코드 판독, 실측 아님) |
  | 홈 히어로 접힘·준비물 제목 | 스크롤 구동(`animation-timeline: scroll()`) | 전역 규칙이 duration 을 1e-05s 로 덮어도 **같은 스크롤 위치에서 같은 모양**(커튼 `matrix(0.457…)` 일치, 스크린샷 동일) | ✅ 의도대로 남는다. 손가락이 움직인 만큼만 움직이는 모션이라 줄이지 않는다는 결정(`stickyMorphTitle.tsx:20`). 전역 규칙과 충돌하지 않는다는 것을 실측으로 확인했다 |

- 손댈 것 없음. 결함으로 이어질 위험은 하나뿐이다. 전역 규칙이 `animation-duration` 을 `!important` 로 덮는데 스크롤 구동은 `auto` 를 기대한다. 지금 Chromium 에서는 문제가 없지만, Safari 가 `animation-timeline` 을 지원하기 시작하면 다시 확인할 자리다.

## 7. 카피

1. **'확인' 이 반대 뜻으로 쓰인다.** 목록·홈의 `확인 31`(`placesPageResults.tsx:21`, `homeTypeCard.tsx:64·71`)은 "확인이 **필요한** 곳" 이다.
   그런데 상세의 신선도 줄은 `2026년 10월에 확인했어요`(`placeFreshness.ts:16`), 곧 "확인을 **마친**" 곳이다. 한 앱에서 같은 낱말이 검증됨과 미검증을 함께 뜻한다.
   배지는 `확인이 필요해요` 로 온전히 말하는데 개수 줄만 줄였다. `aria-label` 도 `확인 31` 이라 스크린리더 사용자에게도 같은 모호함이 간다.
   스킬의 "한 동작은 흐름 전체에서 같은 이름" 의 반대 사례다. **[미결정 기본값]** → §10 의 ⑤. 제안: `가능 3 · 확인 필요 31`, 또는 판정 배지 낱말을 그대로 쓴다.
2. **강아지 등록 흐름의 이름이 네 번 바뀐다.** 홈 `우리 강아지 등록하기` → 화면 제목 `우리 강아지 등록` / `강아지 프로필 수정`(`dogProfilePage.tsx:194`) →
   버튼 **`저장`**(`dogProfilePage.tsx:248`) → 목록 `우리 강아지 정보 고치기 ›`(`placesPageResults.tsx:124`). 특히 `저장` 은 이 앱에서 이미 **하트(장소 저장)** 를 뜻한다
   (`저장함`·`저장했어요`·`저장한 곳 보기`, `saveButton.tsx:24`). 등록 버튼까지 `저장` 이면 핵심 명사가 둘로 갈린다. **[미결정 기본값]** — 버튼은 `등록하기`/`고치기`
   (화면 제목과 같은 동사)로 하고, `프로필` 과 `정보` 중 하나로 맞춘다.
3. **`사실 — 행동` 문장 9곳.** 판정 이유가 `케이지라고 적혀 있어요 — 이동가방도 되는지 확인해 주세요`(`eligibility.ts:217·233·295·324·330·345·354·364`)처럼
   띄운 줄표로 이어진다. 제보 시트 머리도 `{장소} — 무엇이 다른지 골라 주세요.`(`placeDetailReport.tsx:76`)다. 한국어 UI 에서 줄표는 드물어 번역문이나 문서체로 읽힌다.
   이 레포의 문서·주석 문체(줄표가 아주 많다)가 화면 글로 새어 나온 것으로 보인다. 구조(관찰 → 할 일)는 좋다. 그 구조를 **두 문장**으로 쓰거나 이유 줄과 할 일 줄로 나누면 된다.
   스킬 #5 의 `WORD — fragment` 와 모양이 같다. **[미결정 기본값]**, 중간. `eligibility.ts` 문구는 테스트가 문자열을 볼 수 있으니 고칠 때 함께 본다.
4. **`이(가)` 자리표시.** `{이름} {몸무게}kg 이(가) 맞나요?`(`dogProfilePage.tsx:236`). 레포에는 이미 `withJosa`·`josa`(`placesPageResults.tsx:149·161`)가 있다. **[미결정 기본값]**, 낮음, 한 줄 수정.
5. **잘 된 것(유지).** 오류·빈 상태가 사과하지 않고 원인과 다음 행동을 말한다. 예: `화면을 그리다 멈췄어요. 새로고침하면 대부분 다시 열려요.`(`global-error.tsx:27`),
   `지도는 인터넷이 필요해요`(`mapPageCanvas.tsx:419`). 되돌리기 토스트는 모두 `~했어요` + `되돌리기` 로 같은 문법이다(`프로필을 지웠어요` · `저장한 곳을 비웠어요` · `준비물 체크를 모두 풀었어요`). 저장 빈 상태의 머리말(`아직 저장한 곳이 없어요`)과
   상자 제목(`하트를 눌러 모아보세요`)은 같은 말을 두 번 하는데, 둘째가 행동을 말하므로 머리말 부제를 빼도 된다. 낮음.

## 9. r4 대조(10-04 디자인 크리틱)

- r4 "인사 카드가 홈에서 가장 큼" — **확인**, 원인에 그림자 하나를 보탠다(§5-2).
- r4 "상세 판정이 작다, 가격이 아래로" — **확인**. 타입 실측으로 뒷받침한다(판정 16 < 가격 18, §4).
- r4 "마젠타가 판정·CTA·하트·지도 칩을 다 맡는다" — **일부 반박.** 지도 칩은 지금 종류 색 점이다(A-05). 핑크 배지가 판정 ok 전용인 것은 ADR-003 v10 의 결정이다. 하트 = 브랜드도 결정이다(메모리, ADR-003).
- r4 "준비물 이모지가 라인 아이콘과 따로 논다" — **확인하되 [브리프 결정]**. 이모지는 작성자 Notion 원 자료(`items.json` 의 `emoji`)다. 바꾸려면 데이터 결정이 필요하다 → 사용자 판단.
- r4 "지도 로딩 멈춤 · 저장 버튼 가림" — 10-04 §7 에서 이미 촬영 착시로 걸렀다. 이번 촬영에서도 스크롤 뒤 지도가 떴다(C-06·C-07).
- r4 "상세에서 같은 요금이 세 번" — 이번 C-06 에서는 판정 줄과 원문 상자 두 번이다. 원문 인용은 근거라 일부러 둔 것으로 본다. §5-1 의 상자 정리와 함께 풀린다.
- r4 "쿠팡 고지문이 작다(~11px)" — **반박.** 지금은 14px `text-tertiary`(C-09)다.
- r4 "목록 설명이 두 줄에서 잘린다" — 카드 밀도를 위한 선택이다. 이번 렌즈와 무관해 넘긴다.

### 사용자 판단으로 넘길 것 — [브리프 결정]

- **디스플레이 서체를 더할지.** 스킬의 타이포 축(타입이 인격을 싣는다)에는 가까워진다. 대신 1.26MB 프리캐시에 굵기 한 벌을 더하고, 서브셋 정책(완성형 11,172자)도 다시 정해야 한다. ADR-006 은 크기·오프라인을 이유로 한 벌을 골랐다.
- **타입 단계 비율.** 12·14·16·18 의 촘촘한 단계를 넓힐지(예: 본문 14 → 제목 18 → 21 → 24). `--spacing` 파생이라 토큰 몇 줄로 끝나지만 화면 전체가 바뀐다. ADR-006 에 "390/820/1280 세 폭 실측" 이 걸려 있다.
- **준비물 이모지.** 작성자 원 자료다. 라인 아이콘으로 바꾸면 r4 의 혼용 지적은 풀리지만 작성자의 목소리가 줄어든다.
- **크림 바탕·핑크·잉크·사진 없음** — 바꿀 근거를 찾지 못했다. 스킬의 기본값 #1 과 겹치는 것은 크림 하나뿐이고, 세리프·테라코타 없이 핑크 358° + 현무암 잉크로 이 앱만의 조합이 됐다. 그대로 둔다.
