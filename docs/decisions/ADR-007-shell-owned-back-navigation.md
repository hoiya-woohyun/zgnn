# ADR-007 — 뒤로가기는 화면이 아니라 셸이 붙인다

> 최종 수정: 2026-09-17 (v2: 뒤로가기 줄이 스크롤을 따라온다 — `sticky`, 버튼에만 알약 배경)
> 이전 (v1: 신설)

## 맥락

앱은 하단 탭바(모바일) · 사이드바(≥768px)로 메인 화면 다섯 곳을 오간다.
그 안으로 한 단계 들어간 화면 — 장소 상세(`/place/:id`), 강아지 프로필(`/dog`) — 은 탭바에 없다.

**되돌아 나올 길이 없었다.**

- `/dog` 에는 뒤로가기가 아예 없었다. 탭을 눌러 다른 화면으로 도망치는 것 말고는 방법이 없고,
  홈에서 "우리 강아지 등록" 을 눌러 들어온 사람은 그 사실을 모른다.
- 상세에만 뒤로가기가 있었는데, 그것도 `AppBar` 가 `md:hidden` 이라 **모바일 전용**이었다.
  데스크톱용으로는 제목 판 안에 "목록으로" 링크를 손으로 하나 더 달아 두었다.
  그래서 **태블릿(768px 이상)** 은 상세를 빼면 어느 하위 화면에서도 나올 수 없었다.
- 홈 화면에 설치한 PWA 에는 브라우저 뒤로가기도 없다. 화면 안에 없으면 정말로 없는 것이다.

근본 원인은 뒤로가기를 **화면이 각자 챙기는 구조**였다는 점이다. 화면을 새로 만들 때마다
"여긴 하위 화면이니 `AppBar` 를 달아야 한다" 를 기억해야 했고, `/dog` 에서 실제로 빠뜨렸다.

## 결정

**뒤로가기의 책임을 화면에서 셸로 옮긴다.**

1. `src/lib/appRoutes.ts` 가 경로 하나를 보고 루트인지 판정한다. 루트는 **메인 탭 5개뿐**이고,
   **모르는 경로는 전부 하위 화면**으로 친다.
2. `AppShell` 이 루트가 아닌 모든 경로에 `AppBar` 를 얹는다. **폭 제한 없이** — 사이드바는
   어느 탭에 있는지만 알려줄 뿐, 탭 안에서 나오는 길은 되지 못한다.
3. `AppBar` 는 뒤로가기 버튼만 그린다. 셸은 경로만 알고 제목은 모르기 때문이다.
   제목은 화면 본문이 담당한다.

```
AppShell ─ isRootRoute(pathname)?
            ├ 예 → 그대로
            └ 아니오 → <AppBar backTo={parentRouteOf(pathname)} /> + 화면
```

기본값의 방향이 이 결정의 핵심이다. "모르면 하위 화면" 이라야 새 화면에 뒤로가기가 저절로 붙는다.
반대로 뒀다면 원래 문제("기억해야 한다")가 그대로 남는다. 탭바에 넣을 때에만 표에 한 줄을 더한다.

### `navItems.isActive` 를 재사용하지 않는 이유

둘러보기 항목의 `isActive` 는 상세(`/place/:id`)까지 참으로 본다 — 상세에서도 둘러보기 탭에
불이 들어와야 하기 때문이다. 그건 "어느 탭에 불이 들어오나" 이고, 여기 필요한 건
"되돌아 나올 곳이 있나" 다. 질문이 다르므로 표를 따로 둔다. 재사용했다면 상세가 루트로
분류돼 뒤로가기를 잃는다.

## 결과

- `/dog` 를 포함한 모든 하위 화면에 모든 폭에서 뒤로가기가 생겼다.
- 상세의 데스크톱 전용 "목록으로" 링크는 지웠다 — 같은 일을 하는 것이 둘이 되었다.
- 상세의 `h1` 이 하나로 합쳐졌다. 전에는 모바일에서 `AppBar` 가 진짜 `h1` 이고 큰 이름이
  `aria-hidden` 장식, 데스크톱에서는 그 반대였다. 이제 셸의 줄에 제목이 없으므로
  큰 이름이 폭과 무관하게 유일한 `h1` 이다.
- `AppBar` 는 투명하다. 화면마다 맨 위 바탕색이 달라서다. 대신 종류 색 판을 쓰는 상세는
  그 줄 높이만큼 `-mt-14 pt-14` 로 끌어올려 색이 화면 맨 위까지 이어지게 했다 —
  전면 색을 쓰는 화면을 새로 만들면 같은 처리가 필요하다. 지금은 상세 한 곳뿐이다.
- 딥링크 보정(`appHistory.ts`)은 그대로 쓰되, 올라갈 부모를 `parentRouteOf` 가 정한다.
  상세는 장소 종류에 따라 갈리므로(카페 상세 → `/places/cafe`) 경로만 보지 않고 데이터를 본다.

## v2 — 줄이 스크롤을 따라온다 (2026-09-17)

상세 화면은 길다. 판정 카드 · 원문 · 요금 · 근처 장소를 다 읽고 되돌아 나오려면
**맨 위까지 다시 올려야** 했다. 뒤로가기가 있어도 닿지 않으면 없는 것과 같다.

`AppBar` 를 `sticky top-0 z-30` 으로 바꾼다.

### `fixed` 가 아니라 `sticky` 인 이유

`fixed` 면 이 줄이 문서 흐름에서 빠져 **높이가 0** 이 된다. 그러면 위 v1 결과에 적어 둔
상세 제목 판의 `-mt-14 pt-14` 가 존재하지 않는 높이를 상쇄하게 되고, 종류 색 판이 통째로
화면 위로 밀려 나간다. 빌드도 테스트도 통과하고 **상세 화면에서만** 깨진다.
`sticky` 는 흐름 안에 남으므로 그 계산이 그대로 성립한다 — 자리 채우는 빈 칸도 필요 없다.

### 줄은 계속 투명하고, 배경은 버튼에만

따라다니는 줄에 배경을 칠하면 v1 의 전제가 무너진다 — 화면마다 맨 위 바탕색이 다르고,
상세의 종류 색 판 위에 크림색 띠가 얹힌다. 그래서 줄은 투명하게 두고, **무엇 위에 얹힐지
모르는 버튼에만** 반투명 알약 배경(`bg-primary/85` + `backdrop-blur-sm` + 테두리)을 준다.

줄 전체에는 `pointer-events-none`, 버튼·제목·액션에만 `pointer-events-auto` 를 준다.
그러지 않으면 투명한 빈 줄이 화면 폭 전체에서 아래로 지나가는 내용의 터치를 가로챈다.

위쪽 여백의 `pt-safe`(safe-area-inset-top)는 v1 그대로다. 따라다니는 줄이 된 뒤로는
이것이 더 중요해졌다 — 스크롤을 내려도 노치·상태바 밑에 뒤로가기가 깔리지 않아야 한다.
