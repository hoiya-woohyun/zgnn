# 주간 사용성 평가

> 최종 수정: 2026-10-06 (v1: 신설 — 기획 문서를 안 본 페르소나 6명이 매주 한 번 앱을 써 보고, 회차마다 여기에 남는다)

**월요일에 시작하는 주마다 한 번**, 기획 의도를 모르는 평가자(Fable 서브에이전트) 6명이 빌드한 앱을 Playwright 로
써 보고 보고서를 쓴다. 실행 절차는 프로젝트 스킬 [`.claude/skills/ux-eval/SKILL.md`](../../../.claude/skills/ux-eval/SKILL.md)(`/ux-eval`)가 정본이다.

## 왜 이렇게 하나

- **평가는 메인 세션이 하지 않는다.** CLAUDE.md·ADR 을 읽은 세션은 "왜 이렇게 만들었는지" 를 알아서 사용자가 막히는 자리를
  의도로 덮어 읽는다. 평가자는 `fork` 가 아닌 새 에이전트로 띄워 그 맥락을 물려받지 않는다. 평가자는 이 디렉터리(지난 회차)도 읽지 않는다.
- **페르소나와 과제는 매주 같다.** 같은 과제를 반복해야 "지난주 지적이 해소됐나 · 몇 주째 반복되나" 를 셀 수 있다.
  비교와 기존 todo 대조는 평가가 끝난 뒤 메인이 종합 단계에서 한다.
- **스크린샷은 레포에 없다.** `/tmp/ux-eval/<날짜>/shots/` 에만 남는다. 보고서의 파일명은 그 경로 기준이다.

## 실행을 잊지 않게 — SessionStart 훅

[`.claude/hooks/uxEvalWeekly.mjs`](../../../.claude/hooks/uxEvalWeekly.mjs) 가 세션을 열 때(시작·재개·`/clear`) 이번 주
(KST 월요일~오늘)에 `<날짜>/00-종합.md` 가 있는지 본다. 없으면 터미널에 한 줄을 띄우고 Claude 에게 실행을 권하게 한다.

- 완료의 기준은 **디렉터리가 아니라 `00-종합.md`** 다. 평가자가 한도에 걸려 5명 미만이면 종합을 쓰지 않으므로 그 주는 계속 미완료로 남는다.
- 날짜는 mtime 이 아니라 **디렉터리 이름**에서 읽는다(checkout·worktree 가 mtime 을 바꾼다).
- 이번 주만 보므로 **몇 주를 건너뛰어도 권고는 이번 주 한 번**이다. 밀린 주를 소급해 돌리지 않는다.
- 날짜를 바꿔 시험: `UX_EVAL_TODAY=2026-10-12 node .claude/hooks/uxEvalWeekly.mjs`

## 회차가 남기는 것

| 위치 | 내용 |
|---|---|
| `docs/reviews/ux-eval/<날짜>/00-종합.md` | 합의도 순 지적 · 고유 발견 · 바꾸지 말 것 · 재현 필요 · 영향 순 개선 표 · 지난 회차 대비 신규/반복/해소 |
| `docs/reviews/ux-eval/<날짜>/<이름>.md` | 페르소나 보고서 6개(minji · seongho · youngja · junhyuk · haeun · ux-expert) |
| [`docs/todo/14-weekly-ux-eval.md`](../../todo/14-weekly-ux-eval.md) | 회차별 개선 태스크. 기존 07·08·10·11·12 와 겹치면 새로 만들지 않고 그 ID 를 가리킨다 |

앱 코드는 평가 회차에서 고치지 않는다 — 고칠 것은 14 의 태스크로 남기고 따로 작업한다.
