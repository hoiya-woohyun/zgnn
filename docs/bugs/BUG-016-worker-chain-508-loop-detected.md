# BUG-016 — 서버 워커 사슬이 5홉째에서 Vercel 508(루프 감지)로 끊겨, 남은 일이 조용히 멈췄다

> 최종 수정: 2026-10-09 (v1: 신설 — [todo/20](../todo/20-vercel-remote-worker.md) T9 첫 실측에서 발견)
> 상태: 고침(`scripts/lib/workerRemote.mjs` `MAX_HOPS` 12 → 4 · `worker/entry/run.mjs` 사슬 실패 로그). 워커 재배포 전에는 프로덕션이 옛 값이다.

## 증상

2026-10-08 18:49 `/admin` 깨우기 한 번에 서버 워커가 홉 4개(글 20건, 후보 4)를 돌고 멈췄다. 요청 글 37건과 「저수지 10건」 요청이 `queued` 그대로 남았고,
`/admin` 의 서버 배지는 홉이 끝나 사라져 **다 끝난 것처럼** 보였다. 빌드·테스트·함수 로그의 각 홉은 전부 성공이다. 흔적은 4홉째 마지막 줄 하나뿐이었다:
`[worker] 다음 홉(5) 호출 — 508`.

## 원인

Vercel 이 **함수가 자기 자신을 부르는 사슬**을 루프로 보고 끊는다(`INFINITE_LOOP_DETECTED`, 508). 실측은 브라우저 깨우기 1 + 자기 호출 3 = 4홉이 돌고
네 번째 자기 호출이 508 — 같은 패턴의 [커뮤니티 사례](https://community.vercel.com/t/why-vercel-triggers-508-infinite-loop-detected-on-recursive-nuxt-api-calls/37450)도
"4번째 실행 뒤 508" 이다. 우리 호출은 `Authorization`·`X-Zgnn-Hop` 두 헤더만 싣으므로 깊이는 Vercel 이 스스로 센다. 감지 방식은 [문서](https://vercel.com/docs/errors/INFINITE_LOOP_DETECTED)에 없다.

[ADR-028](../decisions/ADR-028-vercel-remote-worker.md) 결정 5 는 상한을 우리 쪽(`MAX_HOPS = 12`, 보안 리뷰의 폭주 둑)에만 뒀고, 플랫폼 상한을 몰랐다.
사슬 호출은 응답 코드만 찍고 2xx 가 아니어도 같은 모양의 줄이었다.

## 고침

- `MAX_HOPS = 4` — 플랫폼 상한에 맞춘다. 4홉째는 `shouldChain` 이 "사슬 4홉 상한 — 남은 일은 다음 버튼이나 로컬 워커가" 로 **스스로** 멈춘다. 깨우기 한 번 = 글 최대 20건.
- 사슬 호출이 2xx 가 아니면 `⚠️ … 508(Vercel 루프 감지) · 사슬이 끊겼다` 로 갈라 찍는다.
- **피해 가지 않는다** — 다른 HTTP 클라이언트·사이트 rewrite 를 돌아 부르기·헤더 바꾸기는 플랫폼 안전장치를 우회하는 일이고, 감지 방식이 비공개라 언제든 다시 깨진다.

## 남는 것

- 깨우기 한 번에 20건이 끝이다. 그 뒤는 다음 버튼(또는 로컬 워커)이 잇는다 — 브라우저에서 새로 깨우면 깊이가 0 부터 다시 세어지는지는 **아직 실측 전**이다(todo/20 T9).
  그게 서면 `/admin` 이 "서버가 쉬는데 일이 남았다" 를 보고 다시 깨우는 길(또는 「이어서」 버튼)을 연다.

## 교훈

자기 호출 사슬의 상한은 우리 코드만이 아니라 **플랫폼도** 정한다. 사슬 호출의 실패는 성공과 다른 모양으로 찍어야 한다 — 같은 줄에 숫자만 다르면 아무도 안 읽는다.
