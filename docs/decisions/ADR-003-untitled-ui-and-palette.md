# ADR-003: Untitled UI 토큰 위에 핑크 · 크림 · 잉크 팔레트

> 작성일: 2026-09-15
> 상태: 채택
>
> 최종 수정: 2026-09-17 (v7: 히어로가 화면 끝까지 깔리지 않고 크림 위의 라운드 판이 된다. PWA `theme_color` 는 잉크에서 크림으로 — 팔레트 값 자체는 그대로)
> 이전 (v6: 종류 색 3개를 삼원색에 가깝게 재조정 — 바다/감귤/라떼(H219·64·55)에서

> 이전 (v2: 감귤 주황 → 더스티 로즈 + 크림 바탕. 라벤더 시안은 "너무 어둡다" 로 거절)
> 이전 (v1: 감귤 주황 브랜드 + 현무암 회색)

## 맥락 (Context)

- 표현 계층을 처음부터 만들 이유가 없어 Untitled UI(React, CLI 로 소스 복사) 를 골랐다. 시맨틱 토큰 체계(`text-primary`, `bg-brand-solid` …)가 갖춰져 있고 react-aria 기반이라 접근성이 따라온다.
- 타깃 취향은 "20대 여성이 좋아할 색, 대신 분홍만 많이 쓰면 취향을 타니 깔끔하게".
- 시행착오: 라벤더는 어둡다고 거절, 더스티 로즈(`#b03a58`)는 화면에서 와인·버건디로 읽혀 "분홍으로" 재요청. 흰 글씨 대비 4.5:1 을 지키려 어둡게 내리면 분홍이 아니게 되는 것이 문제였다.

## 결정 (Decision)

- **글꼴은 이 ADR 밖이다.** `--font-body`/`--font-sans`/`--font-display` 는 나눔스퀘어 네오를 가리키며, 그 판단은 [ADR-006](./ADR-006-responsive-scale-and-font.md) 에 있다. 크기 토큰(`--text-*`)이 `--spacing` 파생이라는 것도 같은 문서.
- **원시 색은 `src/styles/theme.css` 에만.** 화면은 시맨틱 토큰만 쓴다. Tailwind 기본 `neutral` 스케일을 프로젝트 `@theme` 에서 크림·오트밀로 덮어써서 바탕색이 곧 크림이 되게 한다.
- **브랜드 = 핑크, oklch 색상 358°.** 600(`#cd2a77`, 흰 글씨 5.0:1)만 솔리드 버튼에 쓰고, 300~500 의 밝은 단계를 하트·발자국·워시에 써서 전체 인상을 분홍으로 만든다. `bg-brand-solid` 는 600 — 700 으로 내리면 다시 버건디다.
- **로고·히어로 바탕은 잉크 `#2e2327`(`--color-ink`).** 브랜드가 바뀌어도 유지.
  - **v7 — 히어로는 화면 끝까지 깔리지 않는다.** 크림 여백 위에 뜬 **라운드 판**이고, 좌우
    여백도 다른 화면과 같은 `px-4 md:px-6` 를 쓴다. 잉크 자체를 버린 것이 아니라 "맨 위 면이
    잉크" 라는 어법만 놓았다 — 맨 위 면을 전 화면 크림으로 통일하기 위해서다
    (→ [ADR-010 v3](./ADR-010-shell-owned-safe-area.md)). 팔레트 값은 하나도 바뀌지 않아
    `pnpm icons` 재생성도 필요 없었다.
  - **v7 — PWA `theme_color` 는 더 이상 이 값이 아니다.** 크림(`#faf8f4`, `--color-neutral-50`)
    이다. 같은 이유이고, `src/app/layout.tsx` 의 `viewport.themeColor` 와 `src/app/manifest.ts`
    가 짝으로 움직인다.
- **종류 색은 브랜드와 별개 토큰이고, 종류가 셋뿐이라 삼원색에 가깝게 벌린다(v6).**
  숙소 파랑 `#3670c4`(H258) / 식당 빨강 `#c14f18`(H42) / 카페 초록 `#338946`(H148).
  서로 106~110° 씩 떨어져 있어 나란히 놓이지 않아도 어느 종류인지 읽히고, 지도 핀이
  파랑·빨강·초록인 것은 지도의 오랜 관습이기도 하다.

  **왜 옛 값(바다 `#3b8ea5` / 감귤 앰버 `#cf8330` / 라떼 `#9a6846`)을 버렸나.**
  이 앱의 크림·회색은 oklch H≈70~78 인데 옛 식당(H64)·카페(H55)가 **그 색상축 위에 앉아
  있었다.** 그래서 채도를 올려도(2026-09-15 리뷰에서 카페 크로마를 0.045 → 0.08 로 올린 것이
  그 시도였다) "살짝 물든 종이"로 읽혔고, 그 수리는 끝내 듣지 않았다 — 22% 워시가 크림과
  ΔE 3.4(식당)·5.5(카페)에 그쳤고 셋 중 가장 가까운 쌍은 ΔE 2.9 로 사실상 같은 색이었다.
  지금은 워시끼리 최소 ΔE 5.0, 크림과는 5.8~7.0 이다. 노랑(H95)도 같은 이유로 후보에서
  탈락했다(크림과 ΔE 3.0).

  **지켜야 하는 두 가지.** (1) 채도는 브랜드보다 낮게 — 핑크 C≈0.205, 종류 색 0.130~0.159.
  종류 색은 분류 표지지 행동 유도색이 아니라서, 더 올리면 화면마다 CTA 와 경쟁한다.
  (2) 브랜드 색상환에서 떨어지게 — 식당 빨강을 H32 로 뒀더니 옅은 워시가 분홍으로 읽혀
  상세 헤더가 브랜드 면처럼 보였다. H42 로 밀어 44° 를 벌렸다.

  `-deep` 쪽은 **두 기준을 동시에** 만족해야 한다: 흰색 대비 5:1 이상(6.1/6.1/6.0)이면서
  자기 22% 워시 위에서 4.5:1 이상(4.50/4.53/4.57). 뒤엣것을 빼먹으면 상세 헤더에서 글씨가
  바탕에 묻는다 — 헤더가 같은 색의 옅은 그라데이션이기 때문이다(이번에 흰 바탕만 보고
  잡았다가 3.8:1 까지 떨어뜨렸다가 되돌렸다).

  `theme.css` 의 `--color-stay` 등과 `src/lib/places.ts` 의 `TYPE_COLOR` **두 곳에 같은 값**을
  둔다 — 화면(마커·타입 tint·아이콘)은 `TYPE_COLOR` 를 읽으므로 한쪽만 바꾸면 반영되지 않는다.

  부수 효과: v5 에서 "warn 배지가 식당 타입 색과 같은 색상대라 묻힌다" 던 충돌은 식당이
  앰버(H64)를 떠나면서 사라졌다.

- **`fg-quaternary`(검색 아이콘·셀렉트 화살표 등 비텍스트 아이콘)를 `#a69d93` → `#8f867c` 로.** 기존 값은 흰 배경 2.67:1 로 비텍스트 최소 기준(3:1) 미달이었다(2026-09-15 리뷰 P2). 새 값은 `bg-primary`(흰색) 기준 3.58:1, `bg-secondary`(크림) 기준 3.37:1. `neutral-400` 스케일 자체는 다른 곳에서도 참조되므로 건드리지 않고 `--color-fg-quaternary` 토큰만 덮어썼다.
- **반려동물 배지 톤(`petBadges.tsx`)도 팔레트 안으로.** `success`(초록)·`warning`(앰버)이 팔레트 밖이었고, 특히 `warning` 은 식당 타입 색(`#cf8330`)과 같은 색상대라 식당 카드에서 배지가 타입 색에 묻혔다. ok=`brand`, cond=`gray`(유지), warn 은 한동안 `indigo` 였다가 **채도를 0.110 으로 누른 앰버(`orange`)로 되돌렸다**(v5). indigo 는 H 277°·채도 0.240 으로 앱에서 가장 진해, "확인 필요" 라는 부가 정보가 주 버튼(브랜드 0.205)보다 먼저 눈에 드는 위계 역전이 났다. 원래의 충돌은 채도 높은 앰버끼리의 문제였고, 작은 칩과 큰 파스텔 워시는 형태가 달라 같은 색상대라도 부딪히지 않는다.
- **판정 배지(`eligibilityBadge.tsx`) 4단계는 "무게" 로 읽히게.** ok "갈 수 있어요"(브랜드 핑크) → cond "확인이 필요해요"(앰버) → unknown "정보가 없어요"(크림 뉴트럴) → hard "이용하기 어려워요"(잉크). `hard` 는 Untitled UI 의 `slate` 를 쓰고 있었는데 Tailwind 기본 slate 는 H 257° 의 **차가운** 청회색이라 "잉크" 라는 의도와 반대였고, 카드에서 크림 gray 칩(H 78°)과 색상환 179° 차이로 맞닿았다 — `neutral` 을 한 단계 진하게 당겨 쓴다. cond 가 파서 배지의 warn 과 같은 앰버인 것은 의도다: **이 앱에서 앰버는 언제나 "주의"** 를 뜻한다.
- **"켜짐" 은 한 가지 언어로.** 지도 오버레이 위의 컨트롤만 진한 브랜드 면(`bg-brand-solid` + 흰 글씨)을 쓰고 — 복잡한 지도 바탕 위에서 읽혀야 하므로 — 그 밖의 선택 상태는 전부 연한 워시(`bg-brand-primary` + 진한 브랜드 글씨)다. 판정 토글(`placesPageEligibilityToggles`)이 혼자 진한 면이라 같은 화면의 타입 탭·계절 칩과 다른 언어로 그려지고 있었다.
- **면은 파스텔, 글씨·아이콘·주요 버튼만 진하게.** 카드·칩·상세 헤더·썸네일은 `typeTint()`(타입 색을 흰색에 10~22% 섞음) 위에 잉크 글씨. 전부 파스텔로 가면 대비가 2:1 대로 떨어지고 CTA 가 사라지므로 하지 않는다.
- 저장 하트(`--color-camellia`)는 브랜드 핑크를 그대로 쓴다. 따로 붉은색을 두면 브랜드와 구분이 안 된다.

## 결과 (Consequences)

- `src/components/base/` 는 고치지 않는다(eslint 도 제외). 변형은 감싸서 만든다.
- 팔레트를 바꾸면 `pnpm icons` 로 아이콘 재생성, `scripts/make-icons.mjs` 의 FG 를 brand-300 과 맞춘다.
- 새 색이 필요하면 토큰을 추가하지 말고 기존 시맨틱 토큰이나 `typeTint` 로 표현할 수 있는지 먼저 본다.
- 다크 모드 토큰은 Untitled UI 가 제공하지만 검수하지 않았다. 지원 범위에 넣으려면 별도 점검이 필요하다.
