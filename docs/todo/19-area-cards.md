## 0. 한 줄 요약

홈 「지역으로 찾기」(관광지 칩 27)를 **6권역 카드**로 바꾸고, 카드마다 "두부랑 **묵을 곳 n · 카페 n**"(홈 N 과 같은 셈)을 단다. 누르면 둘러보기가 그 권역·숙소 탭·'어려운 곳 숨기기' 로 열린다.
0칸은 '없다' 가 아니라 **'저희가 아직 덜 모았다'** 로 말한다. '추천' 이라는 말은 데이터 문턱을 넘은 칸에만(§4).

## 1. 지키는 것 (깨지면 조용히 틀린다)

- **셈은 홈 히어로와 같은 함수.** `countByLevel(그 권역의 placesOfType(type), dog, { needsIndoor })` 의 `ok + outdoor`. 히어로 N(`homePage.tsx`)이 종류별 이 값의 합이다.
  따로 세면 "홈은 12곳, 눌렀더니 11곳" 이 생긴다. **6권역 합 = 전체** 를 테스트로 묶는다(읍면이 매핑에서 빠지면 곳이 사라진다).
- **매핑은 둘이고 서로 맞아야 한다.** 장소는 `region.town`(읍면 13)만 갖는다 → 셈은 읍면 → 6권역. 관광지 칩을 어느 카드에 둘지는 `LANDMARKS_BY_AREA` 키(13, 우도 키 없음) → 6권역.
  같은 이름이 같은 권역으로 가는지 테스트가 잡는다(중문·서귀포·남원 → 남부, 한경 → 서부 …).
- **권역 조건은 비퍼시스트.** 읍면(`town`, 퍼시스트)이 카페 탭·다음 방문까지 새던 문제(ux-expert M-5) 때문에 홈은 퍼시스트 필터를 걸지 않는다(18 T2) — 권역도 관광지 검색어처럼.
- **식당은 카드 머리 숫자에 넣지 않는다.** 대부분 '확인이 필요해요' 인데 전화번호가 없다 — 세면 보증처럼 읽힌다. 둘러보기 식당 탭은 그대로라 길은 안 막힌다.
  > 결정(사용자 2026-10-27): 식당 칸을 **연다 — 07 P0 상세 `tel:` 버튼 뒤에**(T8). 이 줄과 §6 「식당 머리 숫자」 는 T8 이 고친다
- **카드 0칸에 "없어요"·"추천" 을 쓰지 않는다.** 분모와 주어('저희가 모은')로 '모른다' 와 '어렵다' 를 가른다(§3 T4).

6권역(셈용 읍면 매핑):

| 권역 | 읍면 | 관광지 키 |
|---|---|---|
| 서부 | 애월읍 · 한림읍 · 한경면 | 애월 · 한림 · 한경 |
| 서남 | 대정읍 · 안덕면 | 대정 · 안덕 |
| 남부 | 서귀포시 · 남원읍 | 중문 · 서귀포 · 남원 |
| 동남 | 표선면 · 성산읍 | 표선 · 성산 |
| 동부 | 구좌읍 · 우도면 | 구좌 |
| 북부 | 조천읍 · 제주시 | 조천 · 제주시 |

권역 이름(화면)은 임시안 — "서부(애월·협재)" 처럼 아는 지명을 붙이는 쪽을 T4 에서 정한다.

## 7. 지역 확장 설계 (T7 — 둘째 지역을 정하지 않은 채)

> 2026-10-28 · 설계 한 장. 둘째 지역이 언제·어디인지 정하지 않았다(사용자 2026-10-27) — 어느 지역이 붙든 무너지지 않는 꼴만 정한다.
> 코드는 지역이 하나인 지금 화면에서 바뀌는 것 하나(**T7.1** 머리 '제주' 한 줄)뿐이고, 나머지는 둘째 지역이 정해질 때 §7.5 순서로 자른다.

### 7.1 말 — 지역 · 권역 · 읍면

- **지역**(여행지) = 한 번의 여행이 머무는 단위. 지금 '제주' 하나. 행정 도와 같지 않다 — 강원은 한 지역이 아니라 '강릉·속초'·'춘천' 처럼 갈릴 수 있고, 부산은 광역시다.
  그래서 키는 행정 코드가 아니라 우리가 정한 id(`'jeju'`)다.
- **권역** = 지역 안의 동네 묶음(제주 6, `AREAS`). **읍면** = 장소 태그 `region.town`(데이터 표기 그대로).
- 코드 이름: `TRegion` 은 이미 장소의 방향·읍면 칸이다. 지역은 **`dest`**(`TDestId`)로 부른다 — 'region' 이 두 층을 말하면 리뷰가 못 가른다.

### 7.2 데이터 모델 — 지역 → 권역 → 읍면

- **표 하나로 접는다.** `DESTS: Record<TDestId, { label, areas, townToArea, landmarkKeyToArea, cityTowns, map: { center, zoom, bounds }, origin: { name, geo }, searchPrefix, addressHeads }>`.
  §7.4 표의 제주 상수(`AREAS`·`TOWN_TO_AREA`·`LANDMARK_KEY_TO_AREA`·`JEJU_CENTER`·`JEJU_ZOOM`·`JEJU_BOUNDS`·`JEJU_AIRPORT`·`JEJU_CITY`·'제주 ' 접두)가 전부 이 한 칸의 필드다.
- **왜 두 층이 강제되나 — 읍면·시군구 이름은 지역 사이에서 겹친다.** 고성군(강원·경남), 남구·중구·동구(광역시마다). 평평한 `TOWN_TO_AREA` 에 둘째 지역 표를 섞으면
  키가 부딪혀 한 곳이 다른 지역 권역에 **조용히** 세인다. 그래서 `areaOf(place)` 는 `areaOf(dest, place)` 가 되고 지역 키 없이는 정의되지 않는다.
  권역 id(`'west'`)도 지역마다 있을 수 있으니 지역 안에서만 유일하게 두고, 밖으로 나갈 때(스토어·이벤트)는 `jeju/west` 꼴로.
- **지역 키를 얻는 곳** — 넷을 견줬다:

  | 출처 | 판정 |
  |---|---|
  | 주소 첫 마디(`제주`·`부산광역시`) | 정본 불가 — 122곳 중 **8곳이 주소 없음**(2026-10-28 `places.json` 실측), 도 단위라 강원 같은 지역을 못 가른다. **규칙 대조용**(ADR-019 결정 5 와 같은 축 — AI 가 아니라 규칙) |
  | `region_raw`("동쪽 (구좌읍)") | 불가 — 형식이 지역을 모른다(방향 + 읍면뿐, `parseRegion`) |
  | 수집 회차의 지역(키워드 세트가 지역별) | **정본** — 후보는 어느 지역 키워드로 걸렸는지 안다 → 승인(`apply-approved`) 때 `places` 에 적는다 |
  | 운영자 입력(`/admin`) | 고침용 — 부산 키워드에 걸린 글의 제주 가게처럼 수집 지역이 틀렸을 때 |

  → 정본은 `places.dest` 컬럼(`text not null default 'jeju'`) — **마이그레이션은 둘째 지역 때**(지금 만들면 값이 하나뿐인 칸이다). 그 전엔 컬럼 없이 `placeFields` 가 상수로 채운다.
  주소 첫 마디 ↔ `dest` 불일치는 `scripts/lib/regionCheck.mjs` 같은 검사 한 줄(pull 경고 · `/admin` 표시).
- **방향은 제주 전용이다.** `TDirection` 의 `'udo'`, `region_raw` 의 방향 머리, `scripts/lib/jejuRegions.mjs` 의 `TOWN_DIRECTION`, 추출 프롬프트의 방향 표가 한 축이다.
  다른 지역엔 방향이 없을 수 있다(부산에서 '동쪽' 은 안 쓰는 말) → 방향은 지역 표의 선택 필드, 방향 필터(지도·둘러보기)는 그 지역이 방향 표를 가질 때만 선다.
  `regionRaw` 형식은 지역마다 정하거나 읍면만 받는다 — 프롬프트와 지역 표가 갈리면 AI 가 준 값과 화면 선택지가 어긋난다(`jejuRegions.mjs` 머리 주석과 같은 이유).
- **셈 불변식(§1)은 지역 범위를 상류 한 곳에서 건다.** 지금 화면 전부가 받는 `PLACES` 자리에 `placesInDest(dest)` 하나 — 히어로 N · 카드 n · 둘러보기 · 지도 · 검색 · 관광지 칩이 그것을 받는다.
  소비처마다 거르면 §1 이 막던 "홈은 n곳, 눌렀더니 m곳" 이 **지역 단위로** 되살아난다(지도엔 부산이 보이는데 카드는 제주만). 테스트 불변식은
  "모든 장소가 정확히 한 지역" + "지역마다 권역 합 = 그 지역 전체"(지금의 "6권역 합 = 전체" 를 지역별로).
- **번들**: `places.json` 은 webpack 이 통째로 넣는다(CLAUDE.md 「블로그 출처 행」). 지역이 붙으면 첫 방문이 안 갈 지역 데이터까지 받는다 → 지역별 JSON 분할
  (동적 import · 프리캐시 목록 · `scripts/check-bundle.mjs` 한도)은 **미결** — 둘째 지역 크기를 보고 정한다.

### 7.3 화면 두 갈래

**(1) 지역 하나일 때(지금).** 고르기를 띄우지 않는다 — 하나뿐인 선택지는 빈 선택지다. 바뀌는 것은 동네 섹션 안 머리 **'제주' 한 줄**(T7.1)뿐:
「{이름}랑 갈 동네」 h2 밑, 권역 행 위에 목록 묶음 머리 꼴(`GroupList` 의 `title` 과 같은 `text-sm` 600 `text-tertiary`)로 '제주'. 권역 행·셈·진입은 그대로.
지역이 하나인 동안 그 한 줄이 하는 일은 "권역이 '제주' 밑의 층이다" 를 화면에 미리 세우는 것 — 둘째 지역이 붙을 때 행을 다시 짜지 않고 머리만 늘린다.
(대안 — h2 를 "두부랑 갈 제주 동네" 로: 줄이 안 늘지만 둘째 지역 때 제목 말을 다시 바꿔야 한다. 버렸다.)

**(2) 지역이 둘 이상일 때.** 두 갈래를 견줬다:

| | A 지역 줄 접기·펼치기 | B 고른 지역 하나 + 바꾸기 |
|---|---|---|
| 꼴 | 동네 섹션에 지역 머리 줄 여럿, 누르면 그 밑 권역 행이 펼쳐진다 | 화면 전체가 지역 하나를 본다. 머리의 지역 이름이 바꾸기 버튼("제주 ⌄") → 시트에 지역 행(지역마다 "묵을 곳 n") |
| 히어로 N · 종류 수 | 어느 지역 수인지 말할 수 없다 — 두 지역이 함께 펼쳐질 수 있고, 합치면 한 여행에 쓸모없는 수 | 고른 지역 수 하나(§7.2 상류 한 곳) |
| 둘러보기 · 지도 | 카드에서 들어온 지역과 목록 범위가 따로 논다 | 같은 값 — 머리에 지역 이름이 글자로 선다 |
| 지역 수가 늘면 | 홈이 지역 수만큼 길어진다 | 시트 행이 는다 |

**권고: B.** 여행은 한 번에 한 지역이고, §1 의 "한 술어" 가 지역 층에서도 서려면 화면 전체가 같은 지역 하나를 봐야 한다. A 는 홈 한 섹션만 지역을 알고 히어로·탭은 모른다.
- **고르기 자리**: 홈 히어로 부제("두부랑 제주 어디 갈까요?")의 '제주' 를 바꾸기 버튼으로 — 홈에서 가장 먼저 읽히는 자리다. 동네 섹션 머리(T7.1 의 '제주')는 글자로만 따라간다.
  둘러보기·지도엔 고르기를 두지 않고 머리에 지역 이름만 — 바꾸는 곳이 한 곳이어야 셋이 안 갈린다.
- **퍼시스트 — 한다.** 권역을 비퍼시스트로 둔 이유(§1, ux-expert M-5)는 홈 카드가 건 **좁힘**이 다른 탭·다음 방문까지 사용자 모르게 남아 "왜 이것뿐" 이 됐기 때문이다.
  지역은 좁힘이 아니라 "어느 여행을 짜나" 라는 맥락이고, 화면 머리에 늘 글자로 서 있어 숨지 않는다 — 같은 누수가 아니다. `useAppStore` persist(강아지 프로필과 같은 층).
  첫 방문 기본은 `DESTS` 의 첫 지역이고 머리에 바꾸기가 보인다 — 첫 화면을 고르기 문으로 막지 않는다(ADR-011 앱 게이트 제안과 겹치지 않게).
- **저장한 곳 · 하루 동선**: 하트는 지역을 가리지 않는다(저장은 한 목록, 저장 화면은 지역이 둘 이상 섞일 때만 지역 묶음 머리). 날짜·순서 정리(`tripPlan`, ADR-030)는
  **지역 하나 안에서만** — 다른 지역 곳을 한 날에 넣으면 직선거리 순서(`tripRoute`)·공항 출발이 뜻을 잃는다. 출발점 `JEJU_AIRPORT` → `DESTS[dest].origin`(공항·역).
  권고: 정리 화면은 고른 지역의 저장만 보인다. 다른 지역 저장이 이미 날짜를 가진 경우의 처리는 그때 정한다(미결).
- **`/design-audit propose` 는 돌리지 않았다** — 명세는 두 갈래를 propose 로 견주라 했지만 이 줄은 서브에이전트를 띄우지 않는 레인이라 위 비교는 글로만 했다.
  **둘째 지역이 정해질 때 propose 로** B 의 고르기 자리(히어로 부제 vs 동네 섹션 머리)와 시트 꼴을 다시 견준다(§7.5 4).
- 지역을 URL 경로에 넣는 안(`/busan/places`)은 배제 — §6 「새 경로·탭」 · T7 「하지 않는 것」(지역별 정적 페이지). 지역은 스토어 값이다.

### 7.5 둘째 지역이 정해지면 — 자르는 순서

지금은 대기열에 올리지 않는다. 정해지면 한 줄씩 명세로:

1. `DESTS` 표 + `areaOf(dest, place)` — 순수, 화면 그대로(지역 하나). 테스트: 지역마다 권역 합 = 전체 · 모든 장소가 한 지역.
2. `places.dest` 마이그레이션 + `placeFields`·`pull-db` · 주소 첫 마디 대조 검사(§7.2).
3. 수집·분석에 지역 인자(키워드·제목 필터·프롬프트·범위·지명 표) + 새 지역 golden.
4. 상류 범위 `placesInDest` + 지역 스토어(퍼시스트) + 고르기 시트 — **propose 먼저**(§7.3).
5. 지도 첫 화면 · 동선 출발점 · 밖으로 가는 링크 · 어드민 범위.
6. 메타·문구 · 번들 분할 판단(§7.2) · 🙋 앱 이름.
