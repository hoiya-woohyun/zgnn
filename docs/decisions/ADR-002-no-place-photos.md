# ADR-002: 장소 사진을 쓰지 않는다

> 최종 수정: 2026-09-30 (v2: 사진은 가져오지 않고 네이버 플레이스 사진 탭으로 보낸다 — 홈페이지·플레이스 사진 수집을 검토하고 접은 이유)
> 작성일: 2026-09-15
> 상태: 채택

## 맥락 (Context)

- 원 자료의 장소 86곳에는 후기 링크가 있고, 처음엔 그 블로그에서 사진을 내려받아 카드·상세에 쓰려 했다.
- 확인 결과 후기 86개 중 **85개가 작성자가 아닌 다른 블로거의 글**이었다. 한 번 내려받았다가 전부 삭제했다.
- 준비물 이미지는 Notion `attachment:` URI 라 서명 URL 없이는 받을 수 없다.

## 결정 (Decision)

- 사진 없는 화면을 **기본 디자인**으로 삼는다. 사진 자리는 종류 색 워시 + 종류 아이콘이 대신하고, 이름·읍면·특징 문장이 화면을 이끈다.
- `scripts/fetch-blog-images.mjs` 는 `OWN_BLOG_IDS` 허용목록(기본 비어 있음)만 받는다. 타인 블로그를 다시 받지 않는다.
- `TPlace.cover` / `images` 필드와 읽는 코드는 남긴다. 작성자 본인 사진이 생기면 데이터만 채워 사진이 나오게 한다.

### v2 (2026-09-30): 보여 주고 싶으면 **링크로 보낸다**

분석 단계에서 매장 사진 URL 을 모아 상세에 띄우는 안을 검토했고, 접었다.

- **출처 표시는 허락이 아니다.** 저작권법의 출처 명시(37조)는 이미 허용된 이용에 붙는 의무다. 적는다고 쓸 권리가 생기지 않는다.
- **네이버 플레이스 사진도 네이버 것이 아니다.** 업주·방문자가 올린 사진이고, 네이버가 받은 이용 허락은 네이버 서비스 안에서만이다.
  공식 API 로도 받을 수 없어(지역 검색 응답에 이미지가 없다) `m.place.naver.com` 을 긁어야 하는데, 그건 약관의 자동 수집 금지에 걸린다.
- **업체 홈페이지의 `og:image`** 는 공유 미리보기용으로 내놓은 것이라 위험이 가장 작지만, 대개 1장이고 권리자가 업체가 고용한 사진가일 수 있다. 필요해지면 "링크 카드"(사진 + 출처 도메인 + 홈페이지 링크) 모양으로만 다시 검토한다.

그래서 상세에 **"네이버에서 사진 보기"** 버튼을 둔다(`src/lib/naverPlaceLink.ts`). 사진 탭(`/place/{naverPlaceId}/photo`)으로 보낼 뿐이라
권리·약관 문제가 없고, 사용자는 원본·최신·여러 장을 본다. `naverUrl` 이 `naver.me` 단축 링크라 **`naverPlaceId` 가 있어야** 버튼이 생긴다 —
블로그에서 들어온 신규 장소는 `naver_place_id` 가 비어 있어(`applyApproved.mjs`) 사람이 채우기 전까지 버튼이 없다.

## 결과 (Consequences)

- 종류 색이 종류를 가르는 **유일한 시각 신호**가 됐다. 브랜드 색에 흡수시키지 않고 별도 토큰으로 유지한다(→ [ADR-003](./ADR-003-untitled-ui-and-palette.md)).
- 장소 상세 헤더는 사진 대신 타입 색 파스텔 워시 판이다(`src/screens/placeDetailHeader.tsx`).
- 이미지 런타임 캐시 규칙은 `src/app/sw.ts` 에 남아 있지만 지금은 걸릴 요청이 없다.
