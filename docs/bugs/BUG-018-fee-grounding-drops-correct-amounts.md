# BUG-018 — 원문 대조가 모델이 맞게 낸 요금·마릿수를 지운다

> 최종 수정: 2026-10-12 (v2: 리뷰 — `N마리 초과` 를 몇째 마리 표현으로 받으면서 **하나 어긋난 `fromDog`(4)가 금액째 통과**하던 것을 막았다 · 남은 갈래 둘을 21 G1.2·G1.3 으로)
> 이전 2026-10-12 (v1: 신설 — Opus↔Sonnet 비교([todo 21](../todo/21-blog-text-and-extract-model.md)) 중 두 모델이 똑같이 맞게 낸 값이 정규화 뒤 빠져 있었다)
> 상태: 고침(`petPolicyFacts.mjs` · `feeLine.mjs`). 이미 저장된 후보는 지워진 값 그대로다(아래 「남은 것」).

## 증상

상세의 요금 한 줄이 "우리 강아지 기준 금액"(`악동이는 1박 1만원`) 대신 **`적힌 요금 · …` 으로 label 만 늘어놓는다**. 요금 줄은 보이므로 틀린 말은 없고, 계산만 사라진다.
모델 원응답에는 금액·구간이 맞게 들어 있다 — 정규화 결과(`normalizePetPolicy`)에서만 `amountWon`·`minKg`·`fromDog`·`maxDogs` 가 비어 있다.

| 곳 | 원문 | 모델이 낸 값(두 모델 같다) | 지워진 이유 |
|---|---|---|---|
| 솔숲 | `1~5kg 1박에 1만원` / `6~10kg 1박에 1.5만원` | minKg 1·6, 10000·15000 | 구간 하한 `1` 뒤에 `kg` 가 아니라 `~` 가 와서 `mentionsKg` 가 못 읽는다 |
| 아우아우 | `4마리를 초과할 경우 1견당 3,000원` | fromDog 5 | 원문에 `5마리`·`기본 4마리` 가 없고, label `4마리 초과` 가 몇째 마리 표현(`부터`·`째`)으로 안 읽힌다 |
| 일랑일랑 | `최대 인원은 4인 4견` | maxDogs 4 | `N마리` 만 마릿수로 읽는다 |
| 안녕감귤 | `첫 1박 기준 1만5천원` | 15000 | `1만5천원` 을 뒤쪽 `5천원`(5000)으로 읽고, `첫 1박` 의 `박` 을 1박마다로 읽어 `perNight: false` 를 거절 |

**프롬프트 자신의 예시 `FEE_EX.range`(`1~5kg 1만원`)도 지워졌다** — 프롬프트가 가르친 모양을 대조가 지우니, 모델이 맞게 낼수록 요금이 label 로만 남았다.
계약 테스트(`dogFee.test.ts`)가 예시를 계산(`sumByRules`)에만 넣고 대조(`correctPetPolicyFacts`)에는 안 넣어 몰랐다. 빌드·테스트는 전부 초록이었다.

## 원인

`correctFeeRules` 의 계산 칸 근거를 **상한·마릿수 판단(`weightLimitKg`·`maxDogs`)과 같은 판독기**로 봤다. 그 판독기는 지어낸 제한을 막으려고 좁게
만든 것이라("원문에 `N kg` 이 그대로 있나"), 요금표의 흔한 모양 — 구간·초과·첫날 — 을 근거로 못 읽는다. 금액 정규식은 `만` 뒤에 `원` 이 붙은 것만
만 단위로 봐서 섞은 금액을 반만 읽었고, 정규화(`canonical`)가 그 값으로 label 을 `1만5,000원` 으로 다시 써 DB 에도 그렇게 남았다.

## 수정

- `feeLine.mjs` `AMOUNT_RE` — `N만 M천원`·`N만 M,000원` 을 한 금액으로(`1만5천원` = 15000). 뒤가 다시 `만원`(`1만 2만원`)이면 섞지 않는다.
  저장된 `1만5,000원` 도 15000 으로 읽혀 앱이 다시 대조해도 산다. 정규화는 이제 `1.5만원` 으로 쓴다.
- `petPolicyFacts.mjs`
  - `mentionsKgFrom` — 요금의 `minKg` 에만 구간 하한을 인정한다. **`weightLimitKg`·`maxKg` 는 그대로** — `6~10kg 1.5만원` 의 6 을 상한으로 받으면 6kg 넘는 강아지를 막는다.
  - `mentionsDogs` 가 숫자 바로 뒤 `견` 을 마릿수로 읽는다(`4견`). `1견당` 은 마리당 요금이라 뺀다.
  - `mentionsDogsOver` — `N마리를 초과` 를 `fromDog` N+1 의 근거로. 요금 칸에서만이다(넘는 마리도 받는다는 말이라 상한이 아니다). `shapeMatchesLabel` 도 `초과·넘` 을 몇째 마리 표현으로 보되 **수까지 맞춘다**(`N마리 초과` ⇒ fromDog 가 정확히 N+1) —
    원문의 `4마리` 가 `mentionsDogs` 로 fromDog 4 의 근거로도 잡혀서, 수를 안 보면 하나 어긋난 4 가 네 마리 손님에게 없는 3,000원을 확정 문장으로 낸다(v2, 리뷰).
  - `shapeMatchesLabel` — `첫 1박` 이 든 label 은 1박마다가 아니다(`perNight: true` 면 오히려 거절 — 첫날 요금이 박마다 곱해진다).
- 테스트: 모델 원응답 칸 그대로(원문은 조건 줄만)로 "대조 → label 정규화 → 다시 대조" 가 고칠 것 없이 남는지(`petPolicyFacts.test.mjs`),
  **`FEE_EX` 전부를 label 을 원문 삼아 대조에 넣는 계약**과 솔숲의 `formatDogFee` 문장(`dogFee.test.ts`). 지어낸 숫자 쪽(BUG-009 테스트)은 그대로 초록.

## 남은 것

- **저장된 후보는 돌아오지 않는다.** 대조가 이미 비운 칸이라 앱이 `withPolicyFacts` 로 다시 대 봐도 채울 값이 없다. 2026-10-12 원격 조회로 세면 대기 후보 중
  요금 3곳(`1만N천` 2 · `초과` 1 · `첫 1박` 1, 겹침 있음) · 원문에 `N견` 이 있는데 `maxDogs` 가 빈 곳 3곳 — **적어도** 6곳, 게시된 곳 0
  (줄은 남고 금액만 빈 것만 셌다. 모델이 `1.5만원` 으로 바꿔 쓴 줄은 옛 판독(원문 5000 ↔ label 15000)에서 줄째 빠져 이 질의에 안 잡힌다). 재추출은 하지 않는다
  (요금 줄은 label 로 남아 틀린 말은 없고, 다음 재분석 때 저절로 돌아온다).
- 일랑일랑의 요금 `추가 1마리 5,000원`(fromDog 2)은 여전히 빠진다 — 원문이 "기본 요금에는 … 반려견 1마리가 포함" 이라 `기본 N마리` 모양이 아니다. 범위 밖으로 남겼다([todo NOW](../todo/NOW.md) 「발견」).
- `N박째부터 1박당 1만원` 의 금액은 여전히 산다 — 칸에 없는 조건이라 null 이어야 한다. 혼자 있으면 1박 손님에게 확정 금액을 낸다 → [21 G1.2](../todo/21-blog-text-and-extract-model.md).
- `/admin` 의 칠하기(`CORRECTION_CUES` 의 `amount`·`dogs`)는 새 판독과 어긋난다 — `1만5천원` 에서 `5천원` 만 칠하고 `4견` 은 못 칠한다 → [21 G1.3](../todo/21-blog-text-and-extract-model.md).
- 안녕감귤처럼 `첫 1박`(한 번) + `2박째부터 1박당`(박마다)이 섞이면 앱은 여전히 `적힌 요금` 으로 물러난다 — 정상이다(한 번 붙는 요금과 박마다 붙는 요금을 합치지 않는다).
