# 장소 제보 — "정보가 달라요"

> 최종 수정: 2026-10-01 (v1: 신설 — 상세 맨 아래 "다녀와 보니 달랐나요?" 카드와 제보 시트. 종류 다섯(폐업·다른 가게·주소·조건·기타) + 선택 한 줄, 장소·배포는 자동.
> 받는 곳은 Supabase `place_reports` 의 insert 하나 → [ADR-021](../decisions/ADR-021-place-reports.md). 자리·문구는 **임시안**이다 — 디자인 트랙([10 §7](../todo/10-user-feedback-personas.md))이 다시 정할 수 있다)

왜 받는지·어디까지 받는지는 [ADR-021](../decisions/ADR-021-place-reports.md), 페르소나 셋이 왜 이 자리에 닿았는지는 [todo/10](../todo/10-user-feedback-personas.md).

## 사용자가 하는 것

1. 상세 맨 아래 **다녀와 보니 달랐나요?** 카드의 `정보가 달라요` 를 누른다.
2. 시트에서 하나를 고른다 — 문을 닫았어요(폐업·휴업) · 다른 가게로 바뀌었어요 · 주소·위치가 달라요 · 반려동물 조건이 달라요 · 그 밖에 달라요.
3. 필요하면 한 줄(200자까지) 적고 `보내기`. 결과는 화면 아래 한 줄로만 온다(`고마워요! 운영자가 확인하고 고칠게요`).

## 비직관적인 것

- **맨 아래에 둔다.** 제보는 다녀온 **뒤**의 동작이다. 제목 밑 액션 줄은 가기 **전**의 동작(저장·공유·네이버)이라 섞으면 액션 줄이 길어지고
  "헛걸음" 이 첫 화면의 말이 된다(07 의 판단).
- **보낸 것을 다시 볼 수 없다.** 비로그인 역할에는 select 가 없다 — 그래서 "보낸 제보 목록" 같은 화면은 만들 수 없고, 만들려면 기기 식별자를 받아야 한다(ADR-012 의 선 안쪽).
  답장도 없다. 루프가 닫힌 것은 **"최근 확인" 날짜가 바뀌는 것**으로만 보인다(F3).
- **하루 한도는 기기 쪽의 부드러운 한도다.** 같은 장소·같은 종류는 24시간에 한 번(localStorage `zgnn-reports`, 앱 스토어 `zgnn-jeju` 와 키를 가른다 — 그쪽이 깨져 지워질 때 같이 지워지지 않게).
  지우면 풀린다. 서버 한도는 없다(ADR-021 R2).
- **실패하면 시트를 닫지 않는다.** 적은 말을 잃지 않고 다시 누를 수 있게. 오프라인 · 표 미적용(마이그레이션 전) · CHECK 위반 · 그 밖을 서로 다른 말로 한다
  (`placeReportSend.ts` 의 `classifySendFailure`). 큐에 넣어 나중에 보내기는 없다(v1 — 제보가 실제로 쌓이는 것을 본 뒤).
- **전화번호 칸은 아직 없다.** 표의 종류(`phone`)에는 있지만 고를 수 있는 목록에서 뺐다 — 번호 데이터(07 P0)가 없는데 "번호가 달라요" 를 고를 수는 없다.
- **supabase-js 를 쓰지 않는다.** POST 한 번에 GoTrue 클라이언트까지 끌려오면 사용자 화면에 인증 저장소가 생긴다. `apikey` 헤더 하나 + `Prefer: return=minimal`.
