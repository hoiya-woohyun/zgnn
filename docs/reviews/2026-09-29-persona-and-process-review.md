## 0. 한 줄 요약

**화면이 서로 반대로 말하는 자리가 다섯 곳 있고**(못 간다면서 챙길 것을 준다 · 확인하라면서 야외면 된다고 한다 · 못 가는 곳의 청소비를 우리 개 요금처럼 적는다 ·
준비물의 가방과 프로필의 가방이 따로 논다 · 홈 숫자와 목록 숫자가 다르다), **사용자가 한 번 고른 기본값("이동 수단 없어요")이 식당 결과를 조용히 뒤집는다.**
프로세스 쪽은 **엔지니어링 검증은 과할 만큼 강한데 제품 검증 루프가 0** 이고, 정본 문서들이 서로 모순돼 새 세션(특히 가벼운 모델)이 틀린 사실로 출발한다.

## 1. 사용자 과제 흐름 — 어디서 멈추나

### 지수 (27, 말티푸 4kg, 천 이동가방 있음, 제주 첫 방문, 카톡 링크로 진입)

| 단계 | 멈춘 곳 | 앱 밖으로 나가는 순간 |
|---|---|---|
| 강아지 등록 | 이동 수단이 **"없어요" 로 미리 골라져 있다** — 가방이 있지만 그냥 저장 (`dogProfilePage.tsx:75` `useState<TCarrier>('none')`) | — |
| 애월 점심 | "애월" 검색 → 식당 3곳 전부 "이용하기 어려워요 · 케이지 필요". 내 천 가방도 안 된다는 뜻인지 모른다. 다음 행동 안내 없음 | **여기서 네이버로 나가 "애월 애견동반 식당" 검색** |
| 상세 | cond 머리글 "확인해야 알 수 있어요" 바로 아래 근거가 "야외 자리만 가능해요" — 되는 건지 확인하라는 건지 | — |
| 상세 | "이용하기 어려워요" 아래 노란 박스 "여기 가려면 6가지를 더 챙겨야 해요" (`placeDetailPage.tsx:83` 가 판정 등급을 보지 않음) | — |
| 저장 | 하트 눌러도 피드백 없음. `/saved` 는 탭에 없고 홈 맨 아래 카드로만 간다 | — |
| 준비물 | "강아지 기내용 가방" 을 체크했는데 프로필은 여전히 `none` — 식당 판정 그대로 | — |
| 친구에게 보내기 | 상세에 **공유 버튼이 안 보인다** — Web Share 가 없는 환경(카톡 인앱·데스크톱)에서는 버튼 자체를 안 그린다 (`placeDetailPage.tsx:28-42`) | 주소창 복사 |

> "숙소·카페는 추천. 식당은 기본값과 '케이지 필요' 때문에 애월이 전부 어려워요로 보여서 네이버로 나갔어요."

### 민준 (34, 28kg + 17kg, 배+차로 입도, 4박, 숙소부터)

| 단계 | 멈춘 곳 |
|---|---|
| 후보 추리기 | 홈 "7/26" vs 목록 머리 "26곳" — 어려움 14곳이 섞여 있고 **카드만 봐서는 왜 '확인' 인지 모른다**(카드에 근거 줄 없음, `placeCard.tsx:60-63`). 7곳을 다 눌러야 한다 |
| 가능 상세 | "6만원 (1마리당 3만원)" 은 믿음이 간다 — 그러나 **1박인지 숙박 전체인지** 없다 |
| 어려움 상세 | 요금 줄이 "**대장이와 초코** · 청소비 5만원" — 못 가는 곳의 청소비를 우리 개 요금처럼 읽는다 (`dogFee.ts:111` 대체 경로가 이름을 붙임) |
| 확인 상세 | 원문에 "10kg 이상 4만원" 이 있는데 판정은 "대형견 언급이 없어요" (`eligibility.ts:218` C5 가 요금 줄의 kg 구간을 안 봄) |
| 정보 없음 5곳 | 그중 4곳에서 "정보가 없다" 인데 "대형견 언급이 없어요" 가 먼저 나온다(C5 가 `noInfo` 에서도 발동 — 등급은 이미 unknown, 문구만 틀림) |
| 어려움 근거 | "15kg 이하" 를 누가 넘는지 이름이 없다 |
| 준비물 | 배로 가는데 "기내용 가방 (5kg 이하/이상)" 이 맨 위 — 이동 방식 입력이 없다 |
| 지도 | 서쪽 "가능" 숙소 2곳 중 요호르기 스테이는 좌표·주소가 없어 지도에서 빠진다 |

> "숙소 거르기용으로는 쓴다(26 → 4를 10분). 하지만 실제 결정(전화·1박 요금·경로)은 전부 네이버에서 했다.
> 카드에 근거 한 줄이 붙고 전화 버튼이 생기면 '대형견이면 이거 먼저 봐' 라고 보내겠다."
> 제외 목록으로서의 가치: **높음** — 틀리게 제외된 곳은 못 봤다.
