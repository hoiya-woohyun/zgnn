# BUG-011 — 재빌드 429(시간당 한도)를 "Deploy Hook 이 폐기된 것 같다" 로 말했다

> 최종 수정: 2026-10-06 (v1: 신설 — [todo/13](../todo/13-ai-analysis-audit-2026-10-04.md) T3.2 "훅 복구" 가 실은 복구할 것이 없었다)
> 상태: 고침(`src/lib/adminRebuild.ts` `rebuildHeadline` — 429 갈래).

## 증상

2026-10-02 04:24 의 일괄 고치기 뒤 `/admin` 머리글이 "Vercel 이 재빌드를 거절했어요(… · 429) — Deploy Hook 이 폐기된 것 같아요. 새 주소를 Vault 에 넣어 주세요" 로
떴다. 점검 문서는 그대로 **훅 회전**을 사람 손 태스크(T3.2)로 올렸다. 10-06 에 같은 훅이 다섯 건 전부 201 — 훅은 멀쩡했다.

## 원인

Deploy Hook 은 **프로젝트당 시간당 60번**이 한도다(Vercel 문서 「Deploy Hooks → Limits」). `places` 트리거는 게시 집합이 바뀌는 **행마다** 한 번 부르므로
일괄 승인·일괄 고치기 한 번이면 닿는다 — `rebuild_log` 에 같은 분 6건이 전부 429 였다. 머리글은 4xx·5xx 를 한 문장으로 말했고, 그 문장이 가리키는 원인은
폐기(404) 하나였다. 멀쩡한 훅을 회전하게 만드는 안내다 — 회전은 그 자체로 사고 경로라([ADR-018](../decisions/ADR-018-in-app-admin-review.md) 결정 9) 더 나쁘다.

## 고침

- `rebuildHeadline` 에 429 갈래: "한 시간에 재빌드를 60번 넘게 불러 Vercel 이 이번 호출을 거절했어요. 훅은 그대로예요. 다음에 성공하는 재빌드가 이것까지 같이 반영해요 —
  한 시간 뒤에도 안 걸리면 게시 중인 장소 하나를 다시 저장해 주세요". Vault 를 가리키지 않는다. 테스트 한 갈래 추가.
- 빌드는 DB 전체를 읽으므로 거절된 변경은 **잃어버린 것이 아니다** — 다음 성공한 호출 하나가 다 싣는다. 그래서 자동 재시도를 붙이지 않았다.

## 남는 것

- 승인 N건 = 호출 N번 구조는 그대로다([admin-review](../features/admin-review.md) 「승인 N건 = 빌드 N번」). 60/시간 안에서는 Vercel 이 같은 훅의 앞 빌드를 취소해 주므로
  비용은 괜찮고, 한도에 닿는 것은 일괄 작업뿐이다. 트리거 쪽에서 묶어 한 번만 부르는 것(statement 단위 · debounce)은 닿는 일이 잦아지면 연다.

## 교훈

HTTP 코드를 한 묶음으로 말하면 문장이 **한 원인**만 가리키게 되고, 그 원인이 틀릴 때 안내가 해를 끼친다. 운영자에게 할 일을 시키는 문장은 코드별로 가른다.
