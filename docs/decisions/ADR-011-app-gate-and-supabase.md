# ADR-011 — 앱 전체를 잠그되 정적 내보내기는 버리지 않는다

> 최종 수정: 2026-09-17 (v1: 신설 — 잠금 층위, 데이터를 번들 밖으로, Supabase 경계, 블랙리스트)
> 상태: 제안 — 구현 전. 코드는 아직 하나도 바뀌지 않았다.

## 맥락

회원을 받아 **이용 가능한 사람과 불가능한 사람을 가르고 싶다**. 그런데 이 앱은
정적 내보내기(`output: export`, [ADR-001](ADR-001-pwa-static-export.md))라 **서버가 없다.**

여기서 대부분의 설계가 조용히 실패한다.

- `src/data/places.json` 은 빌드 시점에 **번들 안으로 구워진다.** `out/` 을 받은 사람은
  이미 86곳 전부를 손에 쥐고 있다. 서비스워커가 프리캐시까지 해 둔다.
- 그래서 화면에서 "로그인 안 했으면 목록을 숨긴다" 를 아무리 정교하게 짜도 **자물쇠는
  데이터를 내준 뒤에 달린다.** 개발자 도구를 열 필요도 없이 JS 번들에 텍스트로 들어 있다.

서버 없이 접근을 **실제로** 막을 수 있는 자리는 하나뿐이다 — **Supabase 안에 있는 데이터에
걸린 RLS.** 즉 "잠글 것" 과 "Supabase 로 옮길 것" 은 같은 말이다.

### 먼저 정직하게 — 장소 데이터는 애초에 기밀이 아니다

원본은 **공개 Notion 페이지**(`src/data/meta.json` 의 `sourceUrl`,
`zzanggununa.notion.site/jejudo`)다. 86곳의 이름·위치·이용 조건은 지금도 누구나 본다.
레포에도 `data/jejudo-notion-export.json` 이 커밋돼 있고, git 히스토리는 지워지지 않는다.

**그러니 이 잠금의 목적은 "정보를 감추는 것" 이 아니다 — "누가 이 앱을 쓰는가" 의 통제다.**
이걸 섞어 적으면 나중에 "레포를 공개해도 되나" 같은 질문에 답할 수 없다. 답은: 레포 공개
여부와 무관하게 **앱 층위의 잠금**이고, 데이터 기밀성은 처음부터 목표가 아니었다.

## 결정

### 1. `output: export` 를 유지한다 — 대신 데이터를 번들 밖으로 뺀다

SSR/미들웨어로 갈아타면 PWA·오프라인·무료 호스팅이 전부 딸려 나간다. 그럴 필요가 없다.
**정적인 것은 껍데기이고, 잠글 것은 내용물**이기 때문이다.

| 지금 | 바뀐 뒤 |
|---|---|
| `src/data/places.json` (번들에 구워짐) | `data/places.json` — **빌드 입력**이자 Supabase 시드. 번들에 안 들어감 |
| — | Supabase `places` 테이블 — 앱이 로그인 뒤 런타임에 읽는 **유일한** 장소 데이터 |
| — | `src/data/place-ids.json` — **id 목록만**. `generateStaticParams` 와 `next.config.mjs` 의 프리캐시 라우트 목록용 |

- 껍데기(HTML·JS·CSS·아이콘)는 지금처럼 정적으로 나가고 프리캐시된다.
- 로그인한 active 회원만 Supabase 에서 장소를 받아 **IndexedDB 에 캐시**한다. 오프라인은
  "빌드 시점 프리캐시" 가 아니라 "한 번 본 것을 남긴다" 로 성격이 바뀐다.
- Notion 블록 id 는 그 자체로 아무 정보도 아니라 공개돼도 무방하다. 라우트 목록이 노출되는
  대가로 주소 체계(`/place/[id]`)와 [ADR-007](ADR-007-shell-owned-back-navigation.md) 을 그대로 지킨다.

### 2. "Notion → DB 마이그레이션" 은 선택이 아니라 **필수**가 된다

앞선 계획에서는 Supabase 로의 장소 마이그레이션이 "넣어도 되고 말아도 되는" 항목이었다.
전체 잠금을 택한 순간 **마이그레이션이 곧 잠금 장치**다 — 데이터가 Supabase 에 없으면
RLS 가 걸 대상이 없고, 그러면 잠금이 다시 장식이 된다.

### 3. Supabase 경계

| 테이블 | 무엇 | RLS 요지 |
|---|---|---|
| `profiles` | `user_id`(→`auth.users`), `status`(`pending`\|`active`\|`blocked`), `phone`, `dog_name`, 가입일 | 본인 행만 읽기/쓰기 |
| `places` · `items` | 파이프라인이 만든 데이터 | **`status='active'` 인 로그인 사용자만** select. insert/update 는 서비스 키(파이프라인)만 |
| `saved` | 사용자별 저장 목록 | 본인 것만 |
| `blocklist` | 아래 4번 | 일반 사용자 접근 전면 차단 |

- 승인은 대시보드에서 `status` 를 바꾸는 것으로 한다. **레포에 허용목록을 넣지 않는다** —
  정적 번들이라 우회 가능하고, 남의 연락처를 코드에 커밋하는 꼴이 된다.
- 클라이언트가 쓰는 anon key 는 공개돼도 되는 키다. 실제 방어선은 키가 아니라 RLS다.

### 4. 블랙리스트

- `blocklist(phone_hash, reason, created_at, created_by)`. **휴대폰 번호 원문을 저장하지
  않는다** — salt 를 섞은 해시만 둔다. 가입 시점에 같은 방식으로 해싱해 대조하면
  "이 사람이 차단 대상인가" 는 답할 수 있고, 번호 자체는 갖고 있지 않게 된다.
- 차단이 성립하려면 **탈퇴 뒤에도 남아야 한다**(탈퇴 → 재가입으로 뚫리면 의미가 없다).
  이건 파기 의무와 정면으로 부딪히는 지점이라 근거와 고지 방식은
  [ADR-012](ADR-012-personal-data-and-consent.md) 에서 다룬다.
- `profiles.status='blocked'` 는 **즉시** 듣는다 — RLS 는 쿼리마다 다시 평가되므로 다음
  요청부터 막힌다. 단 **refresh token 을 폐기해야** 세션이 계속 access token 을 찍어내지 않는다.

## 결과 — 무엇이 깨지고 무엇을 새로 지켜야 하나

- **"런타임 fetch 는 없다" 가 깨진다.** `docs/architecture/data-pipeline.md` 의 첫 문단부터
  다시 써야 한다. 오프라인 전략도 마찬가지다(`pwa-offline.md`).
- **첫 프레임에 데이터가 없다.** 지금도 `skipHydration` 때문에 "저장 0" 이 한 프레임 보이는데,
  이제는 목록 전체가 그렇다. 스켈레톤이 필요하고, 그건 버그가 아니라 설계다.
- **⚠️ 프리캐시 revision 이 데이터 변경을 못 잡는다.** `next.config.mjs` 의 `revisionHash` 는
  `src/` 전체를 해싱한다. `places.json` 이 `src/` 밖으로 나가면 **장소 내용이 바뀌어도
  revision 이 그대로다.** 라우트가 늘고 주는 것은 `place-ids.json` 이 잡아 주지만 **내용 변경은
  아무도 안 잡는다.** 데이터 버전을 따로 들고 IndexedDB 캐시를 무효화하는 장치가 필요하다 —
  빌드는 통과하고 화면도 뜨는데 **옛 데이터만 계속 보이는** 종류의 고장이다.
- **Supabase 무료 티어는 7일 비활성이면 프로젝트를 재운다.** 잠들면 앱이 **로그인부터**
  안 된다. 주간 크론이 이제 "있으면 좋은 것" 이 아니라 **가용성 요건**이다.
- **이미 받아간 캐시는 회수할 수 없다.** 차단해도 그 기기의 IndexedDB 는 지울 수 없다.
  최선은 "다음에 온라인으로 접속할 때 캐시를 비운다" 이고, 오프라인으로만 쓰면 그마저 안 듣는다.
  이 한계를 문서와 약관에 적어 둔다.
- **레포와 Notion 원본은 여전히 공개 경로다.** 위 '맥락' 의 결론을 다시 적는다 — 이 잠금은
  앱 층위다.

## 하지 않기로 한 것

- **SSR·미들웨어 전환.** 잠그려고 PWA·오프라인·무료 호스팅을 버릴 이유가 없다.
- **레포에 이메일/전화번호 허용목록.** 우회 가능하고, 남의 개인정보를 커밋하는 일이다.
- **휴대폰 번호를 인증 수단으로 쓰기.** SMS OTP 는 유료 발송 사업자가 필요해 "무료 티어" 라는
  전제를 깬다. 인증은 이메일 매직링크로 하고 번호는 프로필 값으로만 받는다 → [ADR-012](ADR-012-personal-data-and-consent.md).
- **장소 데이터를 감췄다고 말하기.** 원본이 공개라 사실이 아니다.
