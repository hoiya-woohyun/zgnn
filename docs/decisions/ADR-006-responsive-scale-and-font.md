# ADR-006: 화면이 커지면 크기도 커진다 — `--spacing` 한 축 + 나눔스퀘어 네오

> 작성일: 2026-09-16
> 상태: 채택
>
> 최종 수정: 2026-09-29 (v4: **`text-sm` 줄 높이를 `* 5` → `* 5.25`(모바일 20 → 21px, 1.43 → 1.5)**. 여러 줄 문단 대부분이 14px 인데

> 같이 넣어 거의 안 먹으므로, 고치는 자리는 `body` 가 아니라 토큰이다. `h-11` 칩·버튼은 높이가 고정이라 그대로다)
> 이전 (v3: 모바일 점검 — **12px(`text-xs`)는 크기가 아니라 역할로 쓴다.** 라벨·개수·안내는 12px, 누르는 버튼과 읽고 결정해야 하는
> 정보(판정 근거·요금 원문)는 14px(`text-sm`)로 올렸다. 44px 버튼에 12px 글자는 버튼으로 안 읽힌다. 또 `text-quaternary`(#7d756c)는 페이지 바탕
> `neutral-50` 위에서 대비 4.27 로 작은 글씨 기준(4.5)에 못 미쳐, **글자에는 `text-tertiary` 까지만** 쓴다(아이콘은 3:1 기준이라 그대로).
> 입력칸이 16px(`Input size="lg"`)인 것은 iOS 가 포커스 때 확대하지 않는 하한이기도 하다 — `--spacing` 4px 을 안 줄이는 또 하나의 이유)

> 모양이 높이 대비 비율에 달리게 됐는데, rem 고정이면 큰 화면에서 높이만 25% 커지고 반지름은 그대로라 각져 보였다.
> 배수는 모바일 4px 에서 Untitled 원래 값과 정확히 같게 골랐다 — 모바일 화면은 한 픽셀도 안 바뀐다. `rounded-full` 은 비율과 무관해 그대로)
> 이전 (v1)

## 맥락 (Context)

- 지금까지 브레이크포인트는 **레이아웃만** 바꿨다(사이드바 노출, 컬럼 수, 탭바↔사이드바). 글자·여백·컨트롤 높이는 390px 폰과 1280px 데스크톱이 똑같았다. 데스크톱에서 16px 본문은 화면에 비해 작고, 카드가 텅 빈 여백 위에 떠 보인다.
- 2026-09-16 사이즈 감사에서 44px 터치 타깃을 정비하며 드러난 사실: **이 레포의 크기 토큰은 전부 `--spacing` 파생**이다(`--text-md: calc(var(--spacing) * 4)` …, `theme.css`). 즉 축이 이미 하나다.
- 글꼴은 시스템 스택(`-apple-system` → Apple SD Gothic Neo / Malgun Gothic)이었다. 기기마다 다른 글꼴로 그려져 화면 인상이 고정되지 않았고, 한글 본문이 밋밋했다.

## 결정 (Decision)

### 1. 크기 스케일은 `--spacing` 하나로

`src/styles/globals.css` 에서 브레이크포인트마다 `--spacing` 만 바꾼다. 4 → 4.5 → 5px (1 → 1.125 → 1.25배).

| | 모바일(<768) | 태블릿(≥768) | 데스크톱(≥1024) |
|---|---|---|---|
| `--spacing` | 4px | 4.5px | 5px |
| 본문(`text-md`) | 16px | 18px | 20px |
| 컨트롤(`h-11`) | 44px | 49.5px | 55px |
| 섹션 패딩(`px-4`) | 16px | 18px | 20px |

- **모바일 값은 고정이다.** 44px 터치 기준(`h-11` = `--spacing * 11`)이 여기 걸려 있다. 확대 방향으로만 가고, 줄이지 않는다.
- 자리마다 `md:text-lg` 를 손으로 붙이는 방식을 쓰지 않는다. 새로 만드는 컴포넌트가 아무것도 하지 않아도 규칙을 따르는 것이 이 선택의 핵심이다.
- 기준은 화면 폭이 아니라 **"이 화면을 손으로 만지는가"** 다. 그래서 태블릿은 한 단만 올린다.

px 로 박힌 것은 따라오지 않는다. 그중 `PlaceThumb` 은 spacing 파생 클래스(`size-11`/`size-10`)로 옮겨 함께 커지게 했고, **지도 마커는 일부러 남겼다** — 마커 크기는 UI 크기가 아니라 카토그래피 결정이라 화면이 커진다고 핀이 커지면 안 된다(`mapPage.tsx` `markerIcon` 주석). 아이콘 `size={n}` prop 들은 아직 px 다.

### 2. 본문 글꼴은 나눔스퀘어 네오, self-host

- 네이버가 나눔글꼴 라이선스로 배포하는 무료 글꼴. 한글 본문이 또렷하고 제목에서 성격이 산다.
- **CDN 대신 self-host.** 이 앱은 오프라인 프리캐시가 기능의 일부다(제주 산간·비행기 모드에서 열어보는 앱). 외부 도메인에 기대면 그때 시스템 폰트로 떨어진다. 외부 요청 0건이면 CSP·추적 문제도 같이 사라진다.
- 원본 TTF 는 굵기당 2.1MB 라 그대로 못 싣는다. **한글 완성형 11,172자 + 라틴으로 서브셋해 woff2 로 353KB/굵기.** 상용 2350자로 더 줄이지 않은 것은 강아지 이름처럼 **사용자가 직접 치는 글자**가 있어서다 — 줄이면 "똠" 같은 글자만 시스템 폰트로 튄다.
- **굵기는 400·700 둘.** 앱이 많이 쓰는 `font-semibold`(600)는 CSS 폰트 매칭 규칙상 700 에 붙는다(합성 볼드가 아니라 진짜 Bold 자족). 굵기 추가는 +353KB 이므로 필요해질 때 판단한다.
- 시스템 스택은 뒤에 남긴다 — `display: swap` 구간과 서브셋 밖 글자(한자 등)를 받아 준다.

- 라이선스는 **나눔글꼴 라이선스** — 무료 사용·재배포가 되고 글꼴 파일 자체를 파는 것만 금지다.
  서브셋한 파생본을 레포에 담아 배포하는 것도 허용된다. 출처 표시는 `src/app/fonts/README.md` 에 둔다.

재생성 절차는 [architecture/pwa-offline.md](../architecture/pwa-offline.md#글꼴-self-host) 에.

## 결과 (Consequences)

- 데스크톱에서 화면이 "커진다". 카드·버튼·글자가 같은 비율로 커지므로 균형은 유지된다.
- 태블릿(820px)에서 사이드바(`w-64`)도 같이 커져 256 → 288px 이 되고 본문이 그만큼 좁아진다. 2026-09-15 디자인 리뷰가 지적한 "820px 에서 본문이 좁다" 가 조금 더 커졌다 — **사이드바 전환을 `md`(768) 에서 `lg`(1024) 로 올리는 것이 후속 과제**다.
- 번들에 704KB(굵기 2개)가 추가된다. 프리캐시 대상이라 최초 1회 받고 이후 오프라인에서도 뜬다.
- `--spacing` 을 건드리는 것은 이제 앱 전체를 건드리는 일이다. 값을 바꿀 때는 390/820/1280 세 폭을 모두 실측한다.
