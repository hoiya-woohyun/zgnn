## 사용자가 하는 것

1. 상세 맨 아래 **다녀와 보니 달랐나요?** 카드의 `정보가 달라요` 를 누른다.
2. 시트에서 하나를 고른다 — 문을 닫았어요(폐업·휴업) · 다른 가게로 바뀌었어요 · 주소·위치가 달라요 · 반려동물 조건이 달라요 · 그 밖에 달라요.
3. 필요하면 한 줄(200자까지) 적고 `보내기`. 결과는 그 카드의 흔적 한 줄(`알려 주셨어요 — ‘…’. 운영자가 확인할게요.`)로 남는다 — 화면 아래 알림은 띄우지 않는다(v16).

판정이 틀렸으면 — 판정 카드 바로 밑 `판정이 틀렸어요`(강아지를 등록해 판정이 있을 때만). 같은 시트가 종류 고르기 없이 열린다 — 종류는 `반려동물 조건이 달라요` 하나다.
대신 **무엇이 틀렸는지 하나를 꼭 고른다**(v16) — 못 들어갔어요 · 들어갈 수 있었어요 · 요금이 달랐어요 · 그 밖에 달랐어요(이때는 한 줄이 있어야 한다). 한 줄은 180자까지.
흔적 줄이 화면 밖(맨 아래 카드)이라 여기서 보내면 화면 아래 알림이 뜬다.

또 하나 — **그대로였어요.** 같은 카드의 첫 버튼이다. 누르면 "고마워요 · 되돌리기" 알림이 뜨고, 그 알림이 걷힐 때 간다(고를 것도 적을 것도 없다 — v13).

## 비직관적인 것

- **그대로였어요는 시트를 열지 않고, 제보 시트 안의 한 종류도 아니다.** 긍정 신호에 시트를 열면 아무도 안 누르고,
  "정보가 달라요" 를 연 사람에게 "그대로였어요" 는 반대말이다. 버튼 이름이 보내는 것을 끝까지 말한다.
- **그대로였어요는 되돌리기 알림이 걷힐 때 보낸다**(v13, `sendPlaceReportUndoable`). 보낸 것은 다시 읽지도 지우지도 못해(insert 만) 되돌리기는
  아직 안 보냈을 때만 된다. 시간이 다 됐거나 · 다른 알림이 덮었거나 · 화면을 옮겨 셸이 걷었으면 보내고, 되돌리기를 눌렀으면 안 보낸다(`appStatus` 의 `onDismiss` —
  토스트는 누를 때 알림을 **먼저** 걷으므로 "걷힘" 만 보고 보내면 되돌리기가 곧 보내기가 된다). 따로 10초 타이머를 두지 않는 것은 알림이 hover·포커스 동안
  멈추기 때문이다 — '되돌리기' 가 보이는데 이미 보낸 때가 생긴다. 탭을 닫거나 다른 앱으로 넘어가면(`pagehide` · `visibilitychange` hidden — iOS 는
  앱 전환기에서 닫을 때 pagehide 를 믿을 수 없다) 그 자리에서 `keepalive` 로 보내고 알림을 걷는다. 하루 기록은 누르는 순간 남겨 흔적 줄이 바로 서고
  되돌리기 창 동안 버튼을 잠근다(두 번 눌림의 둘째가 쿨다운 알림으로 되돌리기를 덮지 않게) — 되돌리거나 미뤄 보내다 실패하면 걷는다(`forgetReport`).
  오프라인은 "고마워요" 를 보이기 전에 거른다.
  이 말 하나로는 아무것도 안 바뀐다 — 마지막 확인 뒤 **30일 안에 2건**이 모이면 `/admin` 에 「최근 확인으로 반영」 이 서고, 운영자가 누를 때 날짜가 바뀐다
  (한 건은 실수일 수 있고, 자동으로 올리면 열린 폐업 제보와 엇갈린다 — ADR-021 R5).

- **맨 아래에 둔다.** 제보는 다녀온 **뒤**의 동작이다. 제목 밑 액션 줄은 가기 **전**의 동작(저장·공유·네이버)이라 섞으면 액션 줄이 길어지고
  "헛걸음" 이 첫 화면의 말이 된다(07 의 판단).
  **예외 하나 — '판정이 틀렸어요' 는 판정 카드 바로 밑**(v10, 14 W261010.29a). 판정이 틀렸다는 말은 다녀온 뒤가 아니라 판정을 **읽는 그 순간**에 나온다 —
  맨 아래 카드는 문서 2018px 끝이라 화가 났을 때 못 찾았다(ferry-13 · tremor). 오른쪽 끝의 작은 회색 링크라 첫 화면의 말이 되지 않고, 카드 **밖**이라
  근거가 판정과 같은 면에 딸리는 짜임(ADR-003 v15)도 그대로다. 등급은 가리지 않는다 — 틀린 '갈 수 있어요' 가 가장 비싸다. 새 종류를 만들지 않은 것은
  `kind` 가 표의 CHECK 와 짝이라서다(운영자는 `조건` 으로 읽는다). 시트와 흔적 한 줄은 맨 아래 칸이 갖고, 상세가 여는 신호만 건넨다 — 어디서 보내든 흔적이 같이 바뀐다.
- **판정 제보의 이유는 한 줄(note) 앞머리다**(v16). `못 들어갔어요 · 10kg 넘으면 안 된대요` 로 간다 — 표에 칸을 더하면 `kind` CHECK·열 단위 grant 와 짝이라
  마이그레이션이 먼저인데, 운영자는 note 를 그대로 읽으니(접힌 줄도 앞부터) 앞머리로 충분하다. 한 줄 한도를 180자로 줄인 것은 가장 긴 앞머리를 붙여도 표의
  200자 CHECK 안에 들게 하려는 것이다(테스트가 대 본다). 말은 **사용자가 겪은 일**로만 — "판정보다 엄격했어요" 는 판정 결과를 싣는 셈이고(머리 주석·ADR-021 의 선),
  운영자는 그 사람의 강아지·판정을 모르니 읽을 수도 없다.
- **맨 아래 카드에서 보내면 알림을 띄우지 않는다**(v16). 알림 자리(탭바 위)가 그 카드의 흔적 줄과 겹쳐, 같은 말을 하는 알림이 확인 문구를 덮었다(haeun-17b).
  흔적 줄이 확인이고, 읽어 주기는 보낸 때만 채우는 숨은 `role="status"` 줄이 맡는다 — 흔적 줄 자체를 라이브 영역으로 두면 마운트 뒤 기록을 읽어 채울 때마다 읽는다.
  판정 시트는 흔적 줄이 화면 밖이라 알림을 그대로 띄운다.
- **보낸 것을 다시 볼 수 없다.** 비로그인 역할에는 select 가 없다 — 그래서 "보낸 제보 목록" 같은 화면은 만들 수 없고, 만들려면 기기 식별자를 받아야 한다(ADR-012 의 선 안쪽).
  답장도 없다. 루프가 닫힌 것은 **"최근 확인" 날짜가 바뀌는 것**으로만 보인다(F3).
- **하루 한도는 기기 쪽의 부드러운 한도다.** 같은 장소·같은 종류는 24시간에 한 번(localStorage `zgnn-reports`, 앱 스토어 `zgnn-jeju` 와 키를 가른다 — 그쪽이 깨져 지워질 때 같이 지워지지 않게).
  지우면 풀린다. 서버 한도는 없다(ADR-021 R2).
- **보낸 흔적도 이 기록 하나다**(v8). 상세 제보 칸 아래 "알려 주셨어요 — ‘문을 닫았어요(폐업·휴업)’. 운영자가 확인할게요." 한 줄
  (`recentReportKinds` · `reportTraceText`) — 토스트가 사라지면 보낸 일이 없던 것처럼 보였다. 서버에서 다시 읽을 수 없으니(insert 만) 이 기기,
  하루 창뿐이고, 창이 한도와 같아 흔적이 보이는 동안은 같은 종류를 다시 못 보낸다는 것과 맞물린다. "오늘" 이라 쓰지 않는다 — 어젯밤 것도 창 안이다.
- **실패하면 시트를 닫지 않는다.** 적은 말을 잃지 않고 다시 누를 수 있게. 오프라인 · 표 미적용(마이그레이션 전) · CHECK 위반 · 그 밖을 서로 다른 말로 한다
  (`placeReportSend.ts` 의 `classifySendFailure`). 큐에 넣어 나중에 보내기는 없다(v1 — 제보가 실제로 쌓이는 것을 본 뒤).
- **닫아도 초안이 남는다**(v12). 바깥을 건드리거나 끌어 내려 닫혀도 고른 종류·쓴 글을 지우지 않고, 다시 열면 그대로다 — 비우는 것은 보낸 뒤뿐이다.
  "정말 닫을까요?" 를 묻지 않는 것은 한 번 더 누르게 하는 것보다 잃지 않는 쪽이 싸서다. 초안은 시트가 마운트된 동안만 산다(화면을 떠나면 사라진다).
  상세의 두 시트는 **장소가 바뀌면 새로 선다**(`key={place.id}`) — A 에서 쓰다 만 "9월부터 영업 안 해요" 가 근처 장소 B 의 시트에 남으면 B 의 폐업 제보가 된다.
- **전화번호 칸은 아직 없다.** 표의 종류(`phone`)에는 있지만 고를 수 있는 목록에서 뺐다 — 번호 데이터(07 P0)가 없는데 "번호가 달라요" 를 고를 수는 없다.
- **supabase-js 를 쓰지 않는다.** POST 한 번에 GoTrue 클라이언트까지 끌려오면 사용자 화면에 인증 저장소가 생긴다. `apikey` 헤더 하나 + `Prefer: return=minimal`.

## 여기도 갈 수 있어요 — 장소 제안

입구는 넷이고 모두 같은 시트를 **가게 이름 칸 하나**로 연다(장소 id 없음, 이름 필수) — 둘러보기 목록 맨 아래 `여기도 갈 수 있어요 — 알려 주기` ·
검색만으로 어디에도 없을 때 0곳 안내의 `알려 주기`(14 W261013.10) · 홈 동네 카드의 '아는 곳이 있으면 알려 주세요' · **설정의 「장소 알려 주기」**(v11).
설정에 둔 이유: 목록 끝에만 있으면 긴 목록을 끝까지 내린 사람만 본다(tremor-34). 입구마다 이름표(`*.suggest`, ADR-029)가 달려 어디서 여는지 셀 수 있다.

- **제안은 장소를 만들지 않는다.** 동반 조건은 글(원문)에서 뽑는다(ADR-017) — 사용자의 한 줄은 근거가 아니라 단서다. `/admin` 등록 완료 칸에서
  `제보 있는 곳` 을 켜면 목록 위 「사용자가 알려 준 곳」 에 쌓이고, 운영자가 이름으로 네이버를 찾아보고 그럴듯하면 `이 이름으로 수집`(검수 대기 추가 수집과 같은 표 · 같은 워커)을 누른다
  ([ADR-019](../decisions/ADR-019-ai-cross-check-and-address-rules.md) 결정 7 의 업체명 재검색이 생기면 그 큐로 간다).
  찾을 이름은 한 줄의 첫 쉼표·대시 앞으로 채운 **칸**이라, 이름 칸에 문장을 쓴 제안도 운영자가 가게 이름만 남겨 찾는다.
- **하루 한도가 없다.** 장소가 없어 키가 하나로 모이는데, 하루 두 곳을 알려 주고 싶은 사람을 막을 까닭이 없다.
- **보낸 뒤 입구가 바뀐다**(v16) — 둘러보기 목록 끝·설정은 `알려 주셨어요 — ‘카페 바당, 애월읍’. 확인되면 올라가요.`(`suggestTraceText`, 이름은 앞 30자),
  목록 끝 버튼은 '한 곳 더 알려 주기', 같은 검색어의 0곳 안내는 '알려 주기' 를 거둔다. 홈 동네 카드는 이름 없이 '고마워요! 한 곳 더 알려 주세요' —
  시트가 권역을 몰라 다른 권역 카드에 남의 이름이 서게 된다. 토스트만 뜨고 화면이 그대로여서 또 누를 것 같았다(haeun-18b).
  기록에 남기지 않는다(한도가 없으니 꺼낼 일이 없다) — 화면을 떠나면 처음 꼴이다.
- 목록(`PlacesPageResults`) 밖에 둔다 — 스와이프 엿보기가 그 목록을 한 벌 더 그려서, 안에 두면 시트가 둘 생긴다.
- **방금 친 검색어를 이름 칸에 미리 채운다**(v7) — 찾다가 없어서 누른 사람이 같은 이름을 두 번 치지 않게. 시트는 닫혀도 마운트돼 있어
  열리는 순간에 채운다(`initialNote`). 손댄 초안이 있으면 덮지 않는다 — 비었거나 지난번에 채운 그대로일 때만 이번 검색어로 바꾼다(v12). 맨 아래 약속 줄도 제안이면 "고친 내용은 반영돼요" 가 아니라 "확인되면 올라가요"(`reportPromiseText`).

## 확인 날짜 — 루프가 닫혔다는 유일한 답장

반려동물 이용 카드 맨 아래 한 줄이 `2026년 10월에 확인했어요` 를 말한다(`placeFreshness.ts`). 제보를 처리하거나(고쳤어요) 다녀왔어요가 반영되면 이 날짜가 바뀐다.

- **날은 안 쓰고 달만 쓴다.** 날까지 쓰면 그날만 맞는 말로 읽힌다.
- **1년이 넘으면 톤을 낮춘다**(회색 + "지금은 다를 수 있어요"). 오래됐는지는 **브라우저에서만** 묻는다 — 정적 HTML 을 그리는 빌드 시각은 보는 시각이 아니다
  (`useSyncExternalStore` 의 서버 값 null).
- **그리지 않는 경우**: 확인 기록이 없다(지어낸 날짜는 없는 날짜보다 나쁘다) · 열린 폐업 제보가 있다(빌드 때 `openReportKinds`) ·
  원문에 동반 조건이 없다(`policy.noInfo`·`unread`, v6 — 서쪽에서 귤이네 등 4곳). 셋째는 **판정 레벨이 아니라 원문 플래그**로 가른다(레벨은 강아지마다 다르다).
  일반 허용 문장뿐(`genericOnly`)은 그린다 — "동반 가능" 은 확인한 사실이다. 그리지 않을 때는 날짜 줄째 빠지고 공통 AI 정리 안내 줄만 남는다(v9).
- **"무엇으로" 는 알 때만 날짜 앞에 붙는다**(v19) — `places.verified_method`: 후기를 보고 · 전화로 · 직접 가서 · 제보로(`VERIFIED_METHOD_PHRASE`). 날짜를 찍는 길이 **같은 쓰기에** 방법도 싣는다
  (`verifiedWrite`) — 날짜만 바꾸고 방법을 남기면 옛 방법이 새 날짜에 붙는다. 그래서 방법을 모를 때도 칸이 있는 원격에서는 null 로 **지운다**.
  길별: 승인(`approveGroup`)·사이트가 맞아요(`confirmSite`) = 후기 · 시드 백필(`stampSeedVerified`) = 후기(원본이 노션 후기) · 제보 `고쳤어요`·`다녀왔어요 반영` = 제보 ·
  장소 고치기 = 사실 칸을 고치는 저장일 때만 저장 줄에 「무엇으로 확인했나요」 가 서고 기본은 '모르겠어요 (날짜만)'. 번호·소개 오타만 고친 저장은 날짜를 안 찍으니 묻지도 않는다.
  **이미 찍힌 날짜(시드 86곳 등)는 방법 null 로 시작한다** — 날짜가 시드 날과 같다고 '옮긴 날' 로 치는 추정은 하지 않는다(누가 그날 다시 확인하면 조용히 틀린다).
  카드·시트의 짧은 꼬리표("2026년 9월 확인")는 방법을 말하지 않는다(메타 줄이 말줄임에 먼저 걸린다). 칸이 없는 원격(push 전)에서는 쓰기도 폼 줄도 서지 않아 깨지지 않는다.
- **목록 카드·지도 시트에는 짧게**(`freshnessShortLabel`, v5) — 종류 줄 끝 `펜션 · 10월 확인`. 신뢰가 차별점인데 상세에 들어가야 보였다.
  해까지 항상 붙인다 — `2026년 9월 확인`(v17). 예전엔 올해 것이면 달만이었는데 "9월 확인" 이 "9월에 가라는 건지" 로 읽혔고(seongho-08 · youngja),
  상세의 "2026년 9월에 확인했어요" 와 같은 말이 낫다. 지금을 모르는 정적 HTML 과 마운트 뒤가 같아져 깜빡임도 없다. 그리지 않는 경우는 상세와 같다. 1년 넘은 곳도 흐리게 하지 않는다(W261006.15 — 오래될수록 덜 보일 이유가 없다).
