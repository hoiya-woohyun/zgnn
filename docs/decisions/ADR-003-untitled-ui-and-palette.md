## 맥락 (Context)

- 표현 계층을 처음부터 만들 이유가 없어 Untitled UI(React, CLI 로 소스 복사) 를 골랐다. 시맨틱 토큰 체계(`text-primary`, `bg-brand-solid` …)가 갖춰져 있고 react-aria 기반이라 접근성이 따라온다.
- 타깃 취향은 "20대 여성이 좋아할 색, 대신 분홍만 많이 쓰면 취향을 타니 깔끔하게".
- 시행착오: 라벤더는 어둡다고 거절, 더스티 로즈(`#b03a58`)는 화면에서 와인·버건디로 읽혀 "분홍으로" 재요청. 흰 글씨 대비 4.5:1 을 지키려 어둡게 내리면 분홍이 아니게 되는 것이 문제였다.

## 결정 (Decision)

- **글꼴은 이 ADR 밖이다.** `--font-body`/`--font-sans`/`--font-display` 는 Pretendard 서브셋(`Zgnn Sans`)을 가리키며, 그 판단은 [ADR-006](./ADR-006-responsive-scale-and-font.md) 에 있다. 크기 토큰(`--text-*`)이 `--spacing` 파생이라는 것도 같은 문서.
- **원시 색은 `src/styles/theme.css` 에만.** 화면은 시맨틱 토큰만 쓴다. Tailwind 기본 `neutral` 스케일을 프로젝트 `@theme` 에서 크림·오트밀로 덮어써서 바탕색이 곧 크림이 되게 한다.
- **브랜드 = 핑크, oklch 색상 358°.** 600(`#cd2a77`, 흰 글씨 5.0:1)만 솔리드 버튼에 쓰고, 300~500 의 밝은 단계를 하트·발자국·워시에 써서 전체 인상을 분홍으로 만든다. `bg-brand-solid` 는 600 — 700 으로 내리면 다시 버건디다.
- **로고·히어로 바탕은 잉크 `#2e2327`(`--color-ink`).** 브랜드가 바뀌어도 유지.
  - **v7 — 히어로는 화면 끝까지 깔리지 않는다.** 크림 여백 위에 뜬 **라운드 판**이고, 좌우
    여백도 다른 화면과 같은 `px-4 md:px-6` 를 쓴다. 잉크 자체를 버린 것이 아니라 "맨 위 면이
    잉크" 라는 어법만 놓았다 — 맨 위 면을 전 화면 크림으로 통일하기 위해서다
    (→ [ADR-010 v3](./ADR-010-shell-owned-safe-area.md)). 팔레트 값은 하나도 바뀌지 않아
    `pnpm icons` 재생성도 필요 없었다.
  - **v7 — PWA `theme_color` 는 더 이상 이 값이 아니다.** 크림(`#faf8f4`, `--color-neutral-50`)
    이다. 같은 이유이고, `src/app/layout.tsx` 의 `viewport.themeColor` 와 `src/app/manifest.ts`
    가 짝으로 움직인다.
- **종류 색은 브랜드와 별개 토큰이고, 종류가 셋뿐이라 삼원색에 가깝게 벌린다(v6).**
  숙소 파랑 `#3670c4`(H258) / 식당 빨강 `#c14f18`(H42) / 카페 초록 `#338946`(H148).
  서로 106~110° 씩 떨어져 있어 나란히 놓이지 않아도 어느 종류인지 읽히고, 지도 핀이
  파랑·빨강·초록인 것은 지도의 오랜 관습이기도 하다.

  **왜 옛 값(바다 `#3b8ea5` / 감귤 앰버 `#cf8330` / 라떼 `#9a6846`)을 버렸나.**
  이 앱의 크림·회색은 oklch H≈70~78 인데 옛 식당(H64)·카페(H55)가 **그 색상축 위에 앉아
  있었다.** 그래서 채도를 올려도(2026-09-15 리뷰에서 카페 크로마를 0.045 → 0.08 로 올린 것이
  그 시도였다) "살짝 물든 종이"로 읽혔고, 그 수리는 끝내 듣지 않았다 — 22% 워시가 크림과
  ΔE 3.4(식당)·5.5(카페)에 그쳤고 셋 중 가장 가까운 쌍은 ΔE 2.9 로 사실상 같은 색이었다.
  지금은 워시끼리 최소 ΔE 5.0, 크림과는 5.8~7.0 이다. 노랑(H95)도 같은 이유로 후보에서
  탈락했다(크림과 ΔE 3.0).

  **지켜야 하는 두 가지.** (1) 채도는 브랜드보다 낮게 — 핑크 C≈0.205, 종류 색 0.130~0.159.
  종류 색은 분류 표지지 행동 유도색이 아니라서, 더 올리면 화면마다 CTA 와 경쟁한다.
  (2) 브랜드 색상환에서 떨어지게 — 식당 빨강을 H32 로 뒀더니 옅은 워시가 분홍으로 읽혀
  상세 헤더가 브랜드 면처럼 보였다. H42 로 밀어 44° 를 벌렸다.

  `-deep` 쪽은 **두 기준을 동시에** 만족해야 한다: 흰색 대비 5:1 이상(6.1/6.1/6.0)이면서
  자기 22% 워시 위에서 4.5:1 이상(4.50/4.53/4.57). 뒤엣것을 빼먹으면 상세 헤더에서 글씨가
  바탕에 묻는다 — 헤더가 같은 색의 옅은 그라데이션이기 때문이다(이번에 흰 바탕만 보고
  잡았다가 3.8:1 까지 떨어뜨렸다가 되돌렸다).

  `theme.css` 의 `--color-stay` 등과 `src/lib/places.ts` 의 `TYPE_COLOR` **두 곳에 같은 값**을
  둔다 — 화면(마커·타입 tint·아이콘)은 `TYPE_COLOR` 를 읽으므로 한쪽만 바꾸면 반영되지 않는다.

  부수 효과: v5 에서 "warn 배지가 식당 타입 색과 같은 색상대라 묻힌다" 던 충돌은 식당이
  앰버(H64)를 떠나면서 사라졌다.

- **`fg-quaternary`(검색 아이콘·셀렉트 화살표 등 비텍스트 아이콘)를 `#a69d93` → `#8f867c` 로.** 기존 값은 흰 배경 2.67:1 로 비텍스트 최소 기준(3:1) 미달이었다(2026-09-15 리뷰 P2). 새 값은 `bg-primary`(흰색) 기준 3.58:1, `bg-secondary`(크림) 기준 3.37:1. `neutral-400` 스케일 자체는 다른 곳에서도 참조되므로 건드리지 않고 `--color-fg-quaternary` 토큰만 덮어썼다.
- **반려동물 배지 톤(`petBadges.tsx`)도 팔레트 안으로.** `success`(초록)·`warning`(앰버)이 팔레트 밖이었고, 특히 `warning` 은 식당 타입 색(`#cf8330`)과 같은 색상대라 식당 카드에서 배지가 타입 색에 묻혔다. ok=`brand`(→ v10 에서 `gray` + 체크 아이콘), cond=`gray`(유지), warn 은 한동안 `indigo` 였다가 **채도를 0.110 으로 누른 앰버(`orange`)로 되돌렸다**(v5). indigo 는 H 277°·채도 0.240 으로 앱에서 가장 진해, "확인 필요" 라는 부가 정보가 주 버튼(브랜드 0.205)보다 먼저 눈에 드는 위계 역전이 났다. 원래의 충돌은 채도 높은 앰버끼리의 문제였고, 작은 칩과 큰 파스텔 워시는 형태가 달라 같은 색상대라도 부딪히지 않는다.
- **판정은 글자다(v24 — 아래 두 문단을 뒤집는다).** 상태 넷을 색 둘로 칠하고 있었다 — '야외 자리에서 갈 수 있어요' 와 '확인이 필요해요' 가 같은 앰버 알약(면 · 글자 · 링 셋 다 같은 값), '어려워요' 와 '정보 없음' 은 눈으로 안 갈리는 회색 둘. 그래서 넷을 **글자색 넷**으로(`VERDICT_TEXT_CLASS`, `src/lib/verdictLine.ts`): 브랜드 · 앰버 · 회색 · **빨강**. 어려움을 잉크로 두던 "불가가 아니라 어려움" 이라는 톤(ADR-005)보다 구별이 앞선다 — 어려운 곳은 목록에서 기본으로 접혀 있어 붉은 글자가 목록을 덮지 않는다. 야외만은 '갈 수 있어요 · 야외 자리만'(뒤는 `text-tertiary`) — 셈(`isReachable`)이 이미 갈 수 있는 곳에 넣는다. 원문 조건도 카드에서는 칩이 아니라 판정 뒤 회색 글자('· 최대 2마리 · 1만원 외 1개', `VerdictLine`)이고, 읍면은 메타 줄 글자('펜션 · 구좌읍 · 10월 확인', `placeMetaLine`) — 한 줄에 면 있는 요소는 최대 1개. 상세 원문 위 칩(`PetBadges`)만 남았다(22 G7.1 몫).
- **판정 배지(`eligibilityBadge.tsx`) 4단계는 "무게" 로 읽히게.** ok "갈 수 있어요"(브랜드 핑크) → cond "확인이 필요해요"(앰버) → unknown "정보가 없어요"(크림 뉴트럴) → hard "이용하기 어려워요"(잉크). `hard` 는 Untitled UI 의 `slate` 를 쓰고 있었는데 Tailwind 기본 slate 는 H 257° 의 **차가운** 청회색이라 "잉크" 라는 의도와 반대였고, 카드에서 크림 gray 칩(H 78°)과 색상환 179° 차이로 맞닿았다 — `neutral` 을 한 단계 진하게 당겨 쓴다. cond 가 파서 배지의 warn 과 같은 앰버인 것은 의도다: **이 앱에서 앰버는 언제나 "주의"** 를 뜻한다.

    켠 조건 수는 '필터 3' 칩 하나(같은 글자 줄 — 흰 원 배지·채움 없음). 칩을 가로 스크롤 줄에 둘 때는 줄을 44px 로 잡는다(`overflow-x-auto` 가 세로도 잘라 넓힌 4px 가 안 눌린다).
  - **세그먼트**(`components/segmentedControl.tsx`, 공용) — 하나만 고르는 축(강아지 기준 · 저장한 곳의 보기 · 하루 경로 출발점). 트랙 h-11 `bg-tertiary` p-1 알약,
    흰 손잡이(`bg-primary` + `shadow-xs`) **하나가** 칸 사이를 `translateX(i×100%)` 로 옮긴다, 칸 폭은 같게 · 14px · 고른 칸 `text-primary` 600 · 나머지 `text-tertiary` 400.
    트랙이 바탕(`bg-secondary`)과 같은 색이면 크림 위에서 트랙이 사라진다(22 D-16). 고르는 즉시 반영되는 자리에만 — 의미는 라디오라 화살표가 곧 선택이다.
  - **라디오 칸**(지역 읍면 3열) — 원 18px, 꺼짐 1px 테두리(아래 v16 의 `border-field` — `ring-primary` + `field-edge`), 켜짐 `ring-brand` + 8px `bg-brand-solid` 점 · 14px, 켜짐 `text-primary` 600.
  - **체크박스 칸**(원문 조건·숙소 환경 2열 — 여럿을 고르면 모두 맞는 곳, AND 를 모양이 말한다) — base `CheckboxBase` md(20px)를 `rounded-sm` 으로, 꺼짐 테두리는 v16 규칙 그대로,
    켜짐 `bg-brand-solid` + 흰 체크. 불리언 하나(실내 자리 필요)는 스위치 줄(44×24 · 켜짐 `bg-brand-solid` · 꺼짐 `bg-quaternary` — base `Toggle` 의 꺼짐 `bg-tertiary` 는 크림 위에서 안 보인다).
  - **고른 표시가 옮겨 다니는 탭**(둘러보기 숙소·식당·카페)은 2px **잉크**(`bg-primary-solid`) 밑줄 — 브랜드가 아니다. 그 화면은 탭바·지도 버튼·'갈 수 있어요' 점이 이미 핑크라
    표시까지 핑크면 지금 자리가 묻힌다. 흰 상자 안 틴트 알약 세그먼트로 형제 종류를 바꾸는 실서비스는 직접 본 8곳 중 0이었다(ADR-013 v8).
  - 페르소나 스펙의 15·13px 는 크기 토큰에 없어 `text-md`(16)·`text-sm`(14)로 반올림했다(위 네이버 버튼과 같은 이유 — 한 부품만 토큰 밖 크기면 또 하나의 어긋남).
- **버튼은 평면이다**(v23 · 22 G1 · design-audit A-11). Untitled UI 의 `shadow-xs-skeuomorphic`(inset 1px 고리 + 아래 −2px + 바깥 그림자)이 테두리 버튼엔 선을 두 겹,
  채움 버튼엔 어두운 아래 가장자리를 만들어 "찍어 낸" 티가 났다. base 는 복사본이라 그 토큰(`theme.css` — 쓰는 곳이 base `Button` 뿐)을 비운다. 테두리는 `ring-primary` 1px 하나.
  테두리 버튼의 눌림은 `bg-tertiary` — base 의 hover `primary_hover` 는 크림과 같아 눌러도 안 보여서, `globals.css` 가 react-aria 의 `data-pressed` 로 잡는다.
- **반경은 세 단이다**(v23 · A-25) — 일곱 값(r4·r6·r8·r12·r16·full…)이 섞여 자리마다 모서리가 달랐다.
  - **full** — 칩·알약(필터 칩·준비물 보기 칩·동네 꼬리표·세그먼트).
  - **r8**(`rounded-lg`) — 버튼·입력·작은 탭 대상(눌리는 행·동작 칸), 아이콘 상자·썸네일, 면 **안**에 든 작은 판(판정 카드 속 안내·준비물 줄 속 고르기 판) · 지도 위 꼬리표.
    면 안의 판을 r16 으로 하면 바깥 면과 모서리가 겹쳐 둥근 상자가 두 겹으로 보인다.
  - **r16**(`rounded-2xl` — `CARD_SURFACE`) — 면: 카드·그룹 리스트·떠 있는 안내·토스트·시트 위 모서리.
  - **예외 둘**: 체크박스 상자는 제 모양(r4~6 — r8 이면 24px 상자가 원에 가까워 라디오와 갈리지 않는다), 원문 형광 표시(`<mark>`)는 글자 줄의 r4.
    '어려움 N곳 보기' 토글은 면을 걷고 위 1px 구분선 한 줄(테두리 상자 + r12 → 면 없는 행). 운영자 화면(`/admin`)은 이 패스 밖이다.
- 저장 하트(`--color-camellia`)는 브랜드 핑크를 그대로 쓴다. 따로 붉은색을 두면 브랜드와 구분이 안 된다.

## 결과 (Consequences)

- `src/components/base/` 는 고치지 않는다(eslint 도 제외). 변형은 감싸서 만든다.
- 팔레트를 바꾸면 `pnpm icons` 로 아이콘 재생성, `scripts/make-icons.mjs` 의 FG 를 brand-300 과 맞춘다.
- 새 색이 필요하면 토큰을 추가하지 말고 기존 시맨틱 토큰이나 `typeTint` 로 표현할 수 있는지 먼저 본다.
- 다크 모드 토큰은 Untitled UI 가 제공하지만 검수하지 않았다. 지원 범위에 넣으려면 별도 점검이 필요하다.
