## 데이터 — 구현됨

```ts
// src/types.ts
export type TDogSize = 'small' | 'medium' | 'large';
export type TCarrier = 'none' | 'bag' | 'cage' | 'stroller';
export type TDogEntry = { name: string; weightKg: number };
export type TDogProfile = {
  dogs: TDogEntry[];       // 1~3마리, 마리별 이름·몸무게. 무게 상한 비교는 최댓값, 마릿수는 length
  carrier: TCarrier;       // 한 벌 — 보호자가 들고 다니는 것이라 마리마다 갈리지 않는다
  sizeOverride?: TDogSize; // 자동 계산(dogSize())을 사용자가 고친 값
};
```

`needsIndoor` 는 `TDogProfile` 에 없다 — 여행 정보라 `useAppStore.needsIndoor` 로 따로 둔다.

- 스토어 `useAppStore` 에 `dog: TDogProfile | null`, `needsIndoor: boolean`, `setDog`, `clearDog`, `setNeedsIndoor`. persist 대상. `merge` 가 `sanitizeDog`(`src/lib/dogProfile.ts`)를 거친다: `dogs` 가 1~3개이고 각 항목의 이름이 비어 있지 않고 몸무게가 양수여야 하며, `carrier` 가 enum 밖이면 `dog: null`.
- **옛 모양 `{ name, weightsKg: number[] }` 는 버리지 않고 올려 변환한다.** 이름이 하나뿐이던 v1 프로필을 버리면 사용자는 이유도 모른 채 판정이 사라진 화면을 본다. 한 마리면 손실 없이 `[{ name, weightKg }]`, 여러 마리면 첫 마리에 그 이름을 주고 나머지는 `둘째`·`셋째` 라는 자리표시자를 준다(설정 → 수정에서 고칠 수 있다). 새 모양 검사가 먼저 돌아 멱등이다 — 변환은 localStorage 에 다시 써지기 전까지 매 로드마다 돌기 때문에 이 성질이 필요하다.
- 훅은 `src/store/useAppStore.ts` 의 `useDog()` 과 `src/store/useDogEligibility.ts` 의 `useEligibility(place)` · `useEligibilityMap()`(dog·needsIndoor 가 바뀔 때만 재계산).
- 크기 기본값(`dogSize()`, `src/lib/eligibility.ts`): `< 10kg → small`, `10~25 → medium`, `> 25 → large`. 원문의 "대형견" 과 정확히 일치한다는 보장이 없어 프로필 폼의 "크기 수정" 접힘에서 `sizeOverride` 로 고칠 수 있다. 크기는 **프로필에 하나**이고 가장 무거운 아이로 정한다 — 두 마리 이상이면 접힘 머리의 괄호가 "(몸무게로 정했어요)" 대신 "(가장 큰 아이 기준으로 봐요)" 다.

## 프로필 폼 — 구현됨 (`src/screens/dogProfilePage.tsx`)

- 마리별 행(`DogProfileDogRows`, 최대 3행, "한 마리 더"/행 삭제 — 이름이나 몸무게가 있던 행을 빼면 셸 토스트 "두부를 뺐어요 · 되돌리기" 10초, 빈 행은 알리지 않는다. 폼 안의 일이라 되돌리면 폼만 돌아온다(`restoreDogFormRow`, 14 W261010.7a). 키보드로 ✕ 를 누르면 포커스는 Tab 이 그 ✕ 다음에 가던 곳으로 — 뒤에 행이 있었으면 한 칸 올라온 그 행의 이름 칸, 마지막 행이었으면 '한 마리 더'(`dogRowFocusAfterRemove`, 14 W261010.7b). 행 key 가 순번이라 그냥 두면 같은 자리 ✕ 가 다음 마리 것이 되어 Enter 한 번 더에 그 마리가 빠졌다. 손가락으로 누른 ✕ 는 옮기지 않는다(`:focus-visible` — 이름 칸에 포커스를 주면 폰 키보드가 올라온다)) — 행마다 이름(필수, 12자) + 몸무게. 입력 중에는 채워 넣은 값이 틀렸을 때만(0 이하·숫자 아님·12자 초과) 행 에러를 보이고, 빈 칸은 저장을 눌렀을 때 잡는다("이름을 입력해 주세요"/"몸무게를 입력해 주세요") · 이동 수단 4택(`DogProfileCarrierPicker`, 각 한 줄 설명 — **기본 선택 없음**, 안 골랐으면 주 버튼이 "이동 수단 고르기" 이고 누르면(이름 칸의 Enter 도) 검사도 오류 문구도 없이 첫 옵션을 가운데로 올려 포커스 — 14 W261019.7. 이동 수단으로 막히는 일이 없어 그 오류 줄은 없앴다. 기본값 '없어요' 로 두었더니 가방이 있는 사람도 그대로 저장해 식당 대부분이 "어려움" 으로 조용히 뒤집혔다. 기존 프로필은 저장된 값으로 채워진다) · "크기 수정" 접힘(`DogProfileSizeOverride`, 자동 계산값 표시 + 셀렉트로 override) · 저장(**온 곳으로 되감는다** — 앱 안에서 왔으면 `router.back()`, 딥링크로 폼에 바로 들어왔으면 되감을 곳이 없어 부모 `/settings` 로 `replace`. 셸의 뒤로가기와 같은 규칙(`appHistory`)이라 저장 뒤 뒤로가기가 폼으로 가지 않는다. 도착 화면에 셸 상태 줄로 "보리 기준으로 바꿨어요"(`dogProfileSavedMessage`) — 셸이 그리고, 화면이 바뀌면 걷히는 것이 기본이라 이 알림만 `keepOnNavigate` 로 남긴다) · 등록돼 있으면 삭제(주 버튼 줄 밖, 떨어진 조용한 위험 글자 버튼 — 지운 뒤엔 같은 높이의 "프로필을 지웠어요" 줄이 그 칸을 지켜 두 번 눌림의 둘째가 '등록하기' 로 가지 않는다, 14 W261010.7d. 확인 없이 즉시, `window.confirm` 미사용 — 대신 셸 토스트 "프로필을 지웠어요 · 되돌리기" 10초 — 이 화면을 떠나면 걷힌다(다른 화면에 남으면 그 화면의 일로 읽힌다, 14 W261013.9). 지운 프로필은 그 클로저만 붙잡고 저장하지 않는다. 화면 안 배너는 폼 맨 위라 맨 아래 버튼을 누른 사람에게 안 보여 없앴다, [todo/12](../todo/12-ux-audit-2026-10-02.md) U2.1).
- **폰에서 주 버튼 줄은 탭바 위에 붙는다**(sticky — W261010.2). 붙어 있는 줄은 뒤의 칸을 가리므로 그 칸이 말해야 할 것을 줄이 대신 말한다(`dogProfileActionNote` — 안 고른 이동 수단, 이름·몸무게로 막혔을 때의 요약). **주 버튼의 말은 누르면 일어나는 일이다**(`dogProfileSubmitLabel`, 14 W261019.7) — '등록하기' 라 적힌 진한 버튼이 눌러도 등록이 안 되고 빨간 글씨를 냈다. 폰에서 이동 수단이 폴드 아래라 이름·몸무게만 넣고 누른 것이 2/6 이었고(youngja-05 · minji-04), 줄의 회색 안내는 그 버튼 옆에서 읽히지 않았다. 몸무게를 넣으면 스크롤해 주는 쪽은 쓰지 않았다 — 입력 중에 화면을 끄는 것은 폰 키보드와 다투고, 누르기 직전 blur 에 걸리면 버튼이 움직인다. 줄의 면은 탭바 윗선까지 내려오고 원이 솟는 띠는 줄 아래 여백이 된다(틈으로 선택지가 비쳐 지나가 덜 만든 것처럼 보였다). Tab 포커스는 `data-sticky-action` 이 켜는 아래 스크롤 여백으로 줄 위에 선다(globals.css).
- **저장 알림은 판정 수가 얼마나 바뀌었는지까지 말한다**(14 W261010.33a) — "보리 기준으로 바꿨어요 · 갈 수 있는 곳 71 → 54곳". "기준으로 바꿨어요" 만으로는 무엇이 바뀌었는지 몰라 홈으로 가서 숫자를 견줘야 했다(designer-20 · junhyuk-23, 반복 2회). 수는 홈 히어로와 **같은 함수**(`homePageReach`, 같은 `needsIndoor`)로 저장 직전·직후를 센다 — 따로 세면 알림의 54 와 돌아간 홈의 숫자가 갈린다. 처음 등록이면 지금 수만, 같으면 "그대로 N곳"(몸무게를 고쳤는데 말이 없으면 저장이 안 된 것으로 읽힌다). 몸무게뿐 아니라 이동 수단·크기 수정·마리 수가 바뀌어도 같은 줄이다. 알림 속 이름은 **적은 그대로**(`dogNamesAsWritten` — "단풍 기준으로 바꿨어요")다: 방금 적은 이름을 되비추는 말이라 '단풍이' 로 쓰면 이름이 바뀐 것으로 읽히고, 같은 폼의 "두부를 뺐어요" 와 돌아간 설정 카드 제목도 적은 그대로다(14 W261010.33h).
- 화면을 떠나면 쓰다 만 입력이 모듈에 남아(`dogProfileDraft`) 돌아오면 되살아난다. 되살렸고 아직 저장된 값과 다르면 맨 위에 "저장하지 않은 입력이에요" 와 되돌리기 — 이번 방문에 고친 것에는 뜨지 않는다.
- `useAppStore` 가 `skipHydration: true` 라 첫 렌더는 항상 `dog: null` 이다. 폼은 하이드레이션이 끝날 때까지 그리지 않고("불러오는 중"), 끝난 시점의 `dog` 로 한 번만 초기값을 채운다(렌더 중 상태 조정 패턴 — 이펙트로 하면 빈 폼이 한 프레임 보였다가 채워진다).
  - 기다리는 기준은 **"읽기가 끝났나"**(`useStoreHydrated()`)지 "성공했나"(`persist.hasHydrated()`)가 아니다. 저장된 값이 깨지면 후자는 영원히 false 라 이 화면이 "불러오는 중이에요…" 에 갇혔다(→ [BUG-002](../bugs/BUG-002-hydration-deadlock.md)). 읽기에 실패했으면 **저장된 것이 없는 사람과 같은 상태**로 빈 폼을 그린다.

## 판정 — 구현됨

`src/lib/eligibility.ts`

```ts
export type TEligibilityLevel = 'ok' | 'cond' | 'unknown' | 'hard';
export type TReason = { level: TEligibilityLevel | 'info'; text: string; quote?: string };
export type TEligibility = { level: TEligibilityLevel; reasons: TReason[]; fee?: string };

export const dogSize: (dog: TDogProfile) => TDogSize;
export const judgeEligibility: (dog: TDogProfile, policy: TPetPolicy, opts?: { needsIndoor?: boolean }) => TEligibility;
export const compareEligibility: (a: TEligibilityLevel, b: TEligibilityLevel) => number; // ok < cond < unknown < hard
```

규칙표는 [architecture/pet-policy-and-eligibility.md §3](../architecture/pet-policy-and-eligibility.md#3-판정--구현됨) 에 있다. 첫 매치가 아니라 **전부 평가해 가장 센 레벨**을 채택하고, `reasons` 는 심각도순으로 정렬된다.

요금 문구는 `src/lib/dogFee.ts` 의 `formatDogFee(policy, dog)` — `TEligibility.fee` 와 info 근거에 같은 문자열이 들어가고 카드는 그대로 출력한다(예전엔 카드가 이름을 따로 붙였다). 이름이 들어가는 문장은 `src/lib/korean.ts`(`dogCallNames`·`withJosa`)를 거친다. **애칭('단풍' → '단풍이')은 조사가 붙어 문장 안에서 강아지를 부르는 자리에만** 쓴다 — 홈 인사·히어로("단풍이랑 제주 어디 갈까요?")·동네 카드·판정 머리글·요금·"○○만 데려가면"·지도 흐림 범례·근처 장소. 이름만 서는 자리(설정 카드 제목)와 폼에 적은 이름을 되비추는 알림은 적은 그대로(`dogNamesAsWritten`)다(14 W261010.33h).

테스트(`eligibility.test.ts`)는 프로필 3종(두부 4kg·이동가방 / 보리+콩 28kg+17kg·이동 수단 없음 / 콩 17kg·케이지)에 대해 실제 장소(웨스티하우스·모닥식탁·무거버거·맘앤도그·솔숲펜션)의 기대 판정을 적고, 보리+콩 프로필로 86곳 전체를 집계해 디자인 리뷰의 사람 판단(가능 9·조건부 30·어려움 42·정보 없음 5) ±5 안에 들어오는지 확인한다(구현 결과: 7·32·42·5 — 전부 ±5 안).
