# ADR-021: 사용자 제보는 Supabase 에 insert 만 — 사이트가 처음으로 런타임에 쓴다

> 최종 수정: 2026-10-05 (v2: R5 의 날짜가 **판정에도** 쓰인다 — 일반 허용 문장뿐("애견동반 가능해요")인 곳은 이 날짜가 없으면 '확인이 필요해요'(C9,
> [todo/13](../todo/13-ai-analysis-audit-2026-10-04.md) A2). 그래서 날짜를 찍는 길이 늘면 판정이 '갈 수 있어요' 로 풀린다 — 승인이 조건 확인인지는 T2.1 의 열린 결정)
> 이전 2026-10-01 (v1: [docs/todo/10](../todo/10-user-feedback-personas.md) 의 결정 R1~R5 를 옮겼다. 🙋 1~4 는 권장안으로 닫혔다 —
> 받는 곳은 Supabase insert-only, 카테고리는 6 + `visited_ok`·`suggest` 를 한 표에, "다녀왔어요" 는 받되 건수는 안 보인다, 장소 제안은 받는다(처리는 재검색 큐가 생기기 전까지 `/admin` 목록)
> 상태: **표는 파일로 있다**(`supabase/migrations/20261001130000_place_reports.sql`, **원격 미적용** — 🧑 `supabase db push`). 표가 없으면 상세의 제보는
> "지금은 보낼 수 없어요" 로 실패를 말하고, `/admin` 은 제보 칸을 `미적용` 으로 그린다.

## 맥락

운영자(사용자)의 첫 피드백이 "이 매장에 대해 말할 수 있는 게 없다 — 폐업했는지, 주소가 틀렸는지 제보할 버튼이 있어야 한다" 였고,
반려인 페르소나 셋(노령견 · 다두 가족 · 뚜벅이)이 각자 다른 길로 같은 자리에 닿았다 — **앱의 답이 틀렸을 때 사용자가 할 수 있는 일이 없다**.

그런데 이 앱은 정적 내보내기이고 [ADR-015](./ADR-015-supabase-source-and-rebuild.md) §2 가 "사용자 화면은 런타임 fetch 없음" 을 원칙으로 둔다.
제보를 받는다는 것은 그 원칙을 **처음 깨는** 일이라, 어디까지 깨는지를 결정으로 못 박는다.

## 결정

**R1. 제보는 Supabase `place_reports` 에 비로그인(publishable) insert 로 받는다.** 구글 폼·mailto 는 코드가 0 이지만
[ADR-020](./ADR-020-pipeline-stages-and-blocklist.md) 의 영구 제외(`place_blocks`)와 **이어지지 않는다** — 폐업 제보가 블랙리스트까지 가려면
사람이 폼 응답을 읽고 `/admin` 에 옮겨 적어야 하고, 그 단계가 있으면 안 한다. 깨는 범위는 **"insert 한 번, 읽기 없음"** 이다.
`/admin` 이 이미 같은 publishable 키·같은 호스트로 붙으므로 번들 유출 검사(`check-bundle`)에 새로 열 것은 없다.

**R2. 경계는 GRANT · RLS · CHECK 다. 서버 쪽 속도 제한은 두지 않는다.**
- 비로그인 역할에는 **열 단위 insert**(`place_id, kind, note, app_build`)만 준다. select 가 없으니 보낸 것을 다시 읽을 수 없다 —
  보내는 쪽(`placeReportSend.ts`)은 `.insert()` 뒤에 `.select()` 를 **붙이지 않는다**(붙이면 RETURNING 이 select 권한을 요구해 42501).
- 정책 `with check`: 열린 상태로만, 장소는 **사이트에 보이는 것**(`published`)만, `suggest` 는 장소 없이. CHECK: `kind` 목록 · `note ≤ 200자` · 모양(제안은 이름 필수).
- 남용은 **표가 커지는 것** 이상이 아니다 — 이 표는 재빌드 방아쇠가 아니다(트리거를 붙이지 않는다. 붙이면 제보 한 건이 프로덕션 빌드 한 번이 된다).
  폭주하면 `anon_insert` 정책 하나를 끄는 것이 대응이다. 기기 쪽에는 **부드러운** 한도(같은 장소·같은 종류 24시간 1번, localStorage)만 둔다.
  Edge Function·CAPTCHA 는 쓰지 않는다 — 익명·답장 없음·효과 작음.

**R3. 운영자에게도 delete 가 없다.** 처리는 상태 한 칸 `open → handled | dismissed`(+ `handled_note`·`handled_at`)이고 `dismissed` 가 삭제다
([ADR-018](./ADR-018-in-app-admin-review.md) 결정 6~8 과 같은 선). 새 표라 grant·정책을 마이그레이션에 같이 쓴다(`20260922120000` 뒤로 자동으로 안 붙는다).

**R4. 제보는 장소에 대한 말이다.** 사이트에 보이는 것만 제보할 수 있고, 장소를 내리면 그 장소의 열린 `closed`·`replaced` 제보는 `handled` 로 함께 닫힌다.
`/admin` 에는 **두 번째 내리기 버튼을 만들지 않는다** — 폐업 제보의 `등록 해제` 는 기존 해제 폼(사유 `폐업` 을 미리 고른 채, 블랙리스트 영구가 기본)을 연다.
둘이 생기면 한쪽만 `place_blocks` 를 쓰게 된다.

**R5. "최근 확인" 날짜(`places.verified_at`)는 사람이 쓴다.** 갱신하는 길은 셋 — 운영자의 승인·주소 수정·제보 처리, `visited_ok` 제보가
**30일 안에 2건 이상**일 때 운영자가 「최근 확인으로 반영」 을 누르는 것(자동 아님 — 한 번 본다), 재분석 덮어쓰기. 트리거가 아니라 **쓰는 코드가** 찍는다.
열린 `closed`·`replaced` 제보가 있으면 상세는 날짜를 **그리지 않는다**(확인됐다고 말하는 순간 제보가 거짓이 된다) — 이 사실은 빌드 때
`data:pull` 이 `place_report_flags()`(security definer, 장소 id 만 돌려준다)로 옮긴다. 런타임 읽기는 여전히 없다.
**건수·제보 내용은 사용자에게 보이지 않는다** — 후기 서비스가 아니다.

## 받지 않는 것

연락처 · 위치 · 기기 식별자 · 강아지 프로필 · 판정 결과. 열이 없으니 실을 수도 없다 — 하나라도 받으면
[ADR-012](./ADR-012-personal-data-and-consent.md) 의 문서 묶음(방침·동의·파기)이 먼저 필요하다. 그래서 **답장도 없다**:
루프가 닫혔다는 것은 "최근 확인" 날짜가 바뀌는 것으로만 보인다.

## 결과

- 사이트 번들에 쓰기 경로가 하나 생긴다(`src/lib/placeReportSend.ts`). `/admin` 의 클라이언트(`adminSupabase.ts`)는 **재사용하지 않는다** —
  세션·storageKey 를 들고 있어 사용자 화면에 끌려오면 안 된다.
- 표가 원격에 없으면 보내기는 실패를 말하고(오프라인과 같은 자리), `/admin` 은 `미적용` 이다.
- `app_build`(`NEXT_PUBLIC_APP_BUILD` = 커밋 앞 7자, 없으면 `dev`)로 "어느 데이터를 보고 한 말인가" 를 안다.

## 고려했다 버린 것

| 안 | 왜 버렸나 |
|---|---|
| 구글 폼 | 코드 0 이지만 처리 결과가 `places`·`place_blocks` 로 이어지지 않는다 — 옮겨 적는 단계가 생긴다 |
| mailto | 위와 같고, 메일 주소(개인정보)가 따라온다 |
| Edge Function + 서버 속도 제한 | 익명 제보의 남용 효과(표가 커짐)에 비해 운영할 것이 많다. 정책 하나 끄는 것이 대응으로 충분하다 |
| 제보·방문 건수 공개 | 숫자가 적으면 "제보 1건" 이 신뢰를 깎고, 많아지면 조작 유인이 생긴다 |
