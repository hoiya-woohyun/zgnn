# ADR-008 — 지도를 Kakao 지도로, 마커는 표준 핀으로

> 최종 수정: 2026-09-17 (v3: 개발·preview 포트를 7727 로 고정 — 등록 출처를 `http://localhost:3000` 에서 `http://localhost:7727` 로 옮김)
>
> 최종 수정: 2026-09-17 (v2: 지도 화면의 조건을 종류 3개만 남기고 정리 — 읍면 피커·어려운 곳 숨기기 제거, 그에 딸린 시야 맞춤과 `kakaoMapLevel.ts` 도 함께 삭제)
>
> 최종 수정: 2026-09-17 (v1: leaflet + OSM/CARTO 타일에서 Kakao 지도 SDK 로 교체)

## 맥락

지도는 leaflet + react-leaflet 에 OSM 기본 타일(CARTO 키가 있으면 CARTO Voyager)을 얹어
쓰고 있었다. 두 가지가 걸렸다.

- **타일이 한국 지도가 아니다.** 제주의 읍면·포구·올레길 이름이 OSM 에서는 성기고, 표기가
  영문과 섞인다. 이 앱은 "짱구누나가 다녀온 제주"를 보여주는 물건이라 지명이 한국어로
  촘촘한 편이 낫다.
- **마커를 우리가 너무 많이 그리고 있었다.** 종류마다 원·둥근사각·물방울을 직접 그리고,
  판정에 따라 테두리를 점선으로 바꾸거나 회색을 입히고 투명도를 조절했다. 코드는 무거운데
  지도 위 18px 도형에서 그 차이는 읽히지 않았다.

## 결정

**Kakao 지도 JavaScript SDK** 로 바꾸고, 마커는 SDK 의 표준 `Marker` 에 **종류 색만 입힌 핀**을
쓴다.

- SDK 는 npm 패키지가 아니라 `dapi.kakao.com` 이 내려주는 스크립트다. 정적 내보내기라
  서버에서 심을 자리가 없어 지도 화면이 뜰 때 `src/lib/kakaoMap.ts` 가 직접 붙인다.
  `autoload=false` + `kakao.maps.load(cb)` 로 초기화 경합을 없앤다.
- 마커 모양은 `MarkerImage` 에 인라인 SVG data URI 하나. 외부 이미지를 받지 않는다.
- 종류 색(`TYPE_COLOR`)은 남긴다 — 이 앱엔 장소 사진이 없어서(→ [ADR-002](ADR-002-no-place-photos.md))
  종류를 가르는 신호가 색뿐이다.
- 판정(eligibility)의 시각 인코딩은 **`hard` 의 투명도만** 남기고 걷어냈다. 투명도는
  `Marker` 의 기본 옵션이라 덧칠이 아니다. 나머지(점선 테두리 = 확인 필요, 회색 테두리 =
  정보 없음)는 마커를 눌러 열리는 시트와 목록 화면의 배지가 이미 더 정확하게 말한다.

### 지도의 조건은 종류 3개뿐이다

같은 작업에서 지도 위 컨트롤을 **숙소·식당·카페 칩 3개**로 줄였다. 지도가 답하는 질문을
"숙소·식당·카페가 제주 어디에 있나" 하나로 좁힌 것이고, 나머지는 다음 이유로 뺐다.

| 뺀 것 | 이유 |
|---|---|
| 방향(동/서/남/북) | 지도 위에서 "동쪽만 보기" 는 지도를 동쪽으로 끄는 것과 같은 일이다. 무엇을 뜻하는지도 읽는 사람마다 달랐다 |
| 읍면 피커 | 고르면 그 읍면으로 시야를 날려 주는 컨트롤이었다. 확대·이동은 지도가 이미 가진 기능이라 버튼으로 옮겨 놓을 이유가 없다 |
| 어려운 곳 숨기기 | 판정을 좁혀 보는 일은 조건과 정렬이 다 있는 둘러보기 목록이 더 잘한다. 지도에는 `hard` 를 흐리게 그리는 신호만 남겼다 |
| 지도에 없는 N곳 링크(모바일) | 5곳 남짓을 가리키려고 지도 위에 줄을 하나 더 쓰는 값이 안 나왔다. 자리가 넉넉한 데스크톱 좌측 패널에는 남겼다 |

방향·읍면은 **목록 화면(`placesPage`)에는 그대로 있다.** 거기엔 지도가 없어서 그 조건들이
유일한 지역 감각이다 — 같은 컨트롤이라도 화면이 다르면 값어치가 다르다.

## 결과

### 조용히 깨지는 자리 — 확대 수준의 방향이 반대다

leaflet 의 `zoom` 은 클수록 확대지만 Kakao 의 `level` 은 **작을수록** 확대다(ROADMAP 1~14,
기본값 3). 숫자를 옮겨 쓸 수 없고, 부호를 뒤집어도 빌드와 테스트는 통과한다.

`JEJU_LEVEL = 10` 은 화면을 보고 정했다. 예전 `JEJU_ZOOM = 10` 과 숫자가 같은 것은 **우연**이다 —
두 체계는 척도가 달라 대응 관계가 없다.

이 앱은 **처음 한 번 말고는 시야를 코드로 옮기지 않는다.** 지도를 연 순간 제주 전도를 보여
주고, 그 다음은 사용자가 끌고 확대한다. 그래서 `setBounds` 도, 그 뒤에 붙던 level 하한
계산(`kakaoMapLevel.ts`)도 지금은 없다.

나중에 "이 읍면 보여줘" 같은 것을 다시 넣는다면 그때 함정이 하나 있다: Kakao 의 `setBounds`
에는 leaflet 의 `maxZoom` 에 해당하는 인자가 없어서, 맞춘 **뒤에** `getLevel()` 을 읽어 하한으로
눌러야 한다. 방향이 반대라 그 연산은 `Math.min` 이 아니라 `Math.max` 다. 하한이 없으면 장소가
한두 곳뿐인 읍면에서 그 점까지 파고들어 주변 맥락이 사라진다.

### 오프라인 — 외부 코드에 의존하게 됐다

이 앱은 글꼴까지 self-host 해서 런타임 외부 요청을 0 으로 두는 것이 원칙이었다
(→ [ADR-001](ADR-001-pwa-static-export.md)). Kakao SDK 는 그 원칙에서 벗어나는 **유일한
런타임 외부 코드**다. leaflet 때는 타일만 못 받고 마커·컨트롤은 그려졌지만, 이제는 스크립트를
못 받으면 지도 영역에 보여줄 것이 남지 않는다.

두 가지로 받는다.

1. 서비스워커가 `dapi.kakao.com` 을 **StaleWhileRevalidate** 로, 타일(`*.daumcdn.net`)을
   **CacheFirst** 로 캐시한다. 한 번 지도를 연 기기는 비행기 모드에서도 SDK 사본으로 지도를
   띄우고 받아 둔 타일로 본 지역을 그린다(2026-09-17 실측: 오프라인에서 타일 21장·마커·지명이
   그대로 그려진다). SDK 를 CacheFirst 로 두지 않는 이유는 우리가 버전을 못 정하는 남의
   코드이기 때문이다 — 오래된 사본에 못 박히면 SDK 가 바뀔 때 조용히 깨진다.
2. 그래도 못 받으면 지도 자리에 "지도는 인터넷이 필요해요" 와 장소 목록으로 가는 버튼을
   띄운다. 빈 화면은 고장으로 읽힌다.

#### 타일 캐시에는 `statuses: [0, 200]` 이 필수다

타일은 SDK 가 만든 `<img>` 가 `crossorigin` 없이 받아 오므로 응답이 **opaque**(status 0)로
온다. CacheFirst 는 기본으로 200 만 저장해서, `CacheableResponsePlugin({ statuses: [0, 200] })`
이 없으면 규칙이 붙어 있어도 **캐시가 아예 만들어지지 않는다.** 규칙이 존재한다는 것과
동작한다는 것이 다른 자리라, `out/sw.js` 에서 문자열을 grep 하는 것으로는 확인되지 않는다 —
실제로 캐시 항목 수를 세야 한다.

교체 전 OSM/CARTO 규칙이 정확히 그 상태였다. "한 번 본 지역은 오프라인에서도 보인다" 는
`pwa-offline.md` 의 서술은 leaflet 시절 내내 사실이 아니었고, 2026-09-17 에 이 작업을 검증하다
발견해 함께 고쳤다.

한 가지 더: opaque 응답은 브라우저가 용량을 실제보다 크게 잡아(패딩) 할당량을 먹는다.
그래서 `maxEntries` 를 옛 규칙의 500 이 아니라 **200** 으로 뒀다 — 너무 많이 쌓으면 라우트
HTML 프리캐시까지 통째로 밀려날 수 있다.

### 키와 도메인 등록

JS 키는 **출처(origin) 허용 목록**으로 보호되는 공개 값이다. 어디에 두든 빌드 결과물의 JS 에
문자열로 남으므로 기본값을 코드(`src/lib/kakaoMap.ts`)에 두고, 갈아야 할 때만
`.env.local` 의 `NEXT_PUBLIC_KAKAO_MAP_KEY` 로 덮어쓴다. `.env.local` 에만 두면 새로 clone 한
곳에서 지도가 조용히 죽는다 — CARTO 때와 달리 키가 없을 때 쓸 대체 타일이 없다.

**Kakao Developers 콘솔 → 내 애플리케이션 → 플랫폼 → Web 에 주소를 등록해야 한다.**
등록 전에는 코드가 맞아도 SDK 가 인증 오류를 내고 지도 자리가 빈다.

- 개발: `http://localhost:7727`
- 배포: 도메인이 정해지면 추가할 것 (2026-09-17 기준 미정)

**포트까지 봐서 막는다.** `pnpm preview` 가 임의 포트(예: 52164)로 뜨면 같은 localhost 인데도
SDK 가 `401` 을 낸다. `pnpm dev` · `pnpm preview` 둘 다 **7727 로 고정**해 둔 이유가 이것이다
(포트를 바꾸려면 콘솔에 그 포트를 먼저 등록할 것). 안 그러면 코드가 멀쩡한데 지도만 비어
원인을 엉뚱한 데서 찾게 된다.

### 잃은 것

마커의 키보드 접근이 없어졌다. leaflet 때는 `divIcon` 이 만든 엘리먼트에 `role=button` 과
`tabindex` 를 얹어 탭으로 마커를 돌 수 있었지만, SDK 의 `Marker` 는 우리가 그 엘리먼트를
받지 못한다. `CustomOverlay` 로 되돌리면 되찾을 수 있으나 그것이 곧 "직접 그리기" 로 되돌아가는
길이다. 같은 장소를 44px 행으로 고를 수 있는 목록(`/places/*`)과 데스크톱 좌측 결과 패널이
항상 있어서 키보드만으로도 모든 장소에 닿을 수 있다는 점을 근거로 감수했다.
