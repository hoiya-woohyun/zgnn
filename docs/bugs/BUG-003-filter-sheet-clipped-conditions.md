# BUG-003 — 모바일 필터 시트의 마지막 조건이 잘린 채 멈춘다

> 최종 수정: 2026-09-17 (v1: 신설)

## 증상

둘러보기의 모바일 필터 시트에서 **맨 아래 "우리 강아지 기준"("어려운 곳 숨기기" ·
"실내 자리 필요")이 칩 한가운데가 잘린 채** 보인다. 잘린 높이가 얼마 안 돼 스크롤바도 뜨지
않아서, 스크롤이 남은 것이 아니라 **원래 그렇게 생긴 줄로 읽힌다.** 그 두 조건에 손이 닿지
않으니 "필터가 작동하지 않는다" 로 느껴진다.

세로가 짧은 기기일수록 더 많이 잘린다.

## 재현 조건

- 모바일 폭(`md` 미만)에서 둘러보기 → **필터** 버튼
- 강아지 프로필이 등록돼 있어야 한다 — "우리 강아지 기준" 묶음은 프로필이 있을 때만 그려진다
- 숙소 탭이면 "가격 정렬" 줄이 하나 더 있어 더 심하다

측정값(뷰포트 820px, 숙소 탭, 프로필 있음):

| | 값 |
|---|---|
| 스크롤 영역 높이 | 574px (= 70dvh) |
| 그 안의 내용 높이 | 592px |
| 시트 패널 전체 높이 | 689px (뷰포트의 84%) |

## 원인

조건 묶음 하나에 `max-h-[70dvh] overflow-y-auto` 를 걸어 두었다. 그 70dvh 는 **시트가
실제로 쓰는 높이가 아니다** — 제목("필터"), "필터 모두 지우기" 줄, 시트 안쪽 여백
(`pt-6` 핸들 자리 · `pb-sheet`)이 그 밖에 따로 붙는다. 그래서 시트는 화면의 84% 를
차지하면서 정작 스크롤 영역은 70% 에 묶였고, 남은 18px 이 마지막 칩을 반으로 잘랐다.

요컨대 **하나의 높이 상수가 두 가지를 동시에 정하려 했다** — "시트가 화면을 얼마나 덮나"
와 "그 안에서 무엇이 스크롤되나". 조건이 늘거나(프로필 유무·숙소의 정렬 줄) 화면이 짧아지면
둘의 어긋남이 그대로 잘린 높이가 된다.

## 수정

시트 전체를 세로 flex 로 묶고 **가운데 조건 줄만** 스크롤시킨다.

```
flex max-h-[80dvh] flex-col
├─ h2 "필터"            shrink-0      ← 늘 보인다
├─ 조건들               min-h-0 flex-1 overflow-y-auto
└─ "필터 모두 지우기"    shrink-0      ← 늘 같은 자리
```

`min-h-0` 이 요점이다. flex 자식은 기본 `min-height: auto` 라 내용보다 작아지지 않는다 —
바깥을 아무리 묶어도 스크롤이 안 생기고 밖으로 삐져나간다. 이제 화면이 짧아지면 **가운데만
줄어들고** 제목과 지우기 버튼은 남는다.

여기에 "아래 더 있다" 는 신호로 스크롤 줄 끝을 흐린다 — 가로 조건 줄이 쓰는 것과 같은
장치의 세로판이다(`placesPageFilters.tsx` 의 `SCROLL_ROW_CLASS`). 아래 여백(`pb-6`)을 마스크
시작점보다 넓게 잡아, 끝까지 내렸을 때 마지막 칩은 마스크 밖(완전 불투명)에 남는다.

`bottom-sheet.tsx` 는 건드리지 않았다 — 잘못된 상수가 부르는 쪽에 있었고,
`src/components/base/` 는 직접 고치지 않는 폴더다.
