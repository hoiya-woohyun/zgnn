## 0. 한 줄 요약

**경로 짜기는 우리, 운전 안내는 네이버.** 저장한 곳을 날짜별로 묶고 현재 위치 기준으로 순서를 제안한 뒤, 그 순서를 `nmap://route/car` 한 줄(경유지 최대 5)로 넘긴다.
우리만 할 수 있는 부분은 그 순서에 **판정을 얹는 것** — "이 조합이면 콩이가 다 갈 수 있나", "보리 때문에 안 되는 곳은 이 날 빼자".
경쟁 앱 다섯 어디에도 없는 기능이고, 서버·길찾기 API·비용이 **0** 이다.

## 1. 왜 3단계를 만들지 않나

| 단계 | 내용 | 필요한 것 | 결정 |
|---|---|---|---|
| 1 | 저장한 곳을 날짜별로 묶고 순서 정하기(직선거리) | 좌표(86곳 중 81) · `distanceSort.ts` · `savedIds` | **한다** |
| 2 | 묶음 단위 판정("둘 다 갈 수 있나") · 하루 안 충돌 | `eligibility.ts` · `dogSubsetWhatIf.ts` | **한다** |
| 3 | 실제 운전 경로·소요 시간·턴바이턴 | Directions API(서버 한 겹 + 키 + 호출 비용) 또는 자체 내비 | **안 한다** → 네이버 앱에 넘김 |

- 정적 내보내기(서버 없음)라 Directions 키를 둘 곳이 없다. 서버 함수를 들이는 순간 ADR-015 "사이트는 런타임 fetch 없음" 이 두 번째로 깨진다(첫째는 제보 insert).
- 제주는 섬 하나다. 직선거리 × 1.3 이 차로 거리의 어림으로 충분하고, "몇 분" 은 네이버가 더 잘 안다.
- 네이버 지도 앱 URL 스킴은 **경유지 5곳까지 한 번에** 받고, 출발지를 비우면 현재 위치가 출발지다. 우리가 할 일은 순서를 정해 URL 하나를 조립하는 것뿐이다.

## 2. 지금 코드에 있는 것 / 없는 것 (2026-10-06 `develop`)

**있는 것**
- `useAppStore.savedIds` + `savedNotes`(30자 메모, 저장 해제 시 함께 지움) — 날짜 묶음은 이 옆에 선다.
- `distanceSort.ts` — `sortByDistance` · `distancesFrom` · `distanceLabel`. 순수 함수, 테스트 있음.
- `myLocation.ts` — `locateMe()` 한 번 받고 버린다. 지도의 "내 위치" 버튼과 목록의 "가까운 순" 이 쓴다.
- `eligibility.ts` · `dogSubsetWhatIf.ts` — 장소 하나에 대한 판정과 "○○만 데려가면".
- `naverLinkButton.tsx` — 네이버로 나가는 버튼 한 종류. `naverPlaceLink.ts` 가 주소를 만든다.
- 저장 화면(`savedPage.tsx`) — 종류별 묶음 + "지도에서 보기"(`/map/?saved=1`).

**없는 것**
- 영업시간·휴무일·전화번호(10 §1 과 같다. `verifiedAt` 은 타입에만 있고 시드 86곳엔 값이 없다). → **2단계의 "영업시간 충돌" 은 데이터가 생길 때까지 범위 밖**(🙋 3).
- 날짜·일정 개념. 저장은 평면 집합이다.
- 여러 장소를 한 번에 네이버로 넘기는 링크.

## 3. 사용자 흐름 (기능 기획까지 — 화면 자리·문구는 적지 않는다, 10 §7 과 같은 원칙)

1. 저장한 곳에서 **"일정으로 묶기"** 를 켠다. 저장한 곳마다 "1일 / 2일 / 3일 / 미정" 중 하나를 고른다(기본 미정). 숙소는 그 날의 **마지막** 자리로 고정된다.
2. 하루를 열면 **순서 제안**이 나온다 — 시작점은 (a) 현재 위치(누를 때 한 번) 또는 (b) 전날 숙소 또는 (c) 공항. 식당·카페를 가까운 순으로 늘어놓고 숙소로 끝난다. 사용자는 끌어서 바꿀 수 있다.
3. 각 장소 옆에 **우리 강아지 판정 점**이 그대로 붙고, 하루 머리에 **묶음 판정 한 줄**: "콩이·보리 둘 다 갈 수 있어요" / "보리는 ○○에 못 들어가요 — 이 날은 콩이만, 또는 ○○ 대신 △△". 대안은 같은 읍면·같은 종류에서 "가능" 인 곳.
4. **"네이버 지도로 길찾기"** 를 누르면 그 날 순서가 경유지로 실린 `nmap://route/car` 가 열린다. 6곳이 넘으면 "앞 6곳 / 다음 묶음" 으로 나눠 두 번 넘긴다.
5. 지도 시트의 장소 하나에는 **"지금 여기로"**(`nmap://navigation`, 목적지 하나) 가 따로 붙는다. 현장에서 가장 자주 누르는 동작이라 일정과 무관하게 한 번에 간다.
6. 준비물은 바뀌지 않는다 — 이미 "저장한 숙소" 에서 파생되므로 날짜 묶음을 몰라도 같은 답이 나온다. 날짜별 준비물은 **하지 않는다**(ADR-009 의 "한 화면에서 반대를 말하지 않는다" 를 지키는 가장 쉬운 길).

## 4. 결정 — 제안 P1~P6

- **P1 저장 위에 얹는다, 새 집합을 만들지 않는다.** 일정은 `savedIds` 의 부분집합에 날짜 라벨을 붙인 것이다(`dayOf: Record<id, 1|2|3|...>`). 저장을 해제하면 일정에서도 빠진다 — `savedNotes` 와 같은 생명주기. 저장하지 않은 곳을 일정에 넣는 길은 두지 않는다(두면 "저장" 의 뜻이 둘로 갈린다).
- **P2 순서는 제안이고 저장은 사용자의 것.** 자동 순서(가까운 순, 숙소 마지막)는 라벨을 바꿀 때마다 다시 계산하지만, 사용자가 끌어 바꾼 순서는 `order: id[]` 로 따로 저장하고 자동 계산이 덮지 않는다. 버튼 "순서 다시 제안" 으로만 되돌린다.
- **P3 현재 위치는 누를 때 받고 저장하지 않는다**(ADR-012 · `myLocation.ts` 의 원칙 그대로). 시작점 (a) 를 고르면 그 순간 한 번 받아 정렬에 쓰고 버린다. 일정에 좌표가 남지 않는다.
- **P4 운전 안내는 네이버 지도 앱 URL 스킴으로만.** `nmap://route/car?dlat&dlng&dname&v1lat&v1lng&v1name…&appname=` (출발지 생략 = 현재 위치), 목적지 하나는 `nmap://navigation`. Directions API 는 부르지 않는다 — 비용·서버·키가 전부 0 으로 남는다. 앱이 없으면 설치 유도(iOS App Store / Android 인텐트 폴백)와 웹 `map.naver.com/p/directions/…/car` 로 받친다.
- **P5 2단계의 범위는 "조건 판정" 까지.** 영업시간·휴무·계절 충돌은 데이터가 없어 **지금은 하지 않는다**. 데이터가 들어오면(11 의 수집 칸이 늘 때) 같은 묶음 판정 함수에 규칙 하나를 더한다 — 그래서 묶음 판정은 처음부터 `reasons[]` 를 돌려주는 모양으로 짠다.
- **P6 로직은 전부 `src/lib/` 순수 함수 + 테스트.** `tripPlan.ts`(라벨·순서·부분집합) · `tripRoute.ts`(시작점 → 순서 제안, 직선거리) · `tripEligibility.ts`(묶음 판정 + 대안) · `naverRouteLink.ts`(URL 조립, 5곳 분할, 인코딩). 화면은 그 위에 얇게.

## 5. 네이버 URL 스킴 — 적어 두는 것 (실측 전)

- `nmap://route/car` 파라미터: `slat slng sname`(출발, **선택** — 비우면 현재 위치) · `dlat dlng dname`(도착, 필수) · `v1lat v1lng v1name … v5…`(경유 최대 5) · `appname`(필수, 우리 도메인 또는 앱 이름).
- `nmap://navigation?dlat&dlng&dname&appname` — 목적지 하나로 바로 안내.
- 좌표는 WGS84 — 우리 `geo` 와 같다. 이름은 URL 인코딩.
- 폴백: iOS 는 스킴 열기 뒤 타임아웃으로 App Store, Android 는 `intent://…#Intent;scheme=nmap;package=com.nhn.android.nmap;end`. 웹은 `https://map.naver.com/p/directions/{slng},{slat},{sname}/{dlng},{dlat},{dname}/{v1:v2…}/car` 꼴 — **경유가 도착 뒤**(T1.3 메모, 처음 적은 `{s}/{v…}/{d}/-/car` 는 칸이 하나 많았다).
- ⚠️ **전부 문서·검색 기준**이다(NCP "지도 앱 연동 URL Scheme" 가이드). 출발지 생략 시 현재 위치 · 웹 경유지 형식 · 안드로이드 인텐트는 **폰에서 한 번씩 눌러 봐야 한다** — 🧑 H.1.

## 7. 🙋 사용자가 정할 것

1. **날짜 라벨의 상한** — 3일 고정 / 7일 / "N일" 자유. 권장: **1~4일 + 미정**(제주 여행 중앙값, UI 가 칩 다섯으로 끝난다).
2. **시작점 기본값** — 현재 위치 / 전날 숙소 / 공항. 권장: **1일차는 공항, 2일차부터 전날 숙소**, "내 위치에서" 는 버튼으로.
3. **영업시간 데이터를 11 의 수집 칸에 넣을 것인가** — 넣으면 P5 의 충돌 검사가 열린다. 권장: **이 트랙에서는 안 넣는다**(수집·검수 비용이 큼), 2단계는 조건 판정으로 닫는다.
4. **일정 공유** — 하루 순서를 링크 하나로 보내기(10 태호 "아내와 같이 정하기"). 권장: **이 트랙 밖**, 다음 트랙. 링크에 `savedIds` 를 싣는 방식은 ADR-012 와 무관(장소 id 만)이라 가볍다.
