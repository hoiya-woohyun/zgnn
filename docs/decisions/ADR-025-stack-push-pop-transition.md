# ADR-025 — 하위 화면은 위에 쌓인다 (덮기 · 걷기 · 가장자리 스와이프)

> 최종 수정: 2026-10-07 (v4: 「결과」 — 같은 경로의 replace 가 새긴 깊이·탭을 잇는다(`carryHistoryStamp`))
> 이전 2026-10-07 (v3: 「결과」 — 끄는 제스처는 주소가 바뀌면 끝난다, [BUG-013](../bugs/BUG-013-stack-gesture-outlives-navigation.md))
> 이전 2026-10-07 (v2: 결정 6·7 — 하위 화면은 **들어온 탭 밑**에 있다(탭 불은 history 항목마다 새긴 탭), 탭 화면끼리는 history 를 쌓지 않는다(탭 화면에서 Safari 가장자리 뒤로가기를 막는 실제 수단). 사용자 요청 "하위 페이지는 접근한 탭 밑, 최상위 다섯 곳에서의 스와이프 백은 이전 페이지를 보이거나 막거나")
> 이전 2026-10-07 (v1: 신설 — 사용자 요청 "stack 구조일 때는 다른 앱과 같이 swipe 되는 느낌으로")

## 상태

채택.

## 맥락

탭바 화면 다섯 곳은 손가락으로 **옆으로** 넘긴다([ADR-014](ADR-014-shell-owned-swipe-pager.md)). 그런데 그 안으로 들어가는
화면 — 설정 → 우리 강아지(`/dog`), 저장한 곳(`/saved`), 목록·지도 → 장소 상세(`/place/:id`) — 은 제자리에서 갈아 끼워졌다.
네이티브 앱에서 안으로 들어가는 화면은 오른쪽에서 **덮고**, 나올 때 오른쪽으로 **걷히며**, 왼쪽 가장자리를 끌어 걷어 낼 수 있다.
탭 사이가 미끄러지는데 안으로 들어가는 이동만 툭 바뀌면 "덜 만든 것" 으로 읽힌다.

## 결정

### 1. 방향은 history 깊이로 정한다 — 주소가 아니라

`lib/stackTransition.ts` 의 `stackTransitionOf` 하나가 답한다. 같은 `/place/:id` 에 처음 들어가는 것과 뒤로 돌아오는 것은
주소로 구별되지 않으므로([ADR-014](ADR-014-shell-owned-swipe-pager.md) 결정 5 와 같은 이야기) 셸이 history 항목마다 새긴
깊이(`appHistory`)의 변화를 본다 — 깊어지면 덮기(push), 얕아지면 걷기(pop).

| 이동 | 그림 |
|---|---|
| 탭 화면 → 하위 화면, 하위 → 하위(상세 → 근처 상세) | push |
| 하위 화면에서 뒤로(버튼·브라우저·가장자리 스와이프) | pop |
| 딥링크 상세의 뒤로가기(부모로 **갈아 끼움**, 깊이 그대로) | pop — 거는 쪽이 `popRequested` 로 말한다 |
| 탭 화면끼리 | 없음 — 옆 페이저(ADR-014)의 몫 |
| 하위 화면에서 탭바로 다른 탭 | 없음 — "되돌아" 가 아니라 "다른 데로" |
| `/admin` 안팎, 같은 주소(쿼리만 바뀜) | 없음 |

### 2. 옆 장은 떠나기 직전 `<main>` 의 **DOM 복제**다

옆 페이저의 이웃은 정해져 있어 진짜 화면을 그리지만, 쌓인 화면의 이웃은 방금 떠난 화면이라 무엇이든 될 수 있다. 다시 그리면
상세의 미니 지도가 한 번 더 뜨고 폼은 처음으로 돌아간다. 그래서 떠나기 직전의 `<main>` 을 `cloneNode` 로 떠서 `<main>` 밖
`fixed` 층에 띄운다(id 는 지우고 `inert`). 캔버스만 빈다 — 갓 마운트된 지도도 그 모습이라 지도 대역(ADR-014 결정 3)과 같은 이유로 받아들인다.

View Transitions API 를 쓰지 않은 이유: 가장자리 스와이프는 **손가락을 따라가야** 하는데 그것은 스크럽할 수 없다. 어차피 WAAPI 가
필요하면 두 체계를 둘 이유가 없다 — 탭 페이저와 같은 재료(`<main>` 에 WAAPI, `fill: forwards` 는 끝에서 취소, `--swipe-viewport-top`)로 만든다.

### 3. **떠 두는 시점**이 이 결정의 요점이다

주소가 바뀐 뒤(layout effect)엔 `<main>` 이 이미 새 화면이다.

- 들어갈 때: 문서에 **capture** 로 단 click 이 링크를 Next `<Link>`(React 위임) 보다 먼저 본다.
- 뒤로/앞으로: `popstate` 를 **capture** 로 듣는다. React 19 는 popstate 안에서 시작된 전환을 그 자리에서 동기로 그려
  버린다(`react-dom` 의 `shouldAttemptEagerTransition`) — Next 의 리스너 뒤면 이미 늦다.
- 셸의 뒤로가기: 거는 쪽이 직접 뜬다(갈아 끼우는 뒤로가기엔 popstate 가 없다). 그래서 **뒤로가기의 문은 하나**다 —
  헤더 화살표(`AppBar`)와 "저장하고 돌아가기"(`dogProfilePage`)가 `goBackInApp` 을 함께 쓴다. 하나라도 `router.back()` 을
  직접 부르면 그 길만 그림 없이 갈아 끼워진다.

떠 둔 것은 추측이다(그 클릭이 화면을 안 바꿀 수도 있다). 도착한 이동의 출발지와 같을 때만 쓴다.

### 4. 가장자리에서 끌면 걷어 낸다

하위 화면의 왼쪽 가장자리 띠(`canStartStackBackAt`)에서 오른쪽으로 끌면 화면이 손가락을 따라가고, 밑에는 **들어올 때 떠 둔
부모**가 30% 물러난 자리에서 돌아온다. 놓으면 탭 페이저와 같은 문턱·플릭·곡선(`settleSwipe` · `settleDurationOf`)으로 정한다.
걷었으면 주소를 바꾸되 도착할 때 다시 그리지 않는다 — 밑 장이 곧 도착한 화면이다. 1.5초 안에 화면이 안 오면 제자리(`STUCK_MS`).

- 띠: 홈 화면 앱은 0~48px, 브라우저는 24~48px — 맨 왼쪽 24px 는 Safari 의 뒤로가기 몫이다(ADR-014 의 가드와 같은 값).
  가운데서 시작한 끌기는 받지 않는다 — 상세의 가로 스크롤 줄과 싸운다.
- 부모를 떠 둔 적이 없으면(딥링크·새로고침) 밑 장은 크림 한 장이다.

### 5. 브라우저가 이미 그린 뒤로가기는 다시 그리지 않는다

iOS Safari(브라우저)는 가장자리 뒤로가기를 자기 그림으로 걷은 **뒤에** popstate 를 준다. 거기서 또 걷으면 한 장이 두 번 걷힌다.
그래서 셸이 걸지 않은 popstate 는 iOS 이면서 홈 화면 앱이 아닐 때 그리지 않고, Navigation API 가 있으면 `hasUAVisualTransition` 을 따른다.

### 6. 하위 화면은 들어온 탭 밑에 있다 — 탭 불은 가장 가까운 history 의 탭

탭 화면 다섯 곳(홈 · 둘러보기 · 지도 · 준비물 · 설정)이 맨 위(스택의 바닥)이고, 하위 화면은 **그 화면으로 들어갈 수 있는 탭 화면 밑**에
쌓인다. 밑에 있는 동안 탭바는 그 탭에 불을 켠다. 저장한 곳처럼 여러 탭에서 열리는 화면은 **가장 가까운 history 의 탭**을 따른다.

- `lib/appRoutes.ts` 의 `ownerRootOf` 가 답한다: 탭 화면이면 자기 자신 · 이 history 항목에 새긴 값 · 직전 화면의 탭 · 정해 둔 부모(`parentRouteOf`)의 탭 순.
- 셸이 깊이와 함께 항목마다 새긴다(`appHistory` 의 `zgnnRoot`). 뒤로가기로 돌아온 화면은 **처음 들어올 때 새긴 값**을 읽는다 — 직전 주소 하나로
  가르면(14 W261006.10 의 `/dog` 방식) 상세에서 뒤로 돌아온 저장한 곳의 직전 주소가 상세라 틀린다. 정적 규칙(`isActive` 에 `/saved` 를 넣던 것)은
  같은 화면이 어디서 왔느냐로 갈리는 답을 아예 못 한다.
- 탭바는 주소가 바뀐 **렌더 중에** 같은 함수로 먼저 계산한다(effect 면 한 프레임 탭이 꺼졌다 켜진다). 그때 history 는 앞으로 가는 이동이면 아직
  떠나는 항목(Next 가 commit 에서 쌓는다 — 새 하위 화면은 그 탭을 물려받으니 맞다), 뒤로/앞으로면 도착한 항목(제 값이니 맞다)이다.
- 정해 둔 부모는 들어온 길을 모를 때(딥링크)만 쓴다. `/saved` 는 설정 밑으로 되돌렸다 — 홈 아래로 옮긴 이유(12 U3.6, "주 진입점이 홈 카드")는
  탭 불이 들어온 길을 따르게 되면서 사라졌다.

### 7. 탭 화면끼리는 history 를 쌓지 않는다 — 탭 화면에서의 가장자리 뒤로가기를 막는다

탭 화면에서 iOS 가장자리 스와이프 백을 했을 때 "밑에 이전 화면을 보인다" 와 "막는다" 중 **막는다**를 골랐다.

- 탭 화면의 오른쪽 끌기는 이미 **왼쪽 이웃 탭**이다(탭 페이저, ADR-014). 거기에 "직전 history" 를 밑에 깔면 같은 화면에서 같은 방향의 손가락이
  두 뜻이 된다 — 맨 왼쪽 24px 는 직전 화면, 그 오른쪽은 이웃 탭.
- 그림을 우리가 그릴 수도 없다. Safari 의 가장자리 뒤로가기는 페이지 JS 가 취소하거나 다시 그릴 수 없고(결정 5), 홈 화면 앱에는 그 제스처가 없다.
- 그래서 막는 수단은 **history** 하나다. 탭 화면 → 다른 탭 화면은 `pushState` 대신 `replaceState`(`appHistory` 의 `keepTabsOffHistory` ·
  `appRoutes` 의 `isTabSwitch`). 앱을 탭 화면에서 열었으면 그 뒤에 되돌아갈 앱 안 화면이 없어 Safari 의 제스처가 갈 곳이 없다.
- 길(탭바·사이드바·스와이프·종류 알약·화면 안 링크)마다 `replace` 를 챙기지 않고 history 가 쌓이는 자리 하나에서 가른다 — 새 링크 하나가 잊는
  날 탭 뒤에 탭이 쌓인다. Next 는 앞으로 가는 이동을 `HistoryUpdater` 의 `pushState` 한 번으로 남기므로 그것을 감싼다. Next 도 effect 에서
  `pushState` 를 감싸고 언마운트 때 되돌리므로 **셸 모듈 최상단**에서 먼저 감싼다.

남는 것:
- 하위 화면에서 탭바로 다른 탭에 나가면 그 탭 화면 뒤에는 방금의 하위 화면이 남는다(쌓인 대로). 없애려면 `history.go(-깊이)` 로 되감은 뒤
  갈아 끼워야 하는데, 되감는 사이 바닥 화면이 한 번 그려진다 — 이번 범위 밖.
- 탭 화면에서 브라우저·안드로이드 뒤로가기는 앱을 나간다(탭 사이를 되짚지 않는다). 네이티브 탭 앱과 같다.

## 결과

- 느낌을 바꾸는 값(`STACK_SLIDE_MS` 340ms · `STACK_SLIDE_EASING` · `STACK_PARALLAX` 0.3)은 `lib/swipePager.ts` 에 탭 페이저 값과 함께 있다.
- **층은 `body` 가 아니라 셸 안**에 붙는다. 셸 바깥 상자가 `isolate`(바탕 발자국의 음수 z 를 가두는 쌓임 맥락)라, 밖에 붙이면
  z 를 몇으로 주든 탭바까지 덮는다(실측). 덮을 때는 층이 `<main>` 밑(z 20, `<main>` 은 잠시 z 25·크림 바탕·그림자),
  걷을 때는 위(z 35) — 둘 다 탭바(z 40) 아래다.
- 걷을 때 `<main>` 엔 바탕을 칠하지 않는다 — 칠하면 탭 화면의 발자국(음수 z)이 340ms 동안 가려진다.
- 모션 줄임이면 덮기·걷기 그림은 없다(이동만). 가장자리 끌기는 손이 직접 움직이는 것이라 그대로 두고, 놓은 뒤의 밀어내기만 0ms.
- 넓은 화면에서 물러나는 거리는 칸이 아니라 한 장(`<main>`) 폭 기준이다 — 칸 폭의 30% 면 읽던 글이 화면 반을 건너뛴다.
- **끄는 제스처는 이동보다 오래 살지 않는다** — `arrive` 가 비운다. 손을 뗄 때만 비우면, 끄는 중에 탭 화면으로 옮겨 간 순간 `pointerup` 을 받을 핸들러가 없어
  늘 붙은 `touchmove` 잠금이 앱 전체 세로 스크롤을 막는다([BUG-013](../bugs/BUG-013-stack-gesture-outlives-navigation.md)).
- **같은 경로의 replace 는 새긴 값을 잇는다**(`appHistory` 의 `carryHistoryStamp` — `replaceState` 감싸개). Next 는 `router.replace` 에도 state 를 `{ __NA, … }` 로 새로 써
  우리 깊이·탭을 지우는데, 경로가 그대로라 셸이 다시 새기지 않는다(지도의 `?saved=1`, 저장한 곳의 주소 정리). 지우면 그 항목에 뒤로가기로 돌아올 때 새 항목으로 읽혀 걷기가 덮기로 그려진다.
- 스냅샷은 깊이별로 하나씩 메모리에 남는다(걷으면 더 깊은 칸은 지운다). 목록 한 장의 DOM 이라 무겁지 않다.
- 결정 6·7 은 데스크톱 Chrome(dev)에서 history 길이·새긴 값·탭 불로 쟀다(설정→저장→탭 이동 셋→뒤로 둘 · 홈→저장→상세→강아지→뒤로 둘 · 새로고침). iPhone Safari 의 가장자리 제스처가 정말 갈 곳이 없어지는지는 실기에서 아직 안 봤다.
- 폰 실기(iOS 홈 화면 앱)에서 손 느낌은 아직 확인하지 않았다 — Playwright 터치 에뮬레이션(390×844)으로 덮기·걷기 프레임과
  끌기(짧게 놓으면 제자리 · 멀리 놓으면 뒤로 · 딥링크면 크림 밑장 + 부모로 갈아 끼움 · 가운데 시작은 무시)만 쟀다.
