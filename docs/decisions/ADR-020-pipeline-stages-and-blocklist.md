# ADR-020: 파이프라인을 다섯 칸으로 나누고, 반려한 가게는 차단 목록이 막는다

> 최종 수정: 2026-10-01 (v1: 초안 — [docs/todo/09](../todo/09-admin-pipeline-stages.md) 의 결정 D1~D7 을 옮겼다. 🙋 는 전부 닫혔다(A·B·C = v3).
> 이 문서는 **사용자가 한 번 읽는 자리**다 — 읽고 틀린 곳이 있으면 여기와 09 를 같이 고친다)
> 상태: **D1·D2 의 표만 파일로 있다**(`supabase/migrations/20261001120000_place_blocks.sql`, **원격 미적용** — 🧑 `supabase db push`).
> 분석이 그 표를 읽는 것(T1.2)·화면(T1.3~)·다섯 칸 탭(T3.x)은 09 의 태스크대로 뒤따른다. D3 의 `edited` 규칙은 **구현됨**(T2.2).

## 맥락

운영자(사용자)가 `/admin` 을 쓰다 짚은 것 — "수집된 것이 보이니 수집에서 빼는 버튼이 먼저 있어야 한다", "3개월 뒤 풀리는 제외와 영구 제외",
"다시 분석은 분석 데이터를 초기화", "확인할 장소·올린 장소 대신 수집 완료·분석 완료·등록 완료".
코드와 대 보니 방향은 맞고 **자리가 다르다**:

- `data:collect` 는 **글 메타데이터만** 저장한다(`blog_posts`: 제목·링크·키워드·날짜). 가게는 **분석이 본문을 읽은 뒤에야** 생긴다 — 수집 단계엔 제외할 가게가 없다.
- 분석은 **반려한 가게를 전혀 참조하지 않는다**(`analyze-candidates.mjs` 가 읽는 것은 `pending` 뿐). 반려한 가게를 쓴 새 글이 오면 **매번 다시 후보로 올라온다** — 사용자 직감이 가리킨 진짜 구멍이다.
- 재분석은 후보를 **지울 수 없다**(`candidates` 에 DELETE grant 가 없다 — 소프트 삭제 경계, [ADR-018](./ADR-018-in-app-admin-review.md) 결정 6~8). 그리고 `approved`·`merged` 는 이미 `places` 에 쓰여 사이트에 보이는 것이라
  프롬프트를 고쳤다는 이유로 사용자 화면에서 가게가 사라지면 안 된다.
- 버튼은 상태를 바꿀 뿐 **다음 단계를 돌리지 못한다** — 수집·분석은 네이버 키와 `claude -p` 구독이 있는 사용자 터미널에서만 돈다([ADR-016](./ADR-016-secrets-by-login.md)).

## 결정

**D1. 가게 제외는 분석 단계의 차단 목록이다 — `place_blocks`.** 수집은 가게를 모르니 거기 둘 수 없고, `candidates.rejected` 를 재활용하면
`[admin] 재분석` 으로 눕힌 행과 `중복` 반려까지 차단이 된다(재분석한 가게가 다시 안 올라온다). 제외는 **가게**에 대한 결정이고 후보는 그 가게의 글 하나다 — 개체가 다르니 표가 따로 있어야 한다.
키는 `name_key`(`normalizeName`, 후보의 `extracted.nameKey` 와 같은 함수) + 선택 `town`(주소의 읍·면). 이름만으로 막으면 체인·동명 가게(우도 카페살레 vs 본섬)가 같이 막힌다 —
`town` 이 있으면 둘 다 맞아야 걸리고, 후보 쪽 읍·면을 모르면 이름만으로 건다(모르는 것은 막는 쪽으로).

**D2. 만료는 스케줄러가 아니라 비교다.** `until timestamptz`(null = 영구). 분석이 실행마다 `until is null or until > now()` 인 행만 읽는다. 일찍 풀기는 `lifted_at` 을 찍는다(DELETE 없음 — 다른 표와 같은 경계).
기본 기간 **3개월**은 사용자 제안값이고 폼에서 바꿀 수 있다. 사유별 기본값은 아래 표(✅ 사용자 확정 — 폐업은 영구).

**D3. 재분석은 「수집 완료로 되돌리기」 다. 지우지 않는다.** 동작은 `adminReanalyze.ts` 그대로 두고 **말을 사실대로** 바꾼다 — 무엇이 목록에서 빠지고(검수 대기 후보), 무엇이 남는지(등록한 장소 · 사람이 고친 후보),
다음에 누가 읽는지(터미널의 `data:analyze`). 단계 모델에서는 **검수 대기 → 수집 완료** 로 한 칸 되돌리는 것이다.
**사람이 고친 후보(`[admin] 고침`)는 언제나 남긴다** — AI 판단을 사람이 다시 고쳤으면 사람 쪽이 정답이다(✅ 사용자, 체크로 고르게 하지 않는다).
그러면 글을 다시 읽을 때 AI 가 **같은 가게의 후보를 또** 만들어 사람이 고친 행 옆에 새 AI 판단이 한 벌 붙는다. 그래서 **분석은 같은 글(`post_url`)·같은 가게(`nameKey`)의 사람이 고친 pending 후보가 있으면 그 가게를 만들지 않는다**
(제외 이유 `edited` — 구현됨). 사람이 이름을 고치면 `nameKey` 가 새 이름으로 다시 계산되므로 처음 고칠 때 `extracted.editedFrom.nameKey` 에 원래 키를 남기고 둘 다 집합에 넣는다.
같은 가게라도 **다른 글**이면 만든다 — 그것은 새 근거이고 지금처럼 같은 묶음으로 붙는다.

**D4. 다섯 칸 = 네 개체.** 탭 `수집 완료 · 검수 대기 · 등록 완료 · 등록 해제 · 블랙리스트`(✅ 사용자 — 둘째 칸은 '분석 완료' 가 아니라 사람 차례를 말하는 `검수 대기`).
흐름은 `1 → 2 → 3` 에 `3 ⇄ 4`(등록 해제 · 되살리기)가 붙고, `블랙리스트` 는 흐름 밖의 **가로 목록**이다 — 2(제외)·3·4(등록 해제)에서 들어오고, 분석(`data:analyze`)이 읽는다.
단계마다 개체가 다르다: 수집 완료 = **글**(`blog_posts`) · 검수 대기 = **후보**(`candidates` pending) · 등록 완료·등록 해제 = **장소**(`places`, `status` 로 가른다) · 블랙리스트 = `place_blocks`.
탭 라벨에 **건수**를 싣는다 — "어디에 일이 있나" 가 탭 줄에서 읽혀야 한다. `draft`(게시 대기)는 3 에 칩으로 둔다.
낱말 교체(`올리기` → `등록` · `내리기` → `등록 해제` · `승인`·`반영`·`게시` 도 같은 동작)는 맨 마지막 한 커밋으로 묶는다.

**D5. 다음 단계는 터미널 명령이고 화면은 그것을 보여 준다.** 수집 칸 머리에 "미분석 N건 — 터미널에서 `pnpm data:analyze --limit 30`", 검수 칸의 재분석 결과 줄에 "수집 완료로 돌렸어요 — 터미널에서 `pnpm data:analyze`".
버튼으로 돌릴 수 있는 것처럼 그리지 않는다.

**D6. 등록 해제와 블랙리스트는 서로 독립이다**(✅ 사용자).
- **등록 해제**(`places.status='archived'`)는 장소의 **상태**다 — 사이트에서 감춘다, 되살리면 돌아온다. 그 이상의 뜻을 싣지 않는다.
- **블랙리스트**(`place_blocks`)는 가게 **이름**에 대한 결정이다 — 분석이 그 이름의 후보를 만들지 않는다(기간 또는 영구). 등록된 적 없는 가게(제외한 후보)도, 등록 해제한 가게도 같은 표에 선다.
- 그래서 등록 해제 탭의 가게가 새 글로 검수 대기에 올라오는지는 **블랙리스트에 있는지만** 본다. 없거나 만료되면 올라온다 — 그 후보는 **「등록 해제된 가게의 새 글」** 로 표시되고(재개업 신호),
  처리는 `덮어쓰기(내용만)` 또는 `되살려서 덮어쓰기`. 등록 해제할 때 폼의 「블랙리스트에」 선택(없음 / 3개월 / 영구)이 그 결정을 **같은 자리에서** 받는다.
- 3(등록 완료)은 이미 새 글로 후보가 되지 않는다(`skipAsExisting`). 블랙리스트와 무관하다.
- 대조 corpus 에서 `archived` 를 빼는 것이 **아니다** — 빼면 쌍둥이가 생긴다([CLAUDE.md](../../CLAUDE.md) 「조용히 깨지는 것들」, ADR-018 결정 7). 짝은 그대로 잡는다.
- 블랙리스트는 **이름 축 하나**로 건다(D1 의 `name_key`+`town`). `place_id` 는 **되살릴 때 풀 행을 찾는 열쇠**이고 분석의 둘째 판정 축이 아니다 — 두 축이 겹치면 어느 쪽이 막았는지 로그가 둘로 갈린다.

**D7. 등록한 장소는 「출처 글을 다시 읽히는」 것으로 다시 분석한다.** 장소 ↔ 글은 이미 `place_sources` 에 있다. 3·4 탭의 `다시 분석` = 그 장소의 출처 글을 미분석으로 되돌린다.
다음 `data:analyze` 가 그 글을 읽으면 자기 장소와 짝이 잡히는데 `skipAsExisting` 에 걸려 버려지므로, 예외 하나: **글이 그 장소의 출처면 건너뛰지 않고 「갱신 제안」 으로 올린다**. 출처가 아닌 새 글은 여전히 건너뛴다.
갱신 제안은 검수 대기에서 `덮어쓰기` 로 반영한다 — **덮어쓰기 전까지 사이트의 장소는 그대로**이고, 사람이 고친 칸은 덮어쓰기 화면의 비교에서 고른다.
출처 글이 없는 장소는 `다시 분석` 을 **끄고** `다시 읽을 글이 없어요` 라고 적는다(✅ 사용자). 등록 해제 탭에서 덮어써도 **내용만** 바뀌고 상태는 `archived` 그대로다(✅ 사용자) —
`archived` 행의 update 는 재빌드 트리거가 안 부르므로(`published` 가 끼는 변경만) 비용도 없다. **`덮어쓰기` 는 `place_sources` 도 upsert 한다** — 안 쓰면 갱신에 쓴 글이 다음 `다시 분석` 의 출처가 아니다.

### 사유별 블랙리스트 기본값(폼에서 바꿀 수 있다)

| 반려 사유 | 기본 | 왜 |
|---|---|---|
| 동반 불가 | **3개월** | 정책이 바뀔 수 있다 |
| 폐업 | **영구** | 재개업은 드물고 폐업 글은 계속 들어온다. 재개업을 알게 되면 블랙리스트에서 손으로 푼다 |
| 제주 아님 | **영구** | 바뀌지 않는 사실 |
| 홍보·협찬 · 목록글 | 없음 | **글**의 문제라 가게 탓이 아니다 |
| 중복 | 없음 | 막으면 "같은 가게" 신호(`ask` 짝)를 덮는다 |
| 정보 부족 | 없음 | 더 좋은 글이 오면 다시 봐야 한다 |

| 등록 해제 사유 | 기본 | 왜 |
|---|---|---|
| 폐업 | **영구** | 반려와 같다 |
| 동반 불가로 바뀜 | **3개월** | 다시 바뀔 수 있다 |
| 업장 요청 | **영구** | 업장이 빼 달라고 했다 — 새 글로 되살아나면 안 된다 |
| 중복 | **없음** | 블랙리스트는 이름 축이라 살아 있는 쌍둥이의 새 글까지 막는다. 쌍둥이는 `skipAsExisting` 이 걸러 준다 |
| 정보가 틀림 | 없음 | 더 맞는 글이 오면 그것이 고칠 기회다 |
| 기타 | 없음 | 모르는 사유가 수집 결정을 대신 내리면 안 된다 — 운영자가 고른다 |

## 고려했다 버린 것

- **`candidates.rejected` 를 차단으로 재활용** — 재분석으로 눕힌 행·`중복` 반려까지 차단이 된다(D1).
- **수집 단계에서 가게 제외** — 수집은 가게를 모른다(글 메타데이터만). 블로그 단위 차단은 별개의 일이다(09 P2).
- **재분석 = 행 삭제** — DELETE grant 가 없고, 이미 `places` 에 쓰인 것을 지우려면 장소를 내려야 해 사이트에서 가게가 사라진다(D3).
- **「함께 되돌리기」 체크(고친 후보까지 눕히기)** — 사람이 고친 것이 정답이다(D3).
- **`skipAsExisting(matched, { blockedPlaceIds })` 의 `place_id` 축** — 이름 축과 겹쳐 로그가 둘로 갈린다(D6).
- **cron·Actions 로 만료 처리** — 스케줄러가 없다(ADR-016 v5). 비교로 충분하다(D2).

## 결과

- 반려한 가게를 쓴 새 글이 와도 기간(또는 영구) 동안은 후보로 올라오지 않는다 — 분석 로그에 제외 이유 `blocked` 로 남는다(T1.2).
- 사람이 고친 후보는 재분석해도 옆에 AI 판단이 또 붙지 않는다(`edited`).
- 운영자가 "다음에 무엇을 해야 하나" 를 탭 줄(건수)과 칸 머리(터미널 명령)에서 읽는다.
- **원격에 `place_blocks` 가 없는 동안**(🧑 `supabase db push` 전) 분석은 조회 실패를 "차단 0건 + 경고 한 줄" 로 다루고 멈추지 않는다. 화면은 블랙리스트 탭에 `미적용` 을 단다.

## 열린 것

없다 — A~C 가 닫혔다. 첫 실측(반려한 가게 하나를 3개월 제외하고 `pnpm data:analyze --dry-run --limit 5` 로그에 `차단 1`)은 🧑 H.3.
