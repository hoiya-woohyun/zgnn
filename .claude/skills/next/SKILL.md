# /next — 대기열 이어 가기

사용자는 다음 할 일을 매번 고르지 않는다. **판단은 내가 하고, 사람이 꼭 필요한 일만 「기다림」 에 모은다.**
대기열은 `docs/todo/NOW.md` 하나다. 번호 붙은 todo 문서(00~15)는 **명세**이고, NOW.md 는 그중 지금 할 것의 **순서**다.

## NOW.md 의 세 칸

```md
## 지금 (위에서부터)
- [ ] <한 줄 제목> — [14 W261006.1](14-weekly-ux-eval.md) · 왜 지금: <한 마디>

## 기다림 (사람 손·결정)
- 🙋 <정할 것> — [링크] · 권고: <내 권고 한 줄>
- 🧑 <사람이 해야 하는 일> — [링크] · 명령: `<사용자가 칠 것>`

## 발견 (분류 전)
- <작업 중 찾은 것 한 줄> — 출처: <커밋/파일>
```

- 「지금」 은 **5~10개**. 에이전트가 레포 안에서 끝낼 수 있는 일만(사용자 로그인·원격 DB 쓰기·큰 구독 한도·법적 판단이 필요하면 「기다림」).
- 순서 기준: 판정이 틀리는 것(핵심 가치) > 데이터가 틀리는 것 > 막힌 흐름 > 다듬기. 같은 급이면 작은 것 먼저.

## 실행 순서

1. **읽기** — `docs/todo/NOW.md` 만 읽는다. 「지금」 이 비었거나 파일이 없으면 → 4 의 정리부터 한다.
2. **한 일 하기** — 맨 위 항목의 링크(명세)를 열어 그 태스크 절만 읽는다.
   - 시작할 때 한 줄: `▶ <제목> (<링크>)`.
   - 명세가 낡았으면(코드가 이미 그렇다·전제가 바뀌었다) 고치지 말고 명세에 `> 메모:` 로 사실을 적고 닫거나 다시 쓴다.
   - 구현은 CLAUDE.md 의 위임 규칙대로(여러 파일 → executor, 판단이 큰 설계 → opus). 프론트 편집 순서·owner-prefix·문서 갱신 정책을 지킨다.
   - 검증: 관련 테스트 + `pnpm tsc --noEmit -p .`, 화면이 바뀌면 Playwright 로 한 번(개인 레포라 Chrome 도 된다).
   - **커밋** — 경로를 지정해 `git add`(다른 세션의 변경을 섞지 않는다). 명세의 `[ ]` → `[x]` + `> 메모:` 한 줄을 같은 커밋에.
   - NOW.md 에서 그 줄을 지운다(완료 기록은 명세와 git 에 있다 — NOW 에 쌓지 않는다).
3. **발견 적기** — 하다가 찾은 버그·개선점은 고치지 말고(범위가 번진다) 「발견」 에 한 줄. 단 지금 일을 끝내려면 꼭 필요한 한 줄 수정은 그 커밋에.
4. **다음으로 / 멈추기** — 아래 중 하나면 멈추고, 아니면 2 로.
   - 이 세션에서 3개를 끝냈다 · `[컨텍스트 NNNk]` 알림을 받았다 · 다음 일이 사람을 기다린다.
   - 멈추기 전에 **정리**: 「발견」 을 명세 문서(맞는 번호 문서, 없으면 14 처럼 가장 가까운 곳)에 `[ ]` 태스크로 옮기고, 지금 할 만하면 「지금」 에 순서대로 끼운다. 사람이 필요하면 「기다림」. NOW.md 를 커밋한다.
5. **보고** — 짧게: 끝낸 것(커밋 해시) · 「기다림」 에 새로 생긴 것(사용자가 할 일, 명령 포함) · 다음 맨 위 항목. 끝 줄은 `→ /clear 후 /next` .

## 하지 않는 것

- 「지금」 이 남았는데 "다음에 뭘 할까요?" 라고 묻지 않는다. 권고가 있으면 「기다림」 에 권고와 함께 적고 다음 일로 간다.
- 원격 DB 쓰기·`supabase db push`·`pnpm data:*` 의 큰 실행(수십 번의 `claude -p`)·push 는 하지 않는다 → 「기다림」 에 명령과 함께.
- NOW.md 를 다시 140줄로 키우지 않는다. 명세는 번호 문서에.
