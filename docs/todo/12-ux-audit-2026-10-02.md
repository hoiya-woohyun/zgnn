## P0 — 앱이 죽거나 데이터가 틀린 것

### [x] U0.1 localStorage 가 막힌 브라우저에서 앱 전체가 에러 화면이 된다

- 근거: **재현함** — Playwright 에서 `localStorage` 접근이 `SecurityError` 를 던지게 하면 첫 화면이
  `Cannot read properties of undefined (reading 'rehydrate')`. 쿠키·사이트 데이터 차단 브라우저가 이 경우다.
  zustand 는 저장소를 못 열면 `persist` API 를 **붙이지 않고** 돌아간다 — `storeHydration.tsx` 주석("이 경로만 남는다")과 반대.
- 읽을 것: `src/providers/storeHydration.tsx`(28행) · `src/store/useAppStore.ts`(`markHydrationSettled` 67행, `merge` 132~148행) · `src/app/`(`error.tsx`·`global-error.tsx` 없음)
- 단계:
  1. `useAppStore.persist?.rehydrate` 가 없으면 `markHydrationSettled()` 만 부른다. 주석을 실제 동작에 맞춘다.
  2. `src/app/global-error.tsx` 최소판 — "문제가 생겼어요 · 새로고침" (사진·외부 리소스 없이).
  3. `merge` 가 `season`·`checkedItemIds` 도 모양을 검사하게(깨진 값이면 기본값) — 지금은 `...persisted` 로 그대로 펼친다(`savedNotes` 만 `sanitizeSavedNotes` 로 거른다). localStorage 접근은 10 의 `placeReportSend.ts` 처럼 try/catch.
- 테스트: `useAppStore.test.ts` 에 `checkedItemIds: "x"` 같은 깨진 값 → 빈 배열.
- 확인: 위 재현 스크립트로 홈이 그려지고(저장 0) 콘솔 에러가 없다.
- 커밋: `fix - 저장소를 못 여는 브라우저에서도 앱이 뜨게 한다`

> 메모: 재현 스크립트(Playwright, `window.localStorage` getter 가 `SecurityError`)로 홈이 그려지고 콘솔 에러 0. 저장 없이 도는 동안 zustand 가 `set` 마다 **경고**(`storage is currently unavailable`)를 찍는다 — 에러가 아니라 두었다. 문서는 「문서」 줄이 없지만 [BUG-002](../bugs/BUG-002-hydration-deadlock.md) v1 의 설명이 틀려 v2 로 고쳤다.

### [x] U0.2 읍면과 주소가 다른 장소를 빌드 전에 잡는다

  사용자는 '남원읍' 으로 골랐는데 지도 핀이 섬 반대편에 찍힌다.
- 읽을 것: `scripts/normalize.mjs` · `scripts/pull-db.mjs` · [data-pipeline.md](../architecture/data-pipeline.md) · `src/lib/addressMatch.ts`

> 메모: 방향은 **표로 정하지 않았다** — 안덕면이 south 1 · west 1 이라 다수결도 없고, 어느 쪽인지는 도메인 판단이다. 대신 "같은 읍면이 두 방향" 자체를 경고한다. 지금 스냅샷에서 경고 4줄(세 곳 + 안덕면). 시드의 `서귀포`·`서귀포시` 표기는 같은 곳으로 본다.
