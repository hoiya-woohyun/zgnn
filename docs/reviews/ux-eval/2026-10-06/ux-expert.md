- 평가자 페르소나: UX 전문가 (Nielsen 10 휴리스틱 + WCAG 2.1 AA 계측)

## 1. 첫인상

핑크·크림 두 색으로 통일된 톤, 44px 이상으로 맞춘 터치 영역, 포커스 링과 포커스 트랩이 전부 살아 있는 등 접근성 기본기는 이 규모의 사이드 프로젝트에서 보기 드물 만큼 탄탄하다. 그런데 이 앱의 핵심 가치인 "내 강아지 기준 판정" 에서 20kg 강아지에게 "1~5kg 1만원 / 6~10kg 1.5만원" 만 적힌 숙소를 **갈 수 있어요** 로 내보내는 등, 신뢰를 깨는 데이터 판정 오류가 표본 26장 중 3장에서 나왔다. 지도 마커 81개가 접근성 트리에 전혀 없고(role·label·tabindex 없음) 28px 크기로 156쌍이 겹치는 것도 "지도" 탭이 1/5 를 차지하는 앱에서 가볍지 않다.

## 3. 가장 좋았던 점 3가지

1. **접근성 기본기가 실측으로 증명된다.** 86장 카드의 하트 전부 44×44, `aria-label="OO 저장"`+`aria-pressed`, 포커스 링 2px 전 요소, 시트 포커스 트랩·복귀, 200% 확대에도 가로 누수 0, reduced-motion 완전 존중. 체크리스트 수준이 아니라 동작 수준에서 통과한다.
2. **판정 근거를 한 문장으로 붙인다.** "두부(20kg)는 5kg 이하 조건을 넘어요", "케이지 동반시에만 가능해요" 처럼 판정 칩 옆에 이유가 따라오고, 상세에서는 원문 문장에서 근거 구절을 하이라이트한다(ux-expert-26). H1(상태 가시성)·H2 를 동시에 만족하는 보기 드문 패턴.
3. **파괴적 동작의 되돌리기와 빈 상태 설계.** 저장 비우기는 확인 모달 대신 즉시 실행 + "되돌리기" 토스트, 빈 검색·빈 저장함·위치 권한 거부·클립보드 실패에 모두 다음 행동이 있는 문구가 있다.

## 5. 총평

**"접근성과 마이크로카피는 상위권, 정작 판정 엔진의 신뢰성이 앱의 약속을 못 따라간다."**

- 점수: **6.5 / 10**
- 다시 쓸 의향: **조건부** — H-1·M-2·M-3·M-4 (판정과 원문의 모순)가 정리되면 예. 지금은 "갈 수 있어요" 를 보고도 원문을 다시 읽게 되므로 판정 기능의 존재 이유가 약해진다.

## 6. 평가 한계(못 본 것)

- **실기기 미사용.** iOS Safari 의 실제 safe-area, 홈 인디케이터, 스와이프 뒤로가기, 햅틱, 실제 VoiceOver 읽기 순서는 확인하지 않았다. 스크린리더 판단은 DOM 속성(role·aria-*·label)으로만 했다.
- **Next.js 개발 모드 배지("N" 원형)** 가 모든 스크린샷의 왼쪽 아래 "홈" 탭을 가린다. 개발 서버 산출물로 보고 평가에서 제외했으며, 홈 탭의 시각 상태는 계측값(`aria-current=page`, 라벨 12px)으로만 확인했다.
- **공유 기능**은 헤드리스 환경에서 클립보드 권한이 없어 폴백 문구만 확인했다. Web Share 시트는 못 봤다.
- **제보 전송**(보내기)은 실제 서버로 가는 요청이라 미선택 상태의 검증 오류까지만 확인하고 정상 전송은 하지 않았다. "그대로였어요" 는 한 번 눌러 토스트("고마워요! 다녀온 이야기가 확인 날짜에 보태져요")를 확인했다.
- **지도 벤더 크롬**(NAVER 로고 45×10, 10km 10px, © 11px)은 외부 SDK 산출물이라 발견 목록에서 제외했다.
- **다견(2마리) 등록 후 판정**, **이동 수단을 케이지·유모차로 바꿨을 때 판정 변화**, **오프라인(PWA) 동작**, **가로 모드**, **데스크톱 레이아웃**(DOM 에 `aside` 사이드바가 있었다)은 범위 밖으로 두었다.
- 대비 계측기는 `background-image`·그라데이션 위 글자(히어로)를 판정하지 못해 그 영역은 스크린샷 육안 확인으로 대체했다.
