# 18. 홈 구성 바꾸기 — 종류별 디렉터리에서 "내 여행" 중심으로

> 최종 수정: 2026-10-07 (v1: 신설. 사용자 "구성 자체를 변경한다면" 에 답한 계획. 장기 목표(저장한 곳 → 하루 동선, [16](16-trip-route-planner.md))을
> 받칠 수 있는 구성으로 축을 옮긴다 — **종류(숙소·식당·카페)가 아니라 사용자 상태(등록 전 · 등록 · 등록+저장)** 가 홈을 가른다.
> 결정 H1~H4 는 **제안**, 🙋 둘. 한 태스크 = 한 커밋, [08](08-usability-and-process-plan.md) 규약)

## 0. 한 줄 요약

**홈은 "내 강아지 기준 어디 갈 수 있나" 와 "내 여행이 어디까지 됐나" 두 질문에 답하고, 종류별 디렉터리는 그 아래로 내려간다.**
등록 전엔 히어로가 곧 등록 CTA 이고, 등록 뒤엔 저장·준비물·(앞으로) 동선이 **카드 하나**로 첫 블록이 된다.

## 1. 왜 바꾸나

지금 홈(2026-10-07 `develop`)은 위에서부터 히어로 → 등록 CTA(등록 전) → 인사 카드(첫 방문) → 종류 3카드(읍면 칩 포함) → 지도 버튼 → 준비물(계절 칩) → 저장 → 출처다.

- **본체가 종류 3카드다.** 이 앱만 할 수 있는 답("두부가 갈 수 있는 곳 N") 은 히어로 한 줄뿐이다(r3-pm "등록 뒤 첫 결과가 '확인 필요 31'", 디자인 리뷰 §10 ①).
- **저장·준비물이 따로 선다.** ADR-009 가 "준비물은 저장한 숙소에서" 라 했고 16 이 "동선도 같은 원천" 이라 했는데, 화면은 셋을 다른 섹션에 둔다. 동선이 오면 넷째 섹션이 된다.
- **읍면 칩이 필터를 새게 한다.** `town` 은 **퍼시스트**라 홈에서 "구좌읍 숙소 보기" 를 누르면 카페 탭에도, 다음 방문에도 9곳으로 남는다(ux-expert M-5). 07 U3 로 올린 검색어·조건은 비퍼시스트라 다음 방문엔 풀리는데 `town` 만 다르다(14 종합 §5 "조건마다 보관 위치가 다르다").
- **모수가 없다.** 종류 카드의 "가능 7 · 확인 필요 3" 은 26곳 중인지 드러나지 않는다(L-10, 08 T2.2 재점검).

## 2. 제안 구성 — 상태에 따라 홈이 달라진다

A·B·C 는 리뷰들이 쓰던 이름이다(A 등록 전 · B 등록, 저장 0 · C 등록 + 저장).

| 블록 | A | B | C |
|---|---|---|---|
| ① 히어로 | 등록 CTA 가 **히어로 안**("7kg 아이는 18곳, 25kg 아이는 6곳 — 우리 아이는요?") | "두부가 갈 수 있는 곳 **84곳 중 15곳**" | 같음 |
| ② 내 여행 | 없음 | 한 줄 "마음에 드는 곳의 하트를 눌러 모아 두세요" | **카드 하나**: 저장 3곳 · 준비물 1/10(숙소에 2) · (16 뒤) 1일차 3곳 · 2일차 2곳 → `/saved` |
| ③ 어디로 갈까요 | 종류 3카드(총수) | 종류 3카드 "가능 7 · 확인 필요 3 **/ 26곳**" | 같음 |
| ④ 지역으로 찾기 | 관광지 칩 한 줄 — 중문 · 애월 · 성산 … | 같음 | 같음 |
| ⑤ 바닥 | 인사 카드(첫 방문) · 출처 | 인사 한 줄 · 설치 안내(07 U9) · 출처 | 같음 |

### 결정 — 제안 H1~H4

- **H1 「내 여행」 카드는 `/saved` 로 가는 허브다.** 저장 수·준비물 진행률을 담고, 16 T1.4 가 오면 날짜 줄이 같은 카드에 더해진다. 홈에서 계절 칩은 뺀다(준비물 화면에 있다 — 🙋 1).
- **H2 읍면 칩을 관광지 칩으로 바꾼다.** 관광지는 ADR-022 대로 **검색어**(`usePlacesPageFilterStore`, 비퍼시스트, 검색칸에 글자로 보인다)라 다음 방문에 남지 않고, 종류를 넘겨도 "카페에는 '중문' 이 없어요" 빈 상태가 왜 0 인지 말한다. `town` 퍼시스트 자체는 두되(둘러보기 안 필터), 홈이 그것을 거는 길을 없앤다.
- **H3 등록 전엔 히어로가 CTA 다.** 잉크 판 밑에 핑크 면이 또 붙는 지금 모양은 첫 화면에 큰 덩어리가 둘이다. 히어로는 스크롤 구동 모프(ADR-014)라, 접히면 CTA 도 함께 사라지고 크림 헤더 한 줄만 남는다. 강제 라우팅은 여전히 하지 않는다(2026-09-15 리뷰 §1).
- **H4 홈에 지도를 띄우지 않는다.** 지도 비용은 "지도를 띄운 방문 수"(ADR-008). 동선 경로선·소요 시간을 우리 지도에 그리는 것은 16 §8 대로 하지 않고, 하게 되더라도 `/saved` 하루 보기에만.

## 3. 태스크

실행 규약은 [08](08-usability-and-process-plan.md) 과 같다 — 「읽을 것」 만 읽고, 「단계」 대로, 검증 전부 통과 뒤 커밋 하나.

### [x] T1 종류 카드에 모수 — "가능 7 · 확인 필요 3 / 26곳"

> 메모(2026-10-07): 끝. 20kg·이동 수단 없음 실측 숙소 "가능 6 · 확인 필요 2 / 26곳" = 목록 머리 "26곳 · 가능 6 · 확인 필요 2". 390px 에서 숫자 줄은 한 줄 그대로, blurb 는 전부터 두 줄로 접힌다(🙋 2 를 받치는 관찰).

- 근거: ux-expert L-10 · 14 ↪ 08 T2.2 재점검. 20kg 아이에게 숙소 26곳 중 7곳만 가능하다는 사실이 홈에서 안 드러난다.
- 읽을 것: `src/screens/homeTypeCard.tsx`(`levelCounts` 분기) · `src/lib/eligibilityCounts.ts`
- 단계:
  1. 프로필이 있을 때 숫자 줄 끝에 `/ 26곳` 을 작은 글자(`text-sm text-tertiary`)로. 전체 수는 `countByType[type]` 그대로.
  2. `aria-label` 도 "26곳 중 가능 7 · 확인 필요 3" 으로 — 보이는 말과 읽히는 말을 같게(08 T2.2 와 같은 원칙).
  3. blurb 줄은 그대로 둔다(🙋 2 가 정하기 전까지).
- 확인: 390px, 20kg 프로필로 홈 → 숙소 카드 "가능 7 · 확인 필요 3 / 26곳". 목록 머리의 수와 같다.
- 커밋: `feat(home) - 종류 카드에 모수 — 가능·확인 필요 옆에 전체 수 (18 T1)`

### [ ] T2 읍면 칩 → 관광지 칩 한 줄 (H2)

- 근거: ux-expert M-5(홈 읍면 칩이 퍼시스트 `town` 을 걸어 종류 탭·다음 방문까지 남는다) · ADR-022.
- 읽을 것: `src/screens/homeTypeCard.tsx`(`towns`·`goToTown` 블록) · `src/lib/landmarks.ts`(`LANDMARKS_BY_AREA`) · `src/screens/placesPage.tsx` 의 검색칸이 쓰는 `usePlacesPageFilterStore`(07 U3 메모) · `src/screens/placesPageActiveChips.tsx`
- 단계:
  1. `homeTypeCard.tsx` 에서 읍면 칩 블록과 `setTown`·`goToTown` 을 지운다(사용처 먼저, 그다음 import — CLAUDE.md 편집 순서).
  2. 새 파일 `src/screens/homePageLandmarkChips.tsx`(`HomePageLandmarkChips`) — 「어디로 갈까요」 섹션 **아래** 새 섹션 "지역으로 찾기". 칩은 `LANDMARKS_BY_AREA` 의 **권역 순서**로 관광지 이름(`name`)을 44px 칩으로. 누르면 필터 스토어의 검색어를 그 이름으로 **바꾸고**(덧붙이지 않는다) `/places/stay` 로 간다(숙소가 첫 종류 — 그 종류에 0 이면 빈 상태가 "식당에 N곳 있어요" 로 안내한다, 07 U3).
  3. 칩이 많으면(현재 21개) 한 줄 가로 스크롤이 아니라 **줄바꿈**으로 전부 보인다 — 가로 스크롤은 둘러보기 스와이프(ADR-013)와 손가락이 겹친다.
  4. 종류 카드는 아이콘·이름·blurb·수 한 줄로 남는다.
- 테스트: 없음(순수 함수 없음). 관광지 → 반경 매칭은 ADR-022 의 테스트가 이미 있다.
- 확인: 홈 "중문" → `/places/stay` 검색칸에 "중문", 결과가 중문 반경 숙소. 카페 탭으로 넘기면 검색어가 따라오고(07 U3), 새로고침하면 풀린다. `localStorage` 에 `town` 이 바뀌지 않았다.
- 문서: `docs/features/home-header.md`(있으면) 또는 `docs/architecture/app-shell-and-state.md` 의 홈 줄에 "홈은 `town` 을 걸지 않는다" 한 줄.
- 커밋: `feat(home) - 읍면 칩을 관광지 칩 한 줄로 — 홈이 퍼시스트 필터를 걸지 않는다 (18 T2)`

### [ ] T3 「내 여행」 카드 — 저장 + 준비물을 하나로 (H1) · 선행: T2 · 🙋 1

- 근거: §1 둘째. 16 P1 "일정은 저장 위에 얹는다" — 홈의 입구도 하나여야 한다.
- 읽을 것: `src/screens/homePage.tsx` 의 「여행 준비물」·저장 두 섹션 · `src/lib/checklist.ts`(`checklistView`) · `src/components/cardSurface.ts` · `src/screens/savedPage.tsx`(머리 부분만)
- 단계:
  1. 새 파일 `src/screens/homePageTripCard.tsx`(`HomePageTripCard`). 흰 면(`CARD_SURFACE`) 하나에 **두 줄**: "저장한 곳 3" (→ `/saved`) · "준비물 1/10 챙김 · 숙소 2" (→ `/checklist`). 오른쪽 `지도` 버튼은 저장 > 0 일 때만, 지금처럼 카드 링크 **바깥 형제**로(a 안에 a 금지).
  2. 저장 0 이면 카드가 아니라 크림 위 한 줄 "마음에 드는 곳의 하트를 눌러 모아 두세요" (`EmptyState` 가 아니라 본문 한 줄 — ADR-003 v15 "빈 상태는 면 없이").
  3. 홈 순서를 히어로 → (A: CTA) → **내 여행** → 어디로 갈까요 → 지역으로 찾기 → 바닥으로. 지도 버튼("지도로 보기")은 「어디로 갈까요」 밑에 그대로.
  4. 계절 칩은 홈에서 뺀다(🙋 1 이 '둔다' 면 내 여행 카드 준비물 줄 아래 한 줄로).
  5. 16 T1.4 가 오면 셋째 줄("1일차 3곳 · 2일차 2곳")이 들어갈 자리를 주석으로만 남긴다 — 지금 그리지 않는다.
- 테스트: 없음(숫자는 `checklistView`·`useSavedPlaces` 그대로).
- 확인: 390px, 저장 3·체크 1 → 카드 두 줄 수가 `/saved`·`/checklist` 머리와 같다. 저장 0 → 한 줄. 첫 프레임 "저장 0" 은 의도(`skipHydration`).
- 문서: `docs/architecture/app-shell-and-state.md` 홈 줄 · ADR-009 에 "홈 입구는 내 여행 카드" 한 줄(v 올림).
- 커밋: `feat(home) - 저장·준비물을 「내 여행」 카드 하나로 — 동선(16)이 들어올 자리 (18 T3)`

### [ ] T4 등록 전 히어로에 CTA 흡수 (H3) · 선행: T3

- 근거: §1 첫째 · 디자인 리뷰 §10 ①(히어로 위에 템플릿이 얹혀 있다) · r4 A-01.
- 읽을 것: `src/screens/homePageHero.tsx` 전체(모프 구조 — `reach` 슬롯과 접힘 커튼) · `src/screens/homePage.tsx` 의 `!dog` 블록 · [ADR-014](../decisions/ADR-014-shell-owned-swipe-pager.md) · `src/lib/homePageRegisterPreview.ts`
- 단계:
  1. `HomePageHero` 에 `cta?: { title; body; href }` 슬롯을 더한다. `reach` 와 같은 자리(둘 중 하나만 그린다 — 프로필이 있으면 `reach`, 없으면 `cta`).
  2. CTA 는 히어로 판 안의 **브랜드 면 버튼**(`bg-brand-solid` 발바닥 + 흰 글자 두 줄). 접힘 커튼이 내려오면 `reach` 처럼 같이 사라진다 — 접힌 헤더엔 제목만.
  3. `homePage.tsx` 의 `!dog` 핑크 면 블록을 지운다(사용처 먼저).
  4. 미리보기 문구(`homePageRegisterPreviewText`)는 그대로 CTA 본문.
- 확인: 390px 프로필 없음 → 첫 화면에 잉크 판 하나, 그 안에 CTA. 스크롤 → 크림 헤더 한 줄(CTA 없음). 프로필 있음 → 지금과 같다(`reach`). 768px 에서 반 픽셀 선(NOW v5 — 재현 안 됨)이 다시 나는지 한 번 본다.
- 문서: ADR-014 에 히어로 슬롯 둘(`reach`·`cta`) 한 줄.
- 커밋: `feat(home) - 등록 전엔 히어로가 곧 등록 CTA — 첫 화면에 큰 덩어리를 하나로 (18 T4)`

## 4. 🙋 사용자가 정할 것

1. **계절 칩을 홈에서 빼도 되는지.** 권고: **뺀다**. 준비물 수가 계절에 따라 바뀌는 것을 홈에서 비교하려고 넣었는데, 평가 기록(14 · ux-expert)에 홈에서 계절을 고른 페르소나가 없다. 준비물 화면 머리에 같은 칩이 있다.
2. **종류 카드의 blurb 를 유지할지.** 권고: **뺀다**. 모수까지 들어가면 카드가 세 줄이다. "숙소 · 가능 7 / 26" 한 줄로 납작하게. T1 은 blurb 를 두고 가고, 답이 '뺀다' 면 T3 에서 함께.

## 5. 하지 않는 것

- 홈에 지도(미니 지도 포함) — ADR-008 비용(H4).
- 등록 강제 라우팅 — 2026-09-15 리뷰 §1 이탈 원인.
