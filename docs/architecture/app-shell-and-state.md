## 개요

Next.js 16 App Router 를 **정적 내보내기**로 쓴다. 서버는 빌드 때만 돌고, 배포물은 `out/` 의 HTML·JS·JSON 이다.
그래서 서버 컴포넌트가 하는 일은 주소·메타 태그·정적 파라미터 생성뿐이고 화면 동작은 전부 브라우저에서 돈다.

## 라우트와 화면의 분리

```
src/app/place/[id]/page.tsx   ─ 서버: generateStaticParams(86개) · generateMetadata · dynamicParams=false
        └── <PlaceDetailPage place={…}/>   ─ 클라이언트: src/screens/placeDetailPage.tsx
```

- `src/app/**/page.tsx` 는 얇다. 데이터 JSON 에서 대상을 찾아 `screens/` 컴포넌트에 넘긴다.
- `src/screens/` 라는 이름은 Next 가 `src/pages/` 를 Pages Router 로 오인하기 때문이다.
- `/places/[type]` 은 종류 3개, `/place/[id]` 는 장소 86개를 빌드 때 전부 만들고, 그 밖의 주소는 404(`dynamicParams = false`).
  없는 id 에 빈 화면 대신 404 를 내기 위해서다.
- 종류가 빠진 `/places` 는 `src/app/places/page.tsx`(→ `placesIndexPage`)가 받아 브라우저에서 `/places/stay` 로 `replace` 한다.
  정적 내보내기라 서버 리다이렉트가 없고, `vercel.json` 에 리다이렉트를 넣는 길은 택하지 않았다(배포 설정을 건드리면 BUG-005 처럼
  빌드는 초록인데 배포만 깨진다). 스크립트가 늦어도 갈 곳이 보이게 "둘러보기로 가기" 링크를 정적 HTML 에 먼저 그린다.
  둘러보기 탭의 불은 `/places/` 부터 켠다 — `/places` 접두어로만 보면 `/placesX` 같은 404 에서도 켜졌다.
- `/admin`(운영자 검수 화면)도 같은 장치를 쓴다 — `src/app/admin/adminRouteClient.tsx` 가 `dynamic(..., { ssr: false })` 로 감싼다.
  이유는 SDK 가 아니라 **세션**이다: 로그인 상태가 localStorage 에만 있어 서버가 그릴 화면이 로그인 폼과 목록 중 어느 쪽인지 알 수 없다.
  이 화면은 탭바(`navItems.ts`)·스와이프 수열(`SWIPE_ROUTES`)·루트 목록(`ROOT_ROUTES`) 어디에도 없다 — 즉 **아무것도 등록하지 않는 것이 설정**이고,
  셸의 기본값(모르는 경로 = 하위 화면)이 뒤로가기를 붙여 준다. 프리캐시 목록에도 없어 오프라인에서는 404 다(→ [ADR-018](../decisions/ADR-018-in-app-admin-review.md)).
  운영 현황 `/admin/ops`(`adminOpsRouteClient.tsx` → `screens/adminOpsPage.tsx`)도 같은 모양이다 — 세션은 `/admin` 의 것을 그대로 읽고,
  `surfaceKindOf` 가 `/admin` 접두어로 보므로 `wide`·bare 도 따로 적을 것이 없다(→ [features/ops-dashboard.md](../features/ops-dashboard.md)).
- `/map` 은 네이버 지도 SDK 를 `document.head` 에 스크립트로 붙여 받는다 — 서버에는 그 DOM 이 없어
  `src/app/map/mapRouteClient.tsx` 가 `dynamic(..., { ssr: false })` 로 감싼다.
- `/map` 이 주소에서 읽는 것은 둘이다 — `?saved=1`(저장 칩)과 `?place=<id>`(상세의 미니 지도에서 넘어옴: 그 장소를 고르고
  그 자리에서 연다). 저장 칩을 누르면 `replace` 가 `?place=` 를 떨어뜨리지만 선택과 시야는 그대로 둔다 — 보던 것을 되돌릴 이유가 아니다.
  상세의 미니 지도는 `/map` 과 달리 `ssr:false` 없이 붙는다 — SDK 를 effect 안에서만 부르고, 그전엔 빈 판이라 서버가 그려도 어긋나지 않는다.
  화면 본체(`mapPage`)는 무엇을 보여줄지만 정하고, 지도와 마커는 `mapPageCanvas` 가 SDK 를 명령형으로 다룬다
  (→ [ADR-008](../decisions/ADR-008-map-provider.md)).

## 화면 셸 (`src/components/layout/`)

| 폭 | 구성 |
|---|---|
| < 768px | 하단 `AppTabBar`(높이는 `globals.css` 의 `--tab-bar-h` 58px 하나 — 늘린 6px 는 위에만 — 지도 상자·스와이프 대역·본문 여백·토스트가 같은 변수를 본다. 홈·둘러보기·**지도**·준비물·설정 — 가운데 지도는 라벨 없는 솟은 원형 버튼 — 바의 `border-t` 가 원 가장자리를 타고 넘는다, `navItems.ts` 의 `prominent`. 탭을 누르면 셸이 손가락으로 밀 때와 같은 미끄러짐으로 옮긴다(`onNavigate` → `appShellSwipe` 의 `slideTo`, ADR-014 v5). 눌림 효과·길게 누름 시트는 없고 비활성 → 활성으로 **바뀐** 칸의 아이콘만 제 모양대로 한 번 움직인다 — `navItems.ts` 의 `motion`, 키프레임은 `styles/appTabBar.css`) |
| ≥ 768px | 좌측 고정 `AppSidebar`. 탭바는 숨김 |
| ≥ 1024px (지도만) | 목록 패널 + 지도 2단 (`useMapPageWideLayout`) |

폭과 무관하게, **메인 탭이 아닌 화면에는 셸이 상단 `AppBar`(뒤로가기)를 얹는다** — 아래 참고.

**이미 서 있는 탭을 다시 누르면 맨 위로 부드럽게 돌아간다**(`AppTabBar`). 조건은 "지금 주소가
그 탭의 주소와 같은가" 이며, "불이 들어와 있나" 를 쓰면 안 된다 — 하위 화면에서도 들어온 탭에
불이 들어와 있으므로, 상세에서 그 탭을 눌러도 목록으로 가지 못하고 제자리에서 스크롤만 한다. 다른 탭으로 옮길 때는 아무것도 하지 않는다(셸이
경로가 바뀌면 그 화면의 자리로 스크롤을 되돌린다 — 아래 참고). 전역 `scroll-behavior: smooth`
도 쓰지 않는다 — 그 복원까지 애니메이션돼 화면 전환마다 스크롤이 흐른다.

**브레이크포인트는 배치만이 아니라 크기도 바꾼다.** `globals.css` 가 `--spacing` 을 768px 에서
4 → 4.25px 로 올리고, 이 레포의 타이포·간격·컨트롤 높이가 전부 그 파생이라 화면 전체가 같은 비율로
커진다. 모바일 4px 은 44px 터치 기준이 걸려 있어 고정이다([ADR-006](../decisions/ADR-006-responsive-scale-and-font.md)).
본문 글꼴(Pretendard 서브셋 `Zgnn Sans`)도 `src/app/layout.tsx` 의 `next/font/local` 이 `<html>` 에 변수로 얹어,
`theme.css` 의 `--font-body` 가 그것을 1순위로 읽는다.

- 좌우 패딩 계약(`px-4 md:px-6`)은 **예외가 없다**(v10). 홈 히어로가 유일한 예외로 화면 끝까지 깔렸었는데, 라운드 판이 되면서 같은 계약으로 들어왔다.

### 뒤로가기 — 화면이 아니라 셸이 붙인다

> 왜 이렇게 했는지는 [ADR-007](../decisions/ADR-007-shell-owned-back-navigation.md).

`AppShell` 이 경로를 보고 **메인 탭이 아닌 모든 화면**에 `AppBar`(뒤로가기만, 제목 없음)를 얹는다.
화면 쪽 코드는 아무것도 하지 않는다 — 새 화면을 만들면 뒤로가기가 저절로 생긴다.

- **루트 판정은 `src/lib/appRoutes.ts`** 의 `ROOT_ROUTES` 한 곳. 메인 탭 5개(`/`, `/map`,
  `/places/{stay,restaurant,cafe}`, `/checklist`, `/settings`)만 루트다. 둘러보기는 주소가 셋이지만
  사용자에게는 한 화면 안의 탭 전환이라 셋 다 루트다.
- `parentRouteOf`(정해 둔 부모 — 들어온 길을 모를 때만 쓴다): 상세는 장소 종류의 목록으로, **`/dog`·`/saved` 는 `/settings` 로**
  (설정에서 들어가는 화면이라서), 그 밖은 홈으로. `/saved` 는 v35~v58 동안 홈 아래였는데(12 U3.6) 탭 불이 들어온 길을 따르게 된 뒤로는
  "홈 카드가 주 진입점" 이 부모를 정할 이유가 아니다 — 홈 카드로 들어오면 어차피 홈에 불이 들어온다.
- **탭 불은 가장 가까운 history 의 탭이다**(`ownerRootOf` · `useNavHighlightPath`, ADR-025 결정 6). 하위 화면은 처음 들어올 때 직전
  화면의 탭을 물려받아 history 항목에 새기고(`zgnnRoot`), 뒤로가기로 돌아오면 그 값을 다시 읽는다 — 설정 → 저장한 곳 → 상세 → 근처 상세는
  끝까지 설정이고, 상세에서 뒤로 돌아온 저장한 곳도 설정이다. 딥링크면 정해 둔 부모의 탭, 새로고침이면 history 에 남은 값(첫 그림은 정적 HTML 과
  맞추려고 정해 둔 부모로 그리고 마운트 직후 고친다). `navItems.isActive` 는 이제 **탭 화면 주소만** 받는다 — `/saved`·`/place/` 를 거기 넣던
  정적 규칙은 같은 화면이 어디서 왔느냐로 갈리는 답을 할 수 없었다(14 W261006.10 의 `/dog` 예외가 모든 하위 화면으로 넓어진 것).
  `/admin` 은 이 표에 줄을 더하지 않았다 — 기본값(`'/'`)이 맞는 답이고, 적으면 그때부터 기억해야 할 것이 하나 늘어난다.
- **모르는 경로는 하위 화면으로 친다.** 기본값이 반대였다면 새 화면마다 뒤로가기를 기억해야 한다.
- 탭 불(`navItems.ts`)과 루트 판정을 섞으면 안 된다 — 상세에서도 들어온 탭에 불이 들어와 있다. 저기는 "어느 탭에 불이 들어오나",
  여기는 "되돌아 나올 곳이 있나" 다.
- `AppBar` 는 **바탕색(크림)으로 칠한 불투명 헤더**다(v21). 예전엔 칠하면 따라다니는 색 띠가 된다고
  투명하게 뒀지만, 그 색이 바탕 자체가 되면서 띠가 되지 않는다(→ [ADR-010 v4](../decisions/ADR-010-shell-owned-safe-area.md)).
- **v10 부터 하위 화면은 전부 같다.** 상세 제목 판이 자기를 끌어올리던 음수 마진(`under-app-bar`
  → 그 전 `-mt-14 pt-14`)을 버려, `/saved`·`/dog` 처럼 앱바 줄 자리가 크림으로 남는다. 상세만
  예외였던 것이 규칙으로 들어왔다.
- `AppBar` 는 **`bleed-top-0 sticky top-0`** 라 스크롤을 따라오고 상태바 자리까지 자기가 덮는다. `fixed` 로 바꾸면 흐름에서 빠져 높이가
  0 이 되고, 아래 내용이 그만큼 올라와 뒤로가기 버튼 밑에 깔린다(v9 까지는 상세 제목 판을 화면
  밖으로 밀어내기까지 했다 — v10 에서 그 음수 마진이 없어져 결합은 풀렸다).
  맨 위에서는 바탕과 구별되지 않고, 내려 읽을 때만 아래 선이 생긴다.
- 제목은 셸이 모른다(경로만 안다). 그래서 상세의 큰 이름이 폭과 무관하게 그 화면의 유일한 `h1` 이고,
  그 `h1` 이 헤더 밑으로 들어가면 헤더가 같은 글을 띄운다(→ [ADR-007 v4](../decisions/ADR-007-shell-owned-back-navigation.md)).
- **v27: 그 제목이 스크롤을 따라 줄 아랫변에서 올라온다.** h1 윗변이 헤더 아랫변에 닿을 때부터 h1 이 다 가려질 때까지(`barRevealRange`)
  — 본문의 제목이 헤더로 밀려 들어가는 것처럼 읽힌다. 준비물·홈과 같은 장치라 지원하면 스크롤 구동, 아니면 다 가려진 순간 한 번 전환이다.
  제목 칸은 `overflow-clip` 이어야 한다 — `hidden` 은 스크롤 상자를 만들어 안의 `scroll(nearest)` 가 문서 대신 그 칸을 잡고 **멈춘다**(실측,
  빌드·테스트는 통과했다).
- **v27: 화면이 제목 자리를 채울 수 있다**(`AppBarSlot`, 포털). 상세는 왼쪽에 종류 아이콘·이름, 오른쪽에 읍면·종류(`구좌읍 · 펜션`)를 올린다
  (`placeDetailAppBar.tsx`). 채우지 않는 화면은 h1 복사본 그대로라 "새 화면은 아무것도 안 해도 된다" 는 유지된다. 자리는 헤더가 ref 로
  모듈 한 칸에 적고 슬롯이 구독한다 — 탭 화면에서 상세로 바로 들어오면 헤더와 화면이 같은 커밋에 처음 붙어, 렌더 중에 DOM 을 찾으면 자리가 아직 없다.
- **v28: 상세는 본문 제목 줄이 헤더로 날아 들어간다**(`placeDetailHeader.tsx`, 기하는 `lib/titleFlight.ts`). 타일이 상호명 왼쪽에 한 줄로 서고,
  그 줄이 본문과 같이 스크롤되다 **세로 중심이 헤더 가운데에 닿는 스크롤**까지 타일·상호명이 각각 헤더의 아이콘·상호명 자리로 가로로 옮겨
  가며 준다. 세로는 계산하지 않는다 — 스크롤이 저절로 맞춘다(`origin-left` 라 줄여도 세로 중심이 안 움직인다). 마지막 15% 에 헤더 복사본
  (`placeDetailAppBar`, 글리프·상호명)과 겹쳐 바뀐다. 비직관적인 것:
  - **헤더 복사본은 움직이면 안 된다.** 본문 쪽이 그 자리를 재서 겨냥하므로, 슬롯이 채워지면 셸의 "밑에서 올라오기" 를 CSS `:has` 로 끈다
    (`scrollMorph.css`, 인라인 스타일을 이기려고 `!important`).
  - **본문 줄은 헤더보다 위(`z-[31]`)에 그린다** — 밑이면 헤더에 닿는 순간 가려져 날아 들어가는 것이 안 보인다. 그래서 `pointer-events-none` 이다
    (옮겨 가는 동안 뒤로가기 버튼 위를 지난다).
  - 타일은 글리프가 헤더 아이콘(20px) 크기가 될 때까지만 준다(≈0.91). **색 판은 절반까지 빠지고 크기도 절반까지 다 준다** — 판이 끝까지 남으면
    40px 판이 뒤로가기 화살표 옆을 스쳤다(실기기 피드백). 판 위에 같은 글리프를 겹쳐 두고 판만 투명하게 해 아이콘은 끊기지 않는다.

### 상태바 인셋 — 여백은 셸이, 맨 위 면은 전 화면 크림

`viewportFit: cover` 라 내용이 상태바 밑까지 깔린다. **여백은 셸이 한 곳에서만 준다** —
`<main>` 에 인셋만큼. 화면 쪽에 `pt-safe` 는 없다.

그 여백은 아무도 칠하지 않아 페이지 바탕(크림)이 비친다. **모든 화면의 맨 위 면이 크림이므로
그것으로 끝난다**(v10) — 화면 쪽에서 할 일이 없다. 홈 히어로는 그 크림 아래의 라운드 판이고,
상세 제목 판은 앱바 줄 밑에서 시작한다. 지도만 여백조차 없다.

`bleed-top-*` 은 둘러보기 검색 줄(`bleed-top-4`) 하나만 쓴다. 색을 바꾸려는 게 아니라 위에
붙었을 때(`top-0`) 자기 블러 배경으로 인셋 자리를 덮는 용도다.

**두 번 고쳤고 두 번 다 "화면마다 맨 위 색이 다르다" 가 원인이었다.** v8 은 셸이 인셋 높이의
띠를 `fixed` 로 깔고 경로표(`topSurfaceColorOf`)가 첫 블록의 색을 복제해 칠했는데, 띠가
viewport 에 고정돼 스크롤을 내리면 색이 안 맞는 내용 위에 홀로 떠 있었다. v9 는 띠를 버리고
첫 블록(`data-top-surface`)의 색을 읽어 `<html>` 배경에 옮겨 담았다. v10 은 전제를 없앴다 —
`<html>` 배경은 `globals.css` 가 크림으로 정적으로 칠하고 아무도 덮어쓰지 않는다(→
[ADR-010 v3](../decisions/ADR-010-shell-owned-safe-area.md)).

**화면 위에 뜨는 줄은 불투명이어야 한다.** iOS 26 Safari 가 가장자리 `fixed`/`sticky` 요소의
배경색을 읽어 자기 툴바를 칠하는데, `collapsingTitleBar` 는 접히지 않은 동안에도 `opacity-0`
으로 **남아 있어** 보이지 않는 채로 그 색을 정할 수 있다. 탭바·축약 줄 모두 불투명이다.

**딥링크 보정(`src/lib/appHistory.ts`)** — 링크로 상세에 바로 들어온 사용자가 뒤로가기를 누르면 앱 밖으로 나간다.
그래서 history 항목이 앱 안에서 몇 번째인지를 세어 두고, 첫 화면이면 `router.back()` 대신
`parentRouteOf(pathname)` 으로 `replace` 한다. 상세의 부모는 장소 종류에 따라 갈리므로(카페 상세 → `/places/cafe`)
경로만 보지 않고 데이터를 본다. `markReplacedNavigation()` 은 이 교체 이동이 깊이를 늘리지 않게 한다.
같은 경로에서 주소만 고치는 `replace`(지도의 `?saved=1`, 끝 `/` 정리)는 Next 가 새 state 에 우리 값을 싣지 않고 셸도 다시 새기지 않으므로,
`carryHistoryStamp` 가 지금 항목의 깊이·탭을 잇는다 — 안 그러면 뒤로 돌아올 때 처음 온 항목으로 읽혀 걷기가 덮기로 그려지고 탭 불을 잃는다(ADR-025).
테스트: `src/lib/appHistory.test.ts`, `src/lib/appRoutes.test.ts`.

**탭 화면끼리는 history 를 쌓지 않는다(`keepTabsOffHistory`, ADR-025 결정 7).** 탭바·사이드바·좌우 스와이프·종류 알약·화면 안 링크(홈의
"지도에서 보기" 등) 어느 길로든 탭 화면 → 다른 탭 화면이면 `pushState` 를 `replaceState` 로 바꾼다 — 길마다 `replace` 를 챙기지 않고
history 가 쌓이는 자리 하나(Next 의 `HistoryUpdater` 가 부르는 `pushState`)에서 가른다(`isTabSwitch`). 셸 모듈 최상단에서 감싸
Next 의 감싸개보다 먼저 선다. 결과: 탭 화면 뒤에는 앱 안 탭이 없어 브라우저·안드로이드 뒤로가기는 앱을 나가고(또는 탭바로 나오기 전의
하위 화면으로 돌아가고), iOS Safari 의 가장자리 뒤로가기도 탭 사이를 걷지 않는다. 쿼리만 바뀌는 이동과 하위 화면이 낀 이동은 그대로 쌓는다.

### 하위 화면은 위에 쌓인다 — 덮기 · 걷기 · 가장자리 스와이프

> 왜 이렇게 했는지는 [ADR-025](../decisions/ADR-025-stack-push-pop-transition.md).

탭 화면끼리가 **나란히**(아래 절)라면 그 안으로 들어간 화면(`/dog`·`/saved`·`/place/:id`)은 **위에** 쌓인다.
들어가면 새 화면이 오른쪽에서 덮고 밑 화면은 30% 물러나며 그늘이 지고, 뒤로가면 그 반대로 걷힌다. 하위 화면의
왼쪽 가장자리(홈 화면 앱 0~48px · 브라우저 24~48px)를 오른쪽으로 끌면 손가락을 따라 걷힌다.

| 무엇 | 어디 |
|---|---|
| 이 이동이 덮기·걷기·없음 중 무엇인가(history 깊이 변화 + 셸이 건 뒤로가기) | `lib/stackTransition.ts` 의 `stackTransitionOf` |
| 떠나기 직전 `<main>` 을 떠 두기(문서 click · popstate 를 **capture** 로) · 그림 · 가장자리 끌기 | `components/layout/appShellStack.ts` |
| 뒤로가기의 문 하나 — 헤더 화살표와 "저장하고 돌아가기" 가 함께 | `appShellStack` 의 `goBackInApp` |
| 시간·곡선·물러나는 비율 | `lib/swipePager.ts` 의 `STACK_*` |

셸의 경로 이펙트에서 **`finish`(옆 페이저 정리)·스크롤 복원·깊이 새기기 뒤에** `arrive` 를 부른다 — `finish` 가 `<main>` 의
transform 을 지우므로 순서가 바뀌면 그림이 지워진다. 층은 `body` 가 아니라 셸 안에 붙는다(셸 바깥 상자의 `isolate` 때문).

### 화면 사이도 손가락으로 넘긴다 — 셸이 소유하는 한 줄

> 왜 이렇게 했는지는 [ADR-014](../decisions/ADR-014-shell-owned-swipe-pager.md).
> 둘러보기 **안**의 종류 전환은 [ADR-013](../decisions/ADR-013-places-swipe-pager.md).

탭바의 다섯 자리를 둘러보기만 종류 셋으로 펼쳐 **한 줄로 늘어놓는다**
(`lib/appRoutes.ts` 의 `SWIPE_ROUTES`). 손가락에게는 이게 전부다:

```
홈 ─ 지도 ─ 숙소 ─ 식당 ─ 카페 ─ 준비물 ─ 설정
```

`ROOT_ROUTES`(뒤로가기 판정)는 이 배열에서 파생한다 — 스와이프로 가는데 뒤로가기가 붙는
화면이 생기면 그게 버그다. 탭 하이라이트는 여전히 다섯 칸(`navItems.isActive`)이다. 스와이프로 옮겨도 history 는 쌓이지 않는다(`keepTabsOffHistory`).

| 이동 | 주인 | 움직이는 것 |
|---|---|---|
| `/places/*` → `/places/*` | `screens/placesPageSwipe.ts` | 헤더는 선 채 목록과 탭 알약만 |
| 그 밖 | `components/layout/appShellSwipe.ts` | `<main>` 통째로. 탭바는 제자리 |

두 인식기가 같은 포인터 이벤트를 다 받지만, 축이 가로로 잠기는 순간 둘 다
`isWithinPlacesSwipe(지금, 다음)` 에 같은 질문을 던져 정확히 한쪽만 잠긴다 — **서로에게 신호를
보내지 않는다.** 손가락에 관한 숫자(거리·속도·저항·축 고정·밀어내는 시간)는 전부
`lib/swipePager.ts` 한 곳에 있다.

- **지도에서는 밀어서 나갈 수 없다**(`canStartSwipeAt`). 화면 전체가 캔버스라 가로로 끄는 동작이
  이미 지도의 것이다. 들어오는 것은 되고, 나갈 때는 탭바를 쓴다. 같은 이유로 지도에서는
  `touch-action` 도 걸지 않는다.
- **이웃은 진짜 화면을 그린다**(`appShellSwipePeek`) — `<main>` 밖에 `fixed` 로, `inert` 로.
  지도만 예외로 "갓 마운트된 지도" 대역(크림 한 장)을 세운다. 카카오 SDK 를 제스처 중에
  받기 시작하면 첫 프레임이 걸린다.
- **`<main>` 에 transform 이 걸리면 그 안의 `position: fixed` 는 화면이 아니라 `<main>` 기준이
  된다.** 축약 줄이 그래서 `top: var(--swipe-viewport-top, 0px)` 를 쓴다(셸이 잠기는 순간 지금
  스크롤 값을 적어 상쇄). **화면 안에 `fixed` 를 새로 두면 같은 함정을 밟는다.**
- 화면 규격(`<main>` 의 폭·여백)은 `appShellSurface.ts` 에 있고 **셸과 엿보기가 같은 함수를
  부른다** — 어긋나면 놓는 순간 내용이 옆으로 튄다. 갈래는 셋이고 주소에서 `surfaceKindOf` 가 고른다:
  `reading`(기본 `max-w-3xl`) · `map`(제한 없음·여백 없음) · `wide`(`/admin`, `max-w-7xl`).
  **폭을 화면 쪽에서 정하지 않는다** — 엿보기가 같은 값을 봐야 하고, 화면은 자기가 어디에 놓였는지 모른다.

### 스크롤은 화면마다 제자리를 지킨다 (`lib/appScroll.ts`)

옆으로 미는 동작은 화면들이 나란히 떠 있다고 말한다. 나란히 떠 있는 것은 눈을 뗐다고 맨 위로
되감기지 않는다. 목록도 마찬가지다 — 상세를 들렀다 나오면 보고 있던 항목이 다시 보여야 한다.
그래서 **모든 화면이** 떠날 때의 세로 위치를 모듈 변수에 적어 두고 도착할 때 되돌려 놓는다.
자리는 스크롤 이벤트로 ref 에 받아 둔다(경로가 바뀐 **뒤에** `window.scrollY` 를 읽으면 이미 늦다).

**주소로 된 예외는 하나도 없다.** "방금 연 것" 과 "되돌아온 것" 은 주소로 구별되지 않아서,
주소로 가르면 반드시 한쪽이 틀린다(→ [ADR-014](../decisions/ADR-014-shell-owned-swipe-pager.md) §5).
맨 위에서 시작해야 하는 이동은 **그 이동을 하는 쪽**이 도착점 기억을 0 으로 적어 말한다.

**복원이 실제로 보이는 이동은 스와이프와 뒤로/앞으로뿐이다.** 탭바·사이드바·알약(`next/link`)을
탭해서 옮기면 도착이 늘 맨 위다(2026-09-18 실측, 원인 미확인 — ADR-014 §5). 이전 정책에서도
같았다.

맨 위에서 시작하도록 **코드가 직접 말하는** 곳은 하나다:

- **둘러보기의 종류 전환**(`screens/placesPageSwipe.ts` 의 `settle`) — 종류를 바꾸면 조건이 전부
  리셋되는데(`key={type}`) 자리만 남기면 한 화면이 두 가지 말을 한다. 종류 전환의 엿보기가
  이웃을 맨 위로 그리는 것과도 짝이 맞는다(ADR-013). 같은 화면을 떠나서 **돌아오는** 것은
  예외가 아니다 — 카페에서 준비물로 밀고 돌아오면 제자리다.

스와이프의 `router.push` 에는 `scroll: false` 를 준다 — Next 의 기본 리셋과 셸의 복원이 같은
프레임에 싸우면 어느 쪽이 이겼는지 알 수 없다.

### 준비물 — 제목이 곧 헤더가 된다 (`StickyMorphTitle`, v22)

사용자가 원한 것은 "별도의 줄이 내려온다" 가 아니라 **"본문의 제목이 올라가다 붙어서 헤더가 된다"**(애플 제품 페이지의 로컬 내비)였다.
그래서 준비물은 축약 줄 대신 제목 줄 자체를 `sticky` 로 둔다.

1. **진입하면 지금과 같다** — 큰 제목(`display-xs`)이 PageHeader 때와 같은 자리(위 24px)에 있고, 소개 문장이 바로 밑에서 시작한다.
2. **스크롤하면 같이 올라간다** — 흐름 안의 요소라 상태바에 닿기 전까지는 본문과 한 몸이다.
3. **상태바에 닿으면 붙고, 거기서부터 스크롤한 거리(줄 높이 하나)만큼 접힌다** — 글자 24 → 16px, 줄 바닥 → 가운데,
   밑줄·오른쪽 `N/M 준비됨`·얇은 진행 막대가 같은 비율로 나타난다.
4. **시간이 아니라 위치의 함수다** — `--morph`(0~1)를 스크롤 위치로 매 프레임 적으므로 되돌아 스크롤하면 같은 길을 되짚는다.
   방향을 바꿔도 튀지 않고, 애니메이션을 "재생" 하지 않으니 `motion-reduce` 에서도 그대로 둔다.

비직관적인 것:

- **줄 높이는 접히는 동안 고정이고 글자는 `scale` 로 줄인다.** 흐름 안의 요소가 높이를 바꾸면 아래 본문이 스크롤과 다른
  속도로 끌려 올라와 읽던 자리가 미끄러진다. 높이는 처음부터 접힌 헤더 높이(14단, `AppBar` 와 같다)다.
- **큰 제목은 줄의 바닥에 앉아 있다가 접히며 가운데로 올라간다.** 처음부터 가운데에 두면 제목 밑에 12px 이 남고, 그걸 음수 여백으로
  당기면 소개 문장 윗부분이 이 줄의 불투명 배경 밑으로 들어가 **잘려 보였다**(실측).
- **`fixed` 가 아니라 `sticky` 라 스와이프 보정(`--swipe-viewport-top`)이 필요 없다.** 셸이 `<main>` 에 transform 을 걸어도
  `sticky` 는 스크롤 영역 기준이라 자리가 어긋나지 않는다(아래 축약 줄이 그 변수를 쓰는 이유와 대조).
- **진행도는 `window.scrollY` 가 아니라 센티넬의 화면상 위치로 계산한다**(`lib/stickyMorph.ts`). 셸이 옆 화면을 엿보기로 그릴 때
  그 화면은 문서 스크롤과 무관한 자리에 있다. 인셋은 `env()` 를 JS 가 못 읽어 높이를 가진 탐침으로 잰다.
- 값은 React 상태가 아니라 줄의 CSS 변수 하나로 흘린다 — 스크롤 프레임마다 목록 전체를 다시 그리지 않게.
- 제목은 진짜 `<h1>` 이라 접혀도 한 번만 읽힌다. 오른쪽 요약·진행 막대는 본문에 진짜가 있는 복사본이라 `aria-hidden`.

### 홈 — 잉크 히어로가 헤더가 된다 (`HomePageHero`, v23)

같은 네 약속(진입 = 지금 · 올라감 · 붙음 · 위치의 함수)을 **면**에 적용한다. 바뀌는 것이 글자 하나가 아니라 좌우 여백·모서리·색·높이다.

- **블록 전체가 `sticky` 이고 `top` 이 음수다**(`인셋 + 헤더 − 블록 높이`, JS 가 잰다). 블록은 아래쪽 헤더 한 줄만 남을 때까지 올라가다 붙는다.
  준비물과 달리 **붙기 전부터** 접힌다 — 붙는 순간 이미 헤더 모양이어야, 250px 카드가 화면 위를 덮고 있는 구간이 없다.
- **면은 `clip-path: inset()` 으로 줄인다.** 여백·높이를 실제로 바꾸면 아래 카드들이 스크롤과 다른 속도로 움직인다. 잉크·크림 두 장이 같은 클립을 쓰고
  투명도만 서로 바뀐다. 클립의 윗변이 헤더 윗변까지 내려와서, 카드 윗모서리가 화면 밖으로 먼저 사라지지 않고 헤더 쪽으로 내려앉는다.
- **색은 마지막에 바꾼다**(`--tone`: 접힘 0.55 → 0.95). 처음부터 같이 섞으면 중간이 회색 판 위 회색 제목이 돼 안 읽혔다(실측).
  그전까지는 잉크 판 위 흰 제목이 줄어들며 올라간다.
- 발바닥·부제·수는 처음 25% 안에 사라진다 — 늦으면 올라오는 제목이 부제 위에 겹쳐 읽힌다(실측, 40% 에서 겹쳤다).
  (지금 발바닥은 사라지지 않고 제목 앞 표식으로 헤더에 들어간다. 부제·"갈 수 있는 곳 N곳" 줄만 25% 안에 비킨다. 그 줄은 프로필이 있을 때만 있어 블록 높이가 하이드레이션 뒤에 바뀐다 — `ResizeObserver` 가 다시 잰다.)
- **수 줄 자리는 슬롯 둘 중 하나다**(v46, 18 T4) — 프로필이 있으면 `reach`("두부가 갈 수 있는 곳 N곳"), 없으면 `cta`(등록 버튼, 브랜드 면). 버튼도 부제와 같은
  `fade-early` 묶음이라 25% 안에 비키고, 다 접히면 `visibility: hidden` 으로 숨어 **접힌 헤더 자리에서 눌리지 않는다**(투명도 0 만으로는 상태바 밑에 걸린 채 눌린다).
- **면은 v24 부터 `clip-path` 가 아니라 크림 커튼·귀로 가린다** — 아래 절.

**히어로 밑의 순서(v46, 18 T2~T4)** — **내 여행** → 인사말 카드(**첫 방문에만**) → 어디로 갈까요 → 지역으로 찾기(관광지 칩) → 인사말 한 줄·설치 안내(두 번째 방문부터) → 출처.
「내 여행」(`HomePageTripCard`)은 저장한 곳과 준비물 진행을 **흰 카드 하나의 두 줄**로 — 준비물은 저장한 숙소에서 파생되고(ADR-009) 동선(16)도 저장 위에 얹으니 홈의 입구도 하나다.
저장·체크가 다 0 이면 등록한 사람에게만 크림 위 한 줄, 등록 전엔 섹션째 없다. 머리 줄까지 카드가 그려 빈 머리가 남지 않는다. 계절 칩은 홈에서 뺐다(준비물 화면 머리에 같은 칩이 있다).
「지역으로 찾기」 는 비퍼시스트 검색어만 건다 — **홈은 퍼시스트 `town` 을 걸지 않는다**(예전 종류 카드의 읍면 칩이 다음 방문까지 남았다, [home-header](../features/home-header.md) v7).
등록 CTA 는 v46 부터 히어로 안이다 — 밑에 따로 서면 첫 화면에 잉크 판과 핑크 판, 큰 덩어리가 둘이었다(디자인 리뷰 2026-10-06 §10 ①).
(v41 의 순서: 등록 CTA → 인사말 카드 → 어디로 갈까요 → 준비물 → 저장한 곳 → 인사말 한 줄 → 출처.)
인사말이 매번 히어로 밑에 펼쳐져 화면 절반을 먹고 CTA 를 폴드 밑으로 밀었다(UX 평가 2026-10-06). 글은 첫 화면에서 한 번은 읽혀야 해서(신뢰는 "짱구누나가 직접" 에서 온다) 없애지 않고 자리를 옮겼다.
어느 쪽인지는 `visitCount`(스토어 표) 로 가르고, 읽기 전엔 둘 다 그리지 않는다.

### 접히는 헤더가 모바일에서 버벅이던 것 (v24)

PC 에서는 매끄러웠고 폰에서만 버벅였다. 원인은 둘이었고, 둘 다 "GPU 를 켜면" 풀리는 것이 아니었다 — GPU 가 할 수 없는 일을 매 프레임 시키고 있었다.

1. **한 박자 늦었다.** 모바일은 스크롤을 합성 스레드가 먼저 움직인다. `sticky` 블록은 손가락을 바로 따라가는데, 그 안의 제목 위치·크기는
   메인 스레드의 scroll 이벤트 → rAF → `--morph` 쓰기를 거쳐 늦게 따라와 접히는 동안 위아래로 떨렸다. 글자 크기가 "부자연스럽게" 준 것은
   이것과, 변수로 바뀐 `transform` 을 새 배율로 다시 래스터하느라 글자 폭이 프레임마다 흔들린 것이 겹친 것이다.
2. **매 프레임 다시 그렸다**(홈). `clip-path: inset(… round …)` 와 `color-mix` 글자색은 합성되지 않는 값이라, 현무암 무늬(radial-gradient
   네 겹)를 폰의 3배 화소로 매 프레임 다시 그렸다. 층을 따로 올려도(`will-change`) 크롬은 `clip-path` 가 바뀌면 그 층을 통째로 다시 그렸다(실측).

그래서 지금은:

- **접힘을 브라우저의 스크롤 구동 애니메이션이 돌린다**(`animation-timeline: scroll(nearest)`, `styles/scrollMorph.css`). JS 는 크기가 바뀔 때
  구간(`--morph-from`·`--morph-to`, 스크롤 오프셋)과 기하만 적는다. 구간은 `lib/stickyMorph.ts` 의 `stickyMorphRange`·`collapseRange` 가
  계산하고, 옛 진행도 함수와 **모든 스크롤 위치에서 같은 값**이라는 것을 테스트가 잡는다. 여전히 위치의 함수라 되돌아 스크롤하면 같은 길로 풀린다.
- **움직이는 것은 `transform`·`opacity` 뿐이다.** 글자·발바닥 색은 섞지 않고 **두 벌을 겹쳐 투명도로** 바꾼다(뒷 벌은 `aria-hidden`).
- **히어로 면은 가만히 있고 가장자리를 크림 커튼이 덮는다.** 잉크·크림 판은 블록 전체에 깔려 투명도만 바뀌고, 왼·오른 커튼이 걷히고 위 커튼이
  내려오는 만큼 카드가 헤더 모양이 된다. 모서리는 네 귀의 크림 조각이 16px → 0 으로 줄며 만든다. 판 자체를 `scale` 로 누르는 쪽을 먼저 해봤는데,
  모서리가 납작한 타원이 되고 현무암 점이 가로줄로 늘어났다(실측) — 커튼·귀는 단색이라 늘여도 티가 안 난다. **커튼·귀는 페이지 바탕과 같은
  크림이라야 보이지 않는다** — 히어로 밑 바탕색을 바꾸면 카드 바깥에 색 띠가 드러난다.
- 크롬 실측(390×844, DPR 3, CPU 4배 감속, 같은 스크롤 왕복 3회): 홈에서 다시 그린 층 296 → 14, 페인트 450 → 51ms, 스타일·레이아웃 313 → 15ms.
  준비물은 43 → 4. 전·후 스크린샷 차이는 모든 스크롤 위치에서 화소 1% 미만이다. **iOS Safari 는 실기기로만 확인된다** — Safari 26 부터 스크롤 구동
  애니메이션을 지원하고, 그 이전·Firefox 는 `CSS.supports` 가 거짓이라 예전처럼 JS 가 `--morph` 를 적는다(인라인 `calc(var(--morph))` 가
  같은 모습을 내고, 지원하면 애니메이션 값이 인라인 스타일을 이긴다).
- **구간 비율(0.25·0.55·0.95 …)은 `scrollMorph.css` 의 키프레임과 컴포넌트의 인라인 식 두 곳에 있다.** 한쪽만 고치면 브라우저마다 다르게
  접히고, 크롬에서는 인라인 쪽이 안 쓰여 눈에 띄지 않는다.
- **지원하지 않는 브라우저는 다르게 보인다**(v25, `snap`). 같은 모습을 JS 로 흉내 내면 v24 가 고친 늦음·떨림이 그대로 남아(대개 느린 옛 기기다),
  스크롤을 따라가지 않고 **경계를 넘을 때 한 번** `--morph` 를 0 ↔ 1 로 바꾸고 사이를 250ms 전환(transform·opacity)이 채운다. 준비물·설정은 줄이
  붙어 반쯤 올라가면, 홈은 블록이 붙는 순간 접힌다 — 붙기 전에 접으면 헤더 한 줄이 화면 가운데에 떠서 올라온다. 방식은 루트의 `data-morph`
  (`scroll`·`snap`, `morphModeOf` 가 `CSS.supports` 와 **'동작 줄이기'** 로 고른다 — reduce 면 지원해도 `snap`, 전환 0 이라 경계에서 한 번에 바뀐다. 전역 reduce 리셋은 스크롤 타임라인을 못 멈춘다, [BUG-015](../bugs/BUG-015-reduced-motion-scroll-morph.md))가 정하고, `snap` 은 다음 프레임에 적는다(스크롤이 복원된 채 들어올 때
  진입하자마자 전환이 재생되지 않게). snap 모습을 지원하는 기기에서 보려면 `morphModeOf` 가 `'snap'` 을 돌려주게 잠시 바꾸면 된다(v25 에 그렇게 비교했다).
- **스크롤 기준은 가장 가까운 스크롤 상자다**(`scrollDrivenMorph.ts` 의 `offsetInScroller`). 셸의 엿보기(ADR-014)는 자기 스크롤 상자를 가지므로
  `window.scrollY` 로 구간을 재면 엿보기에서 틀린다. CSS 의 `scroll(nearest)` 도 같은 상자를 고른다 — 셸의 `overflow-x-clip` 은 스크롤 상자를
  만들지 않아 본 화면의 기준은 문서다. `<main>` 위에 `overflow: hidden|auto` 를 새로 두면 접힘이 그 상자를 따라가 멈춘다.

### (지움) 제목이 사라지면 축약 줄이 대신 선다 (`CollapsingTitleBar`)

> v23 에 지웠다 — 준비물·설정은 `StickyMorphTitle`, 홈은 `HomePageHero` 로 옮겨 쓰는 곳이 없어졌다. 아래는 그때의 결정 기록이다
> (`fixed` 여서 생긴 스와이프 보정·iOS 툴바 색 샘플링 문제는 `sticky` 로 옮기면서 함께 사라졌다).

메인 탭에는 `AppBar` 가 없다(뒤로가기가 필요 없으므로). 그래서 아래로 내려가면 상단에
아무것도 남지 않는다 — 준비물은 목록이 길어 "몇 개 남았더라" 를 보려면 맨 위까지 되올라가야
했다. 제목 블록이 화면 밖으로 나가는 **그 순간에만** 한 줄(제목 + 짧은 요약 + 진행 막대)을
띄운다. 위에 있을 때는 큰 제목이 이미 말하므로 아무것도 하지 않는다.

지금 쓰는 곳은 **홈**(`강아지랑 제주`) 하나다. 준비물은 v22 부터 아래 `StickyMorphTitle` 로 옮겼다. 나머지 셋은 붙이지 않는다 — 둘러보기는 이미 종류 탭·검색이 `sticky` 로 남고,
지도는 스크롤이 없으며, 설정은 한 화면에 들어온다.

- **`fixed` 다.** 나타났다 사라지는 줄이 흐름에 자리를 차지하면 나타나는 순간 아래 내용이
  통째로 밀려 읽던 자리가 튄다. 늘 있어서 자리를 잡아 두어야 하는 `AppBar`(`sticky`)와
  갈리는 지점이다.
- **상태바 인셋은 스스로 칠한다.** 셸은 색을 모르므로(위 절), 화면 위에 떠서 그 자리를
  덮는 줄은 자기 배경을 인셋만큼 위로 늘려야 한다 — 안 그러면 노치 기기에서 이 줄 위로
  내용이 스쳐 지나간다.
- **접히는 지점은 JS 로 재지 않는다.** 제목 블록 바닥에서
  `calc(env(safe-area-inset-top) + var(--spacing) * 14)` 만큼 띄운 1px 센티넬을
  `IntersectionObserver` 로 본다. 노치 높이도 반응형 스케일(`--spacing`)도 브라우저가 계산하므로,
  기기를 돌리거나 브레이크포인트를 넘어도 다시 잴 것이 없다. 재는 쪽으로 만들면 그
  재계산을 한 번 빠뜨린 상태에서만 접히는 지점이 어긋난다.
- `isIntersecting` 만 보면 안 된다 — 화면이 길어 페이지 전체가 들어오는 데스크톱에서는 센티넬이
  **아래로** 벗어난 경우에도 참이 아니게 된다. 위로 나갔을 때만 접도록 `boundingClientRect.top < 0`
  을 함께 본다.
- 줄 전체가 `aria-hidden` 이다. 제목도 진행률도 본문에 진짜가 있고 여기 것은 복사본이라,
  스크린리더가 두 번 읽으면 안 된다.
- **상태바 뒤에서 미끄러져 내려온다.** 접히면 `-translate-y-full` → `0`. 이 요소의 높이에는
  상태바 인셋(`paddingTop`)이 들어 있어서 올라가 있는 동안에는 인셋까지 통째로 화면 밖이다 —
  그래서 "노치 위에서 내려온다" 로 보인다. 페이드만 하던 판은 같은 자리에서 색만 짙어져,
  없던 줄이 생겼다기보다 화면이 얼룩진 것처럼 보였다.
  배경(`bg-secondary`)은 페이지 바탕과 **같은 값**이라(ADR-010 v3 의 크림) 내려오는 동안
  새 면이 덮이는 느낌이 아니라 제목과 아래 경계선만 나타난다. 여기서 다른 색을 쓰면 그
  순간 화면이 두 층으로 쪼개져 보인다. 들어올 때 300ms `ease-out`, 나갈 때 200ms `ease-in`.

### 종류 전환은 방향을 가진다 (`placesPageTypeTabs` · `placesPageTypeSwitch`)

둘러보기의 숙소·식당·카페는 나란히 놓인 세 묶음이다. 고른 탭의 배경을 켜고 끄기만 하면
"옛 것이 꺼지고 새 것이 켜졌다" 일 뿐, **그 사이를 옮겨 갔다는 말은 못 한다.** 그래서 알약
하나가 탭 사이를 옮겨 다니고, 새 목록도 알약이 간 쪽에서 따라 들어온다.

- **"어디서 왔는지" 는 모듈 변수에만 남는다.** 종류를 바꾸면 화면이 통째로 새로 마운트된다
  (`key={type}` — 조건을 리셋하려고 일부러 그렇게 뒀다). 그래서 어떤 컴포넌트 상태도
  전환을 넘어 살아남지 못한다. `placesPageTypeSwitch.ts` 의 `lastType` 이 그 자리다.
  주소를 새로 열면 `null` 이라 아무 데서도 오지 않은 것이 되고, 그때는 움직이지 않는다 —
  첫 화면이 이유 없이 흔들리지 않게.
- **알약의 렌더는 늘 도착점이다.** 출발점을 그렸다가 옮기는 방법은 이펙트가 곧바로 리렌더를
  부르는 모양이라 린트가 막는다(`react-hooks/set-state-in-effect`). 대신 도착점에 그려 두고
  거기까지 오는 길만 `element.animate()` 로 따로 그린다 — **애니메이션의 중간 좌표는 리액트가
  알아야 할 상태가 아니다.** 정적 HTML 에도 올바른 자리로 박혀 나온다.
- 알약 폭은 `calc((100% - var(--spacing) * 2) / 종류 수)`. 절대 위치의 기준이 `nav` 의 padding box 라
  이 식이 탭 하나의 폭과 정확히 같고, 종류가 늘어도 식은 그대로다. 패딩을 `0.5rem` 으로 굳히면
  안 된다 — `p-1` 은 `--spacing` 파생이라 브레이크포인트마다 값이 바뀐다(ADR-006).
- 목록은 `animate-in` + `slide-in-from-{left,right}-4`. 들어오는 동안 잠깐 밖에 있는 1rem 이
  가로 스크롤을 만들지 않게 `overflow-x-clip` 으로 막는다(`hidden` 과 달리 스크롤 컨테이너를
  만들지 않아 위의 `sticky` 를 건드리지 않는다).
- 모션을 줄이기로 한 사용자에게는 둘 다 도착점만. CSS 쪽은 `globals.css` 의 전역
  `prefers-reduced-motion` 리셋이 이미 끄고, WAAPI 는 그 리셋이 닿지 않으므로 알약 쪽은
  `matchMedia` 로 직접 판단한다(`appTabBar` 와 같은 규칙).
- **손가락으로도 넘긴다**(`placesPageSwipe`). 가로로 잠기면 목록과 알약이 손가락을 따라가고,
  이웃 종류의 본문이 옆에서 엿보인다(`placesPageSwipePeek` — 절대 위치·`inert`, 새 화면이
  마운트됐을 때와 같은 모습). 놓으면 남은 거리를 밀어낸 뒤 `router.push`. 새 화면이 또
  미끄러지지 않도록 도착점을 `lastType` 에 미리 적는다(`arriveBySwipe`). 왜 캐러셀이 아니라
  엿보기인지, 축 고정·`touch-action`·끝 저항·iOS 가장자리는 [ADR-013](../decisions/ADR-013-places-swipe-pager.md).
  본문(개수 줄·목록·빈 상태)은 `placesPageResults` 로 떼어 두어 지금 화면과 엿보기가 같은 것을 그린다.

### 작은 응답 모션과 이스터에그 (`styles/microMotion.css`, v52)

누른 사람에게 "됐어요" 를 몸짓으로 돌려준다. 탭바 아이콘 모션(`appTabBar.css`)과 같은 약속 — `transform`·`opacity` 만, 응답은 0.5s 안.

| 어디 | 무엇 | 언제 |
|---|---|---|
| 하트(카드·지도 시트·상세 액션 줄) | 쿵 커지고 점 여섯이 퍼진다. **8번에 1번 꼴로 점 대신 발바닥** | 저장할 때만(끌 때는 없음) |
| 저장 화면 메모 연필 | 끄적이듯 흔들리고, 입력 칸은 살짝 내려앉으며 나타난다 | 열 때만 |
| 준비물 줄 | 이모지가 한 번 뛴다. **마지막 하나를 챙기면 막대 위로 발바닥 행진** | 체크할 때 |
| 홈 히어로 발바닥 | 손 흔들기. **2초 안에 다섯 번이면 발자국이 카드를 가로지른다** | 누를 때 |
| 홈 줄(종류 카드·지도 버튼·지역·내 여행) | 접힌 히어로 밑으로 들어가기 직전에 작아지며 흐려지고, 아래에서 들어올 땐 다가온다 | 스크롤 위치 |
| 홈 맨 아래 | 발바닥이 고개를 내민다 | 끝까지 내렸을 때 |
| 메인 탭 넷(홈·둘러보기·준비물·설정) | **강아지 한 마리가 지나간 발자국**이 가장자리(왼쪽·오른쪽 끝, 아래쪽)에서 출발해 하나씩 찍힌다(글·카드 위도 지나간다) — 2~5초 뒤 첫 걸음, 0.6~1.8초에 한 걸음씩 3~6걸음, 1.5~4초 쉬고 다른 데서 또. 한 화면에 30개까지만 보이고(넘으면 오래된 것부터), 8~14초 뒤 꼬리부터 또는 누르면 천천히 흐려진다 | 시간 · 누름 |

비직관적인 것:

- **한 번 도는 모션은 상태 변화가 아니라 누른 순간에 건다**(`hooks/useReplay.ts` — 번호를 `key` 로 써서 다시 붙인다). 저장·체크 목록은
  마운트 뒤에 읽어 오므로(skipHydration) 탭바처럼 "바뀌었으면 움직인다" 로 짜면 저장 화면을 열 때마다 하트가 전부 튀고, 다 챙긴 목록으로
  돌아올 때마다 행진한다. 발바닥 행진도 같은 이유로 "다 찼다" 가 아니라 "이 누름이 마지막 하나다" 로 판단한다.
- **홈 스크롤은 JS 가 없다** — `animation-timeline: view()` 이고, 위 끝은 화면 0 이 아니라 접힌 히어로 아래선(14단 + 상태바)이다. 같은
  `transform` 을 두 애니메이션(들어오기·물러나기)이 나눠 쥐므로 채우기를 한쪽씩만 준다(`backwards` / `forwards`) — 둘 다 `both` 면 뒤의 것이 앞의 구간을 덮는다.
  섹션째가 아니라 줄마다 붙인다. 정도는 `--home-depth-scale`·`--home-depth-opacity` 두 값. 스와이프 미리보기는 자기 스크롤 상자가 있어(`overflow: hidden` + `scrollTop`)
  `view()` 가 그 상자 기준으로 같은 모습을 낸다. 지원하지 않는 브라우저(iOS 26 미만 Safari·Firefox)는 아무 일도 없다.
- 홈은 효과 없는 화면이다(ADR-014 — 미리보기도 같은 컴포넌트를 그린다). 이스터에그는 누름 처리기와 CSS 뿐, 마운트에 아무것도 하지 않는다.
- **발자국은 셸이 찍는다**(`components/layout/appShellPawPrints.tsx`, 걸음·시간표는 `lib/pawTrail.ts`). 화면이 타이머를 쥐면 홈이 효과 있는 화면이 된다.
  `<main>` 맨 앞의 높이 0 층에 px 로 찍어 본문과 같이 스크롤·스와이프된다(넘기는 동안 떠나는 화면의 발자국이 본문과 함께 끌려간다).
- **글·카드 위에는 찍어도 되고, 누르는 칸 위에는 안 찍는다**(v57). 발자국은 30% 옅은 브랜드색이라 글자 위에 얹혀도 읽힌다 — v54 까지는 빈 바탕
  (글자 없고 `<main>` 까지 아무 조상도 바탕을 칠하지 않은 곳)에만 찍어, 모바일에선 16px 여백밖에 설 곳이 없어 드물고 단조로웠다. 지금은 찍기 전에
  `elementFromPoint` 로 그 자리가 **이 화면 안**(탭바처럼 `<main>` 밖에 뜬 것이 아님)이고 **버튼·입력칸·아이콘·그림이 아닌지**만 본다 — 버튼에 얹히면
  눌림·상태 표시로 읽히고, 아이콘은 뭉개진다. 막히면 뒤로 돌지 않고 조금씩(18°·36°·60°·90°) 틀어 돌아간다 — 바로 꺾거나 돌던 때는 한두 걸음에 멈추거나
  제 발자국 위를 왕복해 한 자리에 뭉쳤다(실측). 출발점은 지금 보이는 가장자리라, 화면 밖으로 나가면 그 걸음은 끝이다.
- 층은 본문 위(`z-[1]`, 헤더 밑)지만 **손가락을 받지 않는다** — 아래쪽 버튼에 발이 걸쳐도 누름은 버튼에 간다. 발자국을 지우는 누름은 셸 표면이 받아,
  링크·버튼·라벨이 아닌 곳(바탕이나 글)을 눌렀고 가까이(22px) 발자국이 있을 때만 흐린다 — 카드 링크를 누른 것은 그 장소로 가려는 것이다. 흐려지는 1.8초(`PAW_FADE_MS` = CSS 전환)가 지나면 기억에서도 지운다 — `transitionend` 가 아니라
  타이머인 것은 모션을 줄인 사람·가려진 탭에서 끝 이벤트가 안 와 흐린 발자국이 남기 때문이다. 탭이 가려져 있으면(`visibilityState`) 찍지 않고,
  **떠나면 지운다**(v58) — 다른 화면(하위 화면 포함)에 다녀오면 발자국은 없다. 셸이 화면마다 `key` 로 층을 새로 붙이고, 층이 내려갈 때(정리 함수)
  `clearPawPrints` 로 그 화면 것을 지운다. v57 까지는 세션 동안 화면별로 남겨 돌아오면 그대로였다 — 그래서 엿보기에도 같은 층을 두었는데,
  지금은 엿볼 화면에 발자국이 있을 수 없어 뺐다. 기억을 화면별로 나눠 두는 것은 떠나는 층과 도착한 층이 잠깐 함께 있기 때문이다.
- **지나가는 강아지는 넷이다**(`PAW_KINDS` — 꼬마·보통·큰 개·길쭉이, 모양은 `appShellPawPrintShape`). 마리마다 하나를 뽑아 **끝까지 같은 발로** 걷는다 —
  발자국마다 바꾸면 한 마리가 지나간 길이 아니라 무늬로 읽힌다. 크기만 달리하면 30% 투명도에서 같은 개로 보여 실루엣(발가락 수·발톱 자국·길쭉함)도 다르고,
  보폭·발 사이도 발 크기를 따른다(꼬마 발로 큰 개 보폭을 걸으면 띄엄띄엄 찍혀 걷는 것으로 안 읽힌다). 크기는 `--spacing` 배수라 화면 축을 따라간다.
- **알아서 사라지는 것이 보여야 한다**(v60). 수명 25~60초·5~12걸음이던 때는 사라지기 전에 다음 마리가 와서 쌓이기만 했다 — 그래서 셋을 함께 건다.
  ① **한 마리 3~6걸음** — 출발할 때 길 전체를 정해 둔다(`planPawWalk`). 한 걸음씩 그 자리에서 정하던 때는 출발하자마자 막혀 한두 개로 끝나는 마리가
  많았다 — 3걸음을 못 걸을 자리뿐이면 아예 출발하지 않는다. 길은 층 기준 px 라 걷는 도중에 스크롤해도 본문과 함께 간다.
  ② **한 화면 30개까지**(`MAX_PAW_PRINTS`, v61) — 넘으면 종류를 가리지 않고 가장 오래된 것을 툭 없애지 않고 **흐린다**(v60 의 종류별 6개는 걷었다 —
  6은 한 마리의 걸음 상한 `MAX_PAW_WALK` 로만 남는다). 다음 마리까지 1.5~4초라 앞 마리가 덜 사라진 사이에 다음이 지나가는 것이 보통이다.
  수명이 먼저 지우므로 평소엔 30에 닿지 않는다 — 안전망이다.
  ③ **수명은 마리에 하나**(8~14초) — 발자국마다 뽑으면 길 중간이 먼저 빠져 구멍이 난다. 마리에 하나면 찍힌 순서대로, 걸어온 꼬리부터 흐려진다.
- 튀어나가는 조각은 기본이 투명이다. 모션을 줄인 사람에게는 애니메이션이 아예 안 붙어 조각이 제자리에 남지 않는다. `fixed` 는 쓰지 않는다(ADR-014).

### 둘러보기 조건은 모바일에서 접힌다

`/places/[type]` 의 조건은 다섯 묶음(읍면·방향·정렬(가까운 순 · 숙소는 가격 둘)·반려동물 조건·우리 강아지 기준)이라
고정 영역이 첫 화면의 절반을 먹고 목록이 두어 장만 보였다. 모바일에서는 그 다섯을
`PlacesPageFilterSheet`(바텀시트)로 접고 검색창 옆 `필터` 버튼 하나만 남긴다(사용자 문구는 "필터", 판정 레벨 "조건부" 와 헷갈리지 않게) — 고정 영역은 종류 탭 + 검색 두 줄.
데스크톱(≥768px)은 세로가 넉넉해 지금처럼 펼쳐 둔다.

- `PlacesPageFilters` / `PlacesPageEligibilityToggles` 가 `variant='bar' | 'sheet'` 로 같은 조건을 두 모양으로 그린다.
  모바일·데스크톱 판이 DOM 에 둘 다 있지만 숨은 쪽은 `hidden`(= `display:none`)이라 탭 순서·스크린리더에서도 빠진다.
- **"적용" 버튼을 두지 않고 누르는 즉시 반영한다.** 읍면은 이미 스토어(`town`)에 바로 쓰이고 종류를 바꾸면
  조건이 통째로 리셋되는 구조라(`key={type}`), 초안 상태를 하나 더 끼우면 그 둘이 어긋난다.
- 버튼의 숫자에는 검색어를 넣지 않는다 — 검색창은 시트 밖에 그대로 보이므로, 넣으면 시트를 열었을 때
  켜져 있는 조건 수와 어긋난다.
- **0곳이 읍면 탓이면 빈 상태가 그렇다고 말한다**(18 T2.1). 읍면은 퍼시스트라 전에 걸어 둔 '구좌읍' 이 홈 관광지 칩("중문", 검색어)과
  겹쳐 0곳이 된다 — 홈은 퍼시스트 필터를 몰래 풀지 않으므로, 읍면 **하나만** 풀어 센 수(`townReleaseCount`)가 0 보다 크면
  "구좌읍에는 맞는 숙소가 없어요 · 읍면을 풀면 N곳" 과 그 자리에서 푸는 버튼을 그린다. 다른 조건은 그대로 두고 센다 — 버튼이 하는 일과 같아야 N곳을 누르고 N곳을 본다.
- **권역(6, 19 T3)은 읍면이 아니라 검색어 쪽에 산다** — `usePlacesPageFilterStore.area`, 퍼시스트 아님. 홈 동네 카드는 `usePlacesPageAreaEntry`(`screens/placesPageAreaEntry.ts`)
  하나로 권역·**'갈 수 있는 곳만'**(`onlyReachable`)·숙소 탭을 함께 건다 — 따로 걸면 카드의 "묵을 곳 n" 과 열린 목록의 수가 갈린다. 처음엔 '어려운 곳 숨기기' 를 걸었는데
  그건 `hard` 만 빼서 확인·정보 없음이 남았다(보리 · 서남 "묵을 곳 1" → 2곳, 19 T4.1). 카드 셈(`ok + outdoor`)과 목록 거르기가 같은 술어 `isReachable`(`lib/eligibilityCounts.ts`)를 쓴다.
  이 조건도 권역처럼 시트에 자리가 없어 칩으로만 풀고, 관광지 칩 진입이 함께 푼다. 홈의 두 진입(관광지 칩 = 검색어, 카드 = 권역)은
  서로를 지운다(`enterLandmark`·`enterArea`) — 겹치면 '서부' 안에서 '중문' 을 찾는 꼴로 이유 없이 0곳이다. 권역은 시트에 고르는 자리가 없어 칩 줄 맨 앞에만 보이고
  시트 버튼 숫자에 안 든다(검색어와 같다). 0곳이면 빈 상태가 읍면 → '갈 수 있는 곳만' → **권역** → 검색어 순으로 원인을 본다(`reachableReleaseCount`·`areaReleaseCount`) —
  "묵을 곳 0" 카드도 눌리므로, 권역을 풀어 방금 고른 동네를 잃게 하기 전에 그 동네의 확인·정보 없음 곳을 먼저 보여 준다; "다른 종류에 N곳" 도 권역 안에서 센다.

### 긴 목록 select 는 모바일에서 하단 시트로 (`SheetSelect`)

Untitled UI 의 `Select` 는 트리거 폭에 맞춘 앵커 팝오버(최대 224px)라, 읍면(20여 곳)·숙소(26곳)처럼
긴 목록을 넣으면 폰에서 `w-40` 폭 안에 다섯 줄씩 보이는 좁은 드롭다운이 된다. 그래서
`src/components/sheetSelect.tsx` 가 **<768px 에서는 `BottomSheet` 피커, 그 이상은 보통 `Select`** 로 가른다.
지금은 지도 읍면(`mapPage.tsx`) 한 곳만 쓴다 — 준비물의 숙소 선택은 없앴다(ADR-009).

- **항목이 서너 개면 그냥 `Select` 를 쓴다** — 정렬(숙소 4 · 식당·카페 2)·강아지 크기(3)는 그대로다. 정렬은 이미
  `PlacesPageFilterSheet` 안에 있어서 시트 위에 시트가 되기도 한다.
- 폭 기준(md)인 이유: 시트는 `document.body` 로 포털되어 CSS(`md:hidden`)로 못 숨기므로 JS 로 갈라야 하고,
  둘러보기 조건 시트와 같은 지점에서 갈라 화면마다 규칙이 다르지 않게 했다. `src/hooks/useMediaQuery.ts`
  (기존 `useMapPageWideLayout` 을 일반화)가 `useSyncExternalStore` 로 읽는다 — 정적 HTML 의 첫 프레임은
  서버 스냅샷 `false`(= 드롭다운 쪽)로 그려지지만 트리거 모양이 같아 티가 안 난다.
- 시트는 `selectionMode='single'` 인데 react-aria 는 이 모드에서 항목을 눌러도 `onAction` 을 안 부르고,
  이미 고른 항목을 다시 누르면 선택을 **비운다**. 그래서 `onSelectionChange` 하나로 받되 빈 선택은
  "값 유지 + 닫기" 로 다룬다 — 어느 행을 눌러도 시트가 닫힌다.
- `BottomSheet` 는 위쪽 핸들 띠(28px, `touch-action: none`)를 **터치로** 끌어내리면 닫힌다(96px 이상 또는
  빠른 튕김). 시트 전체를 잡게 하지 않는 이유: `touch-action` 은 조상이 막으면 자식이 되살릴 수 없어
  안쪽 목록 스크롤과 양립이 안 된다. 끌리는 이동은 `AriaDialog` 에 걸어 `AriaModal` 의 닫힘 keyframe 과
  안 싸우고, 그 상태는 닫히면 언마운트되는 패널 컴포넌트에 둬 되돌리는 effect 가 없다. 마우스는 제외.
- 시트 바닥 여백은 `pb-sheet`(globals.css) 하나로 준다 — `p-4 pb-safe` 처럼 겹쳐 쓰면 둘 다
  `padding-bottom` 이라 한쪽이 다른 쪽을 **덮어쓴다**(더해지지 않는다). 인셋이 없는 기기에서는
  바닥 여백이 통째로 0 이 되고, 있는 기기에서는 홈 인디케이터에 마지막 줄이 깔린다.
  인셋만 필요한 탭바는 `pb-safe` 를 그대로 쓴다.
- `base/select-item.tsx` 의 `sm` 행에 `min-h-11` 을 넣었다(Untitled 복사본이지만 `select-shared.tsx` 의
  트리거 44px 조정과 같은 선례). 트리거만 44px 이고 드롭다운 행은 38px 이던 불일치를 맞춘 것.

### 잠깐 뜨는 상태 한 줄 — 셸이 `<main>` 밖에 그린다 (`AppStatusToast`)

"링크를 복사했어요" 같은 알림은 화면이 아니라 셸이 그린다. 두 가지 이유가 있다.

- **자리**: 스와이프 중 `<main>` 에 transform 이 걸리면 그 안의 `fixed` 는 화면이 아니라 `<main>` 을
  기준으로 삼는다(ADR-014). 알림이 끌리는 화면과 함께 밀려나지 않게 탭바와 같은 층(셸 루트)에 둔다.
- **수명**: 띄우자마자 화면이 바뀌는 경우(저장 뒤 돌아가기)에도 살아남아야 한다. 그래서 값은 React 밖
  모듈 변수(`lib/appStatus.ts` 의 `showAppStatus`)에 있고 셸이 `useSyncExternalStore` 로 읽는다.

한 번에 하나만 보이고 새 것이 이전 것을 갈아 끼운다(줄 세우면 지나간 동작의 알림이 늦게 뜬다).

**누를 것이 있는 알림은 사라지기 전에 누를 수 있어야 한다**(12 U3.5). 링크·되돌리기 버튼이 있으면 호출한 쪽이 짧게 줘도
최소 5초(`STATUS_INTERACTIVE_MIN_MS`)를 두고, 마우스가 올라가 있거나 포커스가 안에 있는 동안은 타이머를 멈춘다(`holdAppStatus`/`releaseAppStatus`,
떼면 남은 시간 — 최소 2초 — 부터 이어 간다). 터치는 `mouseleave` 가 안 와 멈춘 채 남을 수 있어 hold 에서 뺐다(포커스만).

쓰는 곳: 상세 공유의 링크 복사 · 저장(`SaveButton`). 저장 알림은 **세션에서 처음 두 번만** 뜬다
(`createFirstTimesGate` — 퍼시스트하지 않는다). `/saved` 는 탭바에 없어 처음엔 길을 알려 줘야 하지만,
하트를 연달아 누르는 사람에게 매번 뜨면 소음이다. 해제는 알리지 않는다 — 하트가 비는 것으로 충분하다.
`role="status"` 상자는 비어 있어도 늘 DOM 에 둔다 — 라이브 영역은 먼저 있어야 바뀐 글을 읽어 준다.

**하이드레이션**: 상세의 공유 버튼은 예전에 `'share' in navigator` 일 때만 그려서 카톡 인앱·데스크톱에선
아예 없었다. 지금은 **늘 그리고**, 공유(Web Share)냐 링크 복사냐는 누른 순간에만 가른다
(`lib/placeShare.ts` 의 `shareMethodOf`) — 버튼의 존재가 서버·클라에서 같아 미리 그린 HTML 과 어긋날 일이 없다.

### react-aria 링크와 Next 라우터

Untitled UI 의 `Button href` / `Link` 는 react-aria 라 기본은 전체 새로고침이다.

- **하이드레이션**: HTML 이 빌드 때 만들어지므로 첫 렌더에서 localStorage 를 읽으면 서버 HTML 과 어긋난다.
  `skipHydration: true` 로 두고 `src/providers/storeHydration.tsx` 가 마운트 뒤 `rehydrate()` 한다. 첫 프레임의 "저장한 곳 0" 은 의도.
- **"읽기가 끝났나" 는 `useStoreHydrated()` 로 묻는다. `persist.hasHydrated()` 를 쓰지 않는다** —
  그쪽은 "성공했나" 라서 저장된 값이 깨져 있으면 **영원히 false** 다. 그것을 "아직 읽는 중" 으로
  읽은 화면은 로딩 문구에 갇힌다(→ [BUG-002](../bugs/BUG-002-hydration-deadlock.md)).
  스토어가 성공·실패를 가리지 않는 신호(`hydrationSettled`)를 따로 올리고, 실패한 값은
  `onRehydrateStorage` 에서 지운다 — 남겨 두면 다음 로드에서도 같은 자리에서 또 실패한다.
  이 훅이 필요한 곳은 **없는 것을 근거로 말을 거는 화면**뿐이다(등록 폼·"아직 안 챙겼어요").
  "0 에서 실제 값으로 채워지는" 것은 첫 프레임이 틀려도 해가 없어 그냥 그리면 된다.
- **정합성**: 데이터에 더 이상 없는 저장 id 는 **저장소에서 지우지 않고 보여 줄 때 거른다**(`useSavedPlaces` → `selectSavedPlaces`, 개수 `useSavedCount` 도 같은 길). 장소가 빠지는 길은 운영자의 내리기(`archived`)이고 되살리기가 있다 — `merge` 에서 거르면 걸러진 목록이 다음 아무 쓰기에 localStorage 를 덮어써, 되살려도 하트와 메모가 돌아오지 않는다. 빠진 수는 저장 화면에 한 줄(`useUnlistedSavedCount`)로만 말한다(12 U2.3). `town` 도 같은 이유로 `ALL_TOWNS`(`lib/places.ts`)에 없는 값이면 `null` 로 되돌린다.
- **둘러보기 조건은 저장하지 않는 별도 스토어에 산다**(`src/store/usePlacesPageFilterStore.ts`, `persist` 없음): 검색어·방향·'어려운 곳 숨기기'·**종류별** 반려동물 조건(`petKeysByType` — 숙소에만 환경 조건이 있어 종류마다 키 집합이 다르다). `useAppStore` 는 통째로 localStorage 에 쓰므로 여기 두면 지난 방문의 검색어가 다음 첫 화면을 걸러 버린다. 모듈 메모리라 탭 전환·스와이프·상세에서 뒤로·재진입에는 남고 새로고침에는 사라진다. **정렬·기준점은 싣지 않는다** — 가격순은 숙소에서만, 가까운 순은 위치를 한 번 받아야 의미가 있어서 따라오면 다른 탭에 아무 일도 안 하는 칩이 생긴다(둘 다 `placesPage` 의 로컬 state, `key={type}` 로 종류마다 리셋). 읍면·'실내 자리 필요' 는 전부터 `useAppStore` 값이라 그대로다. 목록·칩 계산은 `lib/placesPageFilter.ts` 한 곳이고 스와이프 엿보기가 같은 함수를 부른다(→ [ADR-013 v4](../decisions/ADR-013-places-swipe-pager.md)). "모두 지우기" 는 다른 종류의 조건까지 푼다 — 안 보이는 탭에 조건이 남지 않게.
- v1 의 강아지 프로필도 이 스토어에 필드로 들어간다(→ [features/dog-profile.md](../features/dog-profile.md)). 서버가 없으니 다른 선택지가 없다.

## 순수 로직은 `src/lib/`

화면 컴포넌트는 표시만 하고, 판단은 `lib/` 의 순수 함수가 한다(파서·필터·체크리스트 진행률·구비 용품 매핑·거리 계산).
테스트가 필요한 것은 전부 여기 있고 vitest 는 Next 를 거치지 않는다(`vitest.config.mts` 가 `@/` 경로를 따로 읽는다).

## 안티패턴

- `screens/` 에서 `localStorage` 를 직접 읽지 않는다. 스토어 밖 읽기는 하이드레이션 불일치를 만든다.
- 종류 색을 화면에서 하드코딩하지 않는다. `TYPE_COLOR` / `typeTint` / `theme.css` 토큰만 쓴다.
- `components/base/` 를 고치지 않는다. Untitled UI 갱신 시 덮어써진다. 변형이 필요하면 감싸는 컴포넌트를 만든다.
- 새 파일은 소유 화면 접두어를 붙인다(`placeDetailNearby.tsx`, `useMapPageWideLayout.ts`). 두 화면 이상이 공유할 때만 접두어 없이 `components/` 로 올린다.
