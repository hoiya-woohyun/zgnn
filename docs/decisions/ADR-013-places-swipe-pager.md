# ADR-013 — 둘러보기 종류 전환은 손가락으로 넘긴다 (캐러셀이 아니라 엿보기)

> 최종 수정: 2026-09-17 (v2: 가로로 잠기면 세로 스크롤을 잠근다 — iOS 에서 둘이 같이 움직이던 것)
> 이전 (v1: 신설)

## 상태

채택.

## 맥락

숙소·식당·카페는 한 화면 안의 탭 전환이다([ADR-007](ADR-007-shell-owned-back-navigation.md) — 셋 다
루트). 탭을 누르면 알약이 옮겨 가고 목록이 그쪽에서 들어오게 해 두었지만
([app-shell-and-state](../architecture/app-shell-and-state.md) "종류 전환은 방향을 가진다"),
손가락으로 목록을 옆으로 밀면 아무 일도 없었다. 네이티브 앱에서 나란한 탭은 좌우 스와이프로
넘어가는 것이 기본이고, 사용자가 그 느낌 — **손가락 위치를 그대로 따라오는 것** — 을 원했다.

세 종류는 각각 다른 주소(`/places/[type]`)이고, 종류를 바꾸면 조건을 리셋하려고 화면을 통째로
리마운트한다(`key={type}`). 스크롤은 document 하나이고, 종류 탭·검색 줄은 `sticky` 다.

## 결정

**세 목록을 한 줄에 늘어놓고 미는 캐러셀은 만들지 않는다.** 대신 손가락이 가로로 잠기면:

1. 지금 목록과 탭의 알약을 손가락 비율대로 끈다.
2. 이웃 종류의 본문을 옆에 **엿보기**(`PlacesPageSwipePeek`)로 띄운다 — 절대 위치, `inert`,
   높이는 지금 보이는 영역만큼. 새 화면이 마운트됐을 때와 같은 모습(맨 위·기본 조건)이다.
3. 놓으면 남은 거리를 WAAPI 로 밀어내고 **그 다음에** `router.push`. 새 화면은 스크롤 0 에서
   뜨므로 엿보기와 픽셀이 이어진다. 그 새 화면이 또 한 번 미끄러지지 않도록 도착점을
   `placesPageTypeSwitch` 에 미리 적는다(`arriveBySwipe`).

코드: `screens/placesPageSwipe.ts`(제스처) · `screens/placesPageSwipePeek.tsx`(엿보기) ·
`screens/placesPageResults.tsx`(본문 — 지금 화면과 엿보기가 같은 것을 그리려고 떼어 냄) ·
`lib/swipePager.ts`(DOM 없는 산수, 테스트 있음).

### 왜 캐러셀이 아닌가

세 패널이 한 스크롤 컨테이너 안에 공존하려면 패널마다 스크롤 컨테이너를 따로 두어야 하고,
그러면 `sticky` 헤더와 셸의 `scrollTo(0, 0)`, `key={type}` 리셋이 전부 깨진다. 엿보기는 그 셋을
하나도 건드리지 않고 "옆에 뭐가 있는지" 만 보여준다 — 손가락이 잠긴 동안만 존재하고
문서 높이에도 스크롤에도 관여하지 않는다.

### 손가락 계산에서 정해 둔 것

- **축 고정.** 10px 을 넘기기 전엔 방향을 정하지 않고, 세로가 더 크면 그 제스처는 포기한다.
  방향을 정하는 데 쓴 거리는 버리고 거기서부터 0 으로 센다 — 잠기는 순간 10px 튀지 않게.
- **`touch-action: pan-y pinch-zoom`** 을 무대에. 세로는 브라우저가 스크롤로 가져가고(그때
  `pointercancel`), 가로만 우리에게 온다. `none` 이면 세로 스크롤이 죽고, 안 걸면 브라우저가
  가로도 가져간다. `pan-y` 만 적으면 핀치 줌이 같이 꺼져서 `pinch-zoom` 을 되살린다.
- **가로로 잠기면 세로 스크롤을 잠근다.** `pan-y` 는 세로를 브라우저에 맡긴다는 뜻이라 iOS
  Safari 는 가로로 끄는 도중 손가락이 위아래로 흐르면 스크롤을 시작한다 — 목록이 옆으로도
  위로도 같이 움직여 어지럽다(실기 피드백). 잠긴 동안 `touchmove` 의 기본 동작을 막는다.
  React 의 `onTouchMove` 는 passive 라 `preventDefault` 가 무시되므로 네이티브 리스너를
  `{ passive: false }` 로 단다. 잠기기 전(방향 미정)에는 막지 않는다 — 세로 스크롤을 죽이면 안 된다.
- **좌표는 ref 로 DOM 에 직접.** 바텀시트는 state 로 두지만 그건 시트 하나라서고, 여기서
  pointermove 마다 state 를 바꾸면 카드 수십 장이 매 프레임 리렌더된다.
- **넘어가는 기준은 폭의 30% 또는 0.3px/ms 플릭**(`lib/swipePager.ts` 의 상수 셋). 네이티브
  페이저(iOS 50%·Android 40%)보다 낮다 — 첫 실기에서 "끝까지 끌어야 넘어간다" 고 느껴졌다.
  같은 느낌의 더 큰 원인은 **속도 측정**이었다: 마지막 두 move 만 보면 손가락이 떨어지기 직전
  잠깐 멈칫한 것이 0 으로 읽혀 플릭이 죽는다. 최근 100ms 구간의 첫·끝 샘플로 재고, 뗄 때도
  그 구간 밖의 샘플은 버린다(멈춘 채 떼면 move 가 안 와 옛 샘플이 남는다). 끌던 방향과 반대로
  튕기며 놓으면 멀리 갔어도 제자리 — 마음을 바꾼 것이다.
- **끝에서는 저항.** 이웃이 없는 방향은 손가락의 30% 만 따라간다 — 딱 멈추면 고장처럼 보이고
  그대로 따라가면 빈 자리가 드러난다. 알약은 테두리 안에서 잘라 둔다.
- **터치만.** 마우스로 목록을 끄는 동작은 데스크톱에서 어색하고, 거기선 탭이 있다.
- **iOS 왼쪽 가장자리 24px 은 건드리지 않는다.** Safari 의 뒤로가기 제스처 자리다. 홈 화면에
  설치한 PWA 에는 그 제스처가 없어 거기서는 그 띠에서도 그냥 안 넘어갈 뿐이다.
- **`pointercancel` 은 제자리.** 브라우저가 가져갔다는 뜻이지 놓았다는 뜻이 아니다.
- **스와이프였으면 뒤따르는 click 을 삼킨다.** 카드가 전부 링크라, 끌다 놓은 자리의 카드가
  열리면 안 된다.
- **주소는 `push`.** 탭 클릭(`<Link>`)과 같아야 한다 — 뒤로가기의 의미가 둘 사이에서 갈리면
  그게 버그다.
- **모션 줄임.** 손가락을 따라가는 것은 직접 조작이라 유지하고, 놓은 뒤 밀어내는 것만 즉시.
  WAAPI 라 전역 CSS 리셋이 닿지 않아 `matchMedia` 로 직접 본다.

## 결과

- 느낌을 바꾸려면 `swipePager.ts` 의 상수 셋(`COMMIT_DISTANCE_RATIO`·`COMMIT_VELOCITY`·
  `EDGE_RESISTANCE`)과 `placesPageSwipe.ts` 의 `VELOCITY_WINDOW_MS` 만 만진다. 테스트는 상수를
  상대적으로 참조해 값을 바꿔도 깨지지 않는다.
- 엿보기는 `PlacesPageResults` 를 기본 조건으로 그린다. **본문 모양을 바꾸면 그 컴포넌트를
  고쳐야** 지금 화면과 엿보기가 같이 바뀐다 — `placesPage` 에 직접 그리면 놓는 순간 모양이 튄다.
- 들어오는 목록의 애니메이션(`animate-in`)과 손가락이 끄는 transform 은 다른 요소에 건다.
  CSS 애니메이션이 인라인 transform 을 덮어써서 같은 요소면 마운트 직후 300ms 동안 손가락을
  안 따라온다.
- `overflow-x-clip` 은 움직이는 것들의 **부모**(무대)에 있다. 요소는 자기 transform 을 자기
  overflow 로 못 자른다.
