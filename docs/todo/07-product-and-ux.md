## 왜 이 문서가 따로 있나

0~6 은 데이터가 DB 에서 사이트까지 가는 길이고 거의 끝났다(남은 사람 손은 4b 와 마이그레이션). 그 사이 사용자 화면은 9/16 이후 크게 바뀌지 않았다.
점검 결과 한 문장: **판정이 가장 자주 내놓는 답이 "확인이 필요해요" 인데, 앱은 그다음 행동을 주지 않는다**(대형견 2마리 기준 카페 23/26, 이동가방 소형견 기준 식당 31/34).
장소를 200곳으로 늘려도 이 비율은 그대로이므로, 아래 **P0 가 파이프라인의 다음 실행보다 먼저**다.

## 순서

```
P0  ★ 전화번호(운영자 입력) · ★ 카테고리 제보 · 사용자 5명 테스트   ← "확인 필요" 에 출구를 낸다. ★ = 사용자가 고른 것(2026-09-29)
P1  공유(OG·저장 목록 링크) · 홈 첫 화면 · 탭 간 필터 유지 · 데이터 신선도
P2  문구·배지 정밀화 · 지도 필터 · 커버리지 채우기 · 설치 안내
P3  여행 단위(날짜·동선) · 데스크톱 2열
```

## P0 — 지금

- [ ] **사용자 5명에게 써 보게 한다** (코드 없음, 반나절). 소형견·중형견·대형견 보호자 섞어서, 과제 셋:
      ① "이번 주말 애월에서 우리 강아지랑 점심 먹을 곳 찾기" ② "숙소 하나 골라 저장하고 준비물 보기" ③ "친구에게 이 숙소 보내기".
      관찰할 것: 프로필을 **스스로** 등록하는가 · "확인이 필요해요" 를 보고 무엇을 하는가(네이버로 나가는가, 포기하는가) · ③ 에서 막히는가.
      결과는 `docs/reviews/` 에 남기고 **이 문서의 P1 이하 순서를 다시 매긴다** — 아래 우선순위는 그 전까지의 추정이다.
- [ ] **"확인이 필요해요" 옆에 전화 버튼** (리뷰 U1, 9/15 P1 미반영분)
  - [ ] 데이터: `places.phone` 칼럼(마이그레이션) + `data:pull` 이 JSON 으로 옮기게. **출처는 운영자 입력으로 정했다**(2026-09-29 사용자).
        기존 86곳은 `naverPlaceId` 가 전부 있어 네이버 장소 페이지에서 옮겨 적으면 된다.
  - [ ] 입력 자리: `/admin` 「올린 장소」 줄에 전화번호 칸(편집 → `places.phone` update). 저장하면 재빌드 방아쇠는 기존 4b 경로 그대로.
        번호 형식은 저장 때 한 번 정규화(`064-xxx-xxxx`·`010-…`·`0507-…` 안심번호) — 순수 함수 + 테스트.
  - [ ] 네이버 지역 검색 응답의 `telephone` 은 **보조**로만 — 빈 값이 많다는 말이 있고, 채워져 있으면 운영자 칸의 미리 채움 정도로 쓴다(실측 전).
  - [ ] 화면: 상세의 판정 카드 바로 아래에 `tel:` 버튼 + "네이버에서 예약·문의" — 판정이 `cond`·`unknown` 일 때 주 버튼으로. 준비물 넛지는 그 아래로 내린다.
  - [ ] 전화가 없는 곳은 지금의 "네이버 지도에서 열기" 문구를 "네이버에서 전화번호 보기" 로 — 버튼이 무엇을 해결하는지 말하게.
  - 문서: `features/` 에 상세 화면 문서가 없다 → 이 작업이 `features/place-detail.md` 를 만들 계기다.
- [ ] **틀린 정보 제보 — 카테고리로 받는다**(2026-09-29 사용자). 상세 맨 아래 "정보가 달라요" 한 줄 → 하나를 고르고 필요하면 한 줄 적는다.
      이게 없으면 폐업·조건 변경을 운영자가 블로그 수집으로만 알게 된다.

      | 카테고리 | 사용자에게 보이는 말 | 운영자가 할 일 |
      |---|---|---|
      | `closed` | 없어졌어요(폐업·휴업) | 확인 뒤 `/admin` 에서 **내리기**(소프트 삭제, ADR-018 결정 6) |
      | `replaced` | 다른 곳으로 바뀌었어요 | 내리고, 새 가게가 반려견 동반이면 후보로 새로 올린다 |
      | `address` | 주소·위치가 달라요 | 주소·좌표 수정(좌표는 03 의 Geocoding 축으로 다시 붙일 수 있다) |
      | `other` | 기타 | 적힌 내용대로 |

      - 보낼 때 **장소 id·이름을 자동으로 싣는다** — 사용자가 어느 곳인지 다시 적게 하지 않는다.
      - 연락처는 받지 않는다(회원·개인정보는 범위 밖 — ADR-015 §3, ADR-012). 답장이 필요 없는 구조로.
      - 제안(사용자 확인 전): 전화번호·반려동물 조건이 달라요 두 칸을 더할지 — 전화번호 칸은 위 운영자 입력의 틀린 번호를 잡는 데 바로 쓰인다.
  - [x] 🙋 **어디로 받을지** — (c) Supabase insert-only 로 닫았다(2026-10-01, 10 🙋 1 권장안). — 아래 표 첫 줄. **[10 R1](10-user-feedback-personas.md) 이 (c) 를 권장**(폐업 제보가 09 의 영구 제외와 한 동작이 되려면). 명세·태스크는 10 의 F1·T1.x.
  - [x] 문서: 받는 경로가 정해지면 `features/place-report.md`, (c) 면 ADR 도. → (c) 로 닫혔다: [features/place-report.md](../features/place-report.md) · [ADR-021](../decisions/ADR-021-place-reports.md)

## P1 — 다음

- [ ] **저장 목록 공유 링크** — `/saved?ids=…` 같은 정적 주소로 "같이 가는 사람에게 보내기". 받는 쪽은 읽기 전용 보기 + "내 저장에 담기". 서버 없이 된다.
- [ ] **홈 첫 화면 재배치** (U2) — 인사말은 첫 방문에만 펼치고 이후 접기(또는 설정·하단으로). 프로필이 있으면 히어로 아래에
      "보리와 콩이 갈 수 있는 곳 숙소 7 · 식당 6 · 카페 26" 한 줄, 없으면 등록 CTA 를 브랜드 면으로 올린다.
- [ ] **탭을 넘겨도 필터가 남게** (U3) — 검색어·방향·조건·"어려운 곳 숨기기" 를 `town` 처럼 스토어(비퍼시스트)로 올린다. 넘길 때 결과 0 이면 "카페에는 '애월' 이 없어요" 빈 상태.
      둘러보기 스와이프(ADR-013)와 스크롤 복원(ADR-014)이 탭마다 상태를 들고 있으니 **함께 본다**.
- [x] **데이터 신선도 표시** — 장소별 `verified_at`(시드는 Notion 작성 시점, 이후는 `/admin` 승인 시각) 을 상세에 "2026년 9월 확인". 1년 넘으면 톤을 낮춘다. → [10](10-user-feedback-personas.md) T2.1·T2.3 으로 닫았다(시드는 null — Notion 에 작성 시점이 없다, 지어낸 날짜를 넣지 않는다)
      `data-pipeline.md`·`01` 스키마와 같이 간다.
- [ ] **가벼운 측정** 🙋 — 없으면 5명 테스트 뒤에 무엇이 나아졌는지 모른다. 페이지뷰·"네이버로 나감"·"전화 누름"·"프로필 저장" 네 개면 충분하다.

## P2 — 정밀화

- [ ] 읍면 표기 통일 (U8) — `서귀포` → `서귀포시`. `normalize`/`pull-db` 쪽에서, 그리고 AI 추출 결과에도 같은 정규화가 걸리는지 확인.
- [ ] **커버리지 채우기** — 수집 키워드를 빈 칸 기준으로: 제주시(공항 근처) · 서귀포 카페 · 북쪽 숙소. 지금 `keywords.json` 6개는 지역을 가리지 않는다.
      `/admin` 검수 화면에 "이 후보가 채우는 빈 칸" 표시는 선택.
- [ ] 숙소 "정보 없음" 5곳 조건 채우기 — 어떤 강아지에게나 같은 다섯 줄이라 데이터 한 번이 가장 싸다.
