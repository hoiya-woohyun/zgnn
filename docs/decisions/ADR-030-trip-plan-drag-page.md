# ADR-030 — 날짜·순서는 저장 카드가 아니라 「날짜별로 정리」 한 화면에서 끌어 놓아 정한다

> 최종 수정: 2026-10-20 (v1: 신설 — 사용자 요청 "저장한 곳에서 날짜별로 정렬하는 것은 드래그 앤 드랍으로, '날짜별로 정리하기' 같은 문구로 섹션이나 페이지를 만들어 거기서".
> 16 T1.4 의 임시안(카드마다 날짜 select + ↑↓)을 대신한다)
> 상태: **구현**(2026-10-20). iOS 실기기(홈 화면 PWA)의 터치 끌기·자동 스크롤은 확인 전 — 헤드리스 Chromium(CDP 터치, 320·390)과 데스크톱 Chrome 만 쟀다.

## 맥락

16 T1.4 는 화면을 디자인 트랙 전의 **임시안**으로 붙였다 — 저장 카드마다 날짜 select(미정·1~4일차)와, 날짜별 보기에서만 ↑↓ 버튼.
쓰는 사람에게 셋이 불편했다.

- **날을 바꾸면 그 카드가 사라진다.** 날짜별 보기에서 2일차 카드의 select 를 4일차로 바꾸면 카드가 화면 아래 다른 묶음으로 옮겨 가, 무엇이 어디 갔는지 따라가야 했다.
- **순서는 한 칸씩만.** 다섯째를 맨 앞으로 보내려면 ↑ 를 네 번.
- **정리와 읽기가 한 화면에 섞였다.** 카드는 판정 배지·메모·길찾기를 이미 싣고 있어 select·번호·화살표 줄이 한 줄 더 붙었다.

## 결정

1. **정리는 하위 화면 하나 — `/saved/plan` 「날짜별로 정리」.** 저장 화면에는 입구 버튼만 둔다('날짜별로 정리하기', 정한 뒤엔 '날짜·순서 바꾸기').
   아직 아무 날도 안 정했으면 종류별·날짜별 두 보기 모두에, 정한 뒤엔 날짜별에만 — 처음 오는 사람은 종류별로 들어온다.
   저장 화면 「날짜별」 은 **읽는 자리**로 남는다(판정·출발·길찾기, '내 위치에서'). 카드의 select·↑↓·'순서 다시 제안' 은 뺐다.
   같은 화면 안의 '편집 모드' 가 아니라 화면을 따로 둔 이유: 카드 그대로(한 장 ~150px)면 열 곳만 돼도 1일차에서 4일차까지 화면 서너 장을 끌고 내려가야 한다.
   정리 화면의 줄은 이름·읍면·종류만 남긴 ~64px 이다.
2. **칸은 늘 다섯(1~4일차 + 날짜 미정), 빈 칸도 그린다** — 놓을 자리가 보여야 끌 수 있다. 칸 자체도 놓는 곳이다.
3. **끄는 것은 줄 오른쪽 손잡이뿐**, 누르자마자 끌린다(`touch-action: none`, 길게 누르기 없음). 줄 전체를 끌게 하면 목록을 스크롤하려던 손가락이 줄을 집는다.
   왼쪽은 셸의 뒤로 끌기 띠(본문 왼쪽 0~48px, ADR-025)라 손잡이를 두지 않는다.
4. **놓은 자리가 그 날의 순서다**(`withTripDrop`) — 제안(가까운 순)이던 날도 끌어 놓는 순간 손 순서가 된다. '가까운 순으로' 가 제안으로 되돌린다(16 P2 의 "순서 다시 제안").
   제자리에 놓으면 아무것도 쓰지 않는다 — 집었다 놓기만 해도 제안이 손 순서로 굳으면 안 된다.
5. **끌지 않는 길이 있다**(WCAG 2.5.7). 줄의 이름 쪽을 누르면 시트에서 날을 고르고, 그 날 안에서 '앞으로·뒤로' 한 칸씩. 시트에서 **날만 고르면 자리는 정하지 않은 것**이라
   기존 `setTripDay` 대로 — 제안인 날은 제안이, 손 순서인 날은 그 끝이 자리다. 키보드는 dnd-kit 의 키보드 끌기(Space·화살표·Space, Esc 취소)와 한국어 안내.
6. **끄는 동안은 화면 초안만, 스토어는 놓을 때 한 번**(`dropTripPlace`). 제안 순서는 시작점(앞 날의 마지막 숙소)에 묶여 있어, 끄는 중에 스토어를 바꾸면
   숙소 하나를 1일차로 끌어 지나가는 것만으로 2일차가 손가락 밑에서 다시 정렬된다. 날과 순서를 따로 두 번 쓰지 않는 것도 같은 이유다(사이 렌더에서 카드가 제안 자리로 튀었다 돌아온다).
7. **라이브러리는 dnd-kit**(`@dnd-kit/core` 6.3.1 · `sortable` 10 · `utilities` 3.2.2, 정확한 버전 고정). 이미 있는 react-aria 의 끌어 놓기를 먼저 봤는데,
   포인터·터치를 **브라우저 기본 끌기**(`draggable`, HTML5 DnD)로 처리해 iOS 에서는 길게 눌러야 시작하고 끄는 중 자동 스크롤·미리보기를 우리가 쥘 수 없다 —
   사용자가 불편하다고 한 바로 그 마찰이고, CDP 터치로 잴 수도 없다. dnd-kit 은 포인터 이벤트라 손잡이를 누르자마자 끌리고 여러 칸 이동·자동 스크롤·키보드 끌기를 함께 준다.
   이 화면 청크에만 들어간다(라우트 단위 분할).

## 결과

- 저장 카드는 다시 "읽고 길찾는 카드" 다 — 날짜 줄이 빠져 카드 높이가 한 줄 준다.
- 하위 화면 밑의 하위 화면이 처음 생겼다. `/saved/plan` 의 정해 둔 부모는 `/saved` 이고(딥링크 뒤로가기), 탭 불은 부모를 거슬러 **탭이 나올 때까지** 올라간다(`ownerRootOf` → 설정).
- **조용히 깨지는 것 하나**: dnd-kit `SortableContext` 의 `items` 에 렌더마다 새 배열을 넘기면, 칸을 넘는 순간 측정 효과 → setState → 새 배열 → 측정이 끝없이 돌아
  "Maximum update depth exceeded" 로 화면이 오류 경계로 떨어진다(같은 칸 안에서만 끌면 안 나서 첫 시험에선 지나간다). 판의 배열 참조를 그대로 넘긴다 — `savedPlanPageColumn.tsx` 의 `ids`.
- 끄는 그림(`DragOverlay`, fixed)은 body 로 포털한다 — `<main>` 에 transform 이 걸리면 fixed 의 기준이 `<main>` 이 된다(ADR-014).
- 시트에서 다른 날을 고르면 그 줄이 다른 칸 목록으로 다시 마운트돼, react-aria 가 돌려보낼 노드(누른 줄)가 문서에서 빠지고 포커스가 body 로 떨어진다.
  지도 시트와 같은 판단(`lib/sheetFocusReturn` — 지도 전용이던 것을 둘이 쓰게 되어 이름에서 `mapPage` 를 뗐다)으로 닫힌 뒤 그 줄(`data-plan-row`)에 둔다.
- 새 화면은 오프라인 프리캐시 목록(`next.config.mjs` 의 손으로 적는 `routes`)에도 한 줄 — 빠뜨려도 빌드는 초록이라 `lib/precacheRoutes.test.ts` 가 `src/app` 과 대 본다.
- 하지 않은 것: 저장 화면 안에서 바로 끌기 · 날 수(4일)를 늘리기 · 정리 화면 안 지도·판정 미리보기.
