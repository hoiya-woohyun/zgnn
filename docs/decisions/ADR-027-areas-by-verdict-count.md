# ADR-027 — 지역은 추천이 아니라 판정 개수로 (문턱 전엔 '추천' 을 쓰지 않는다)

> 최종 수정: 2026-10-08 (v1: 신설 — [기획 토론 2026-10-08](../reviews/2026-10-08-region-pick.md) 의 결론을 오너가 승인했고 [todo/19](../todo/19-area-cards.md) T1~T4.1 이 들어갔다.
> 토론이 고른 모양과 버린 셋을 결정으로 남긴다)

## 상태

채택. 홈 6권역 카드·권역 셈·`pnpm data coverage` 는 코드에 있다([features/area-cards](../features/area-cards.md)). 카드의 자리·문구는 임시안.
라벨(결정 3)은 문턱 판정(2026-10-22) 전이라 **없다**.

## 맥락

오너의 가제는 "오늘 가고 싶은 지역" — 지역을 고르면 가는 길의 카페·숙소를 일자별·지역별로 **추천**하는 기능이었다. 세 갈래(경유 카페 · 지역별 추천 · 일자별 추천)를
사실 묶음과 페르소나 셋으로 따져 보니, 걸리는 것은 기능이 아니라 **데이터가 말할 수 있는 범위**였다.

- 게시 84곳을 6권역 × 강아지 원형 셋으로 판정하면 소형견·다견은 숙소+카페 12칸 중 11칸이 차지만, 30kg 대형견은 숙소가 권역마다 0~1곳이고 식당은 누구에게나 구멍이다.
  0인 칸 대부분은 '그 동네에 없다' 가 아니라 **'우리가 아직 덜 모았다'** 다 — 검수 대기 후보만 99곳이다.
- 코스 생성·지역 추천은 이미 붐빈다(반려생활·네이버 AI탭·지자체 앱). 못 찾은 한 칸은 **"내 강아지 조건으로 거른 동네 묶음"** 이다.
- '추천' 은 고른 사람이 보증한다는 말이다. 0곳을 '없음' 으로, 1곳을 '추천' 으로 말하면 판정 앱이 가장 비싼 실수 — **지어낸 확신** — 를 지역 단위로 하게 된다.

## 결정

### 1. 지역은 판정으로 센 개수로 보여 준다

홈 「지역으로 찾기」 자리에 6권역 카드를 두고, 카드마다 "{이름}랑 **묵을 곳 n · 카페 n**". 셈은 홈 히어로와 **같은 함수**(`countByLevel` 의 ok + 야외)이고,
카드를 누르면 열리는 목록도 같은 술어(`isReachable`)로 거른다 — 홈 N · 카드 n · 목록 수가 한 집합이다. 새 경로·탭은 만들지 않는다(둘러보기가 이미 그 화면이다).

### 2. 0칸은 '모른다' 와 '어렵다' 를 가르고, "없어요" 를 쓰지 않는다

분모(그 권역에 모은 숙소 수)와 주어("저희가 모은")로 말한다. 적게 모았으면 '모른다' + 장소 제안, 모았는데 0이면 "m곳 중 0곳". 0인 카드도 숨기지 않는다 —
숨기면 사용자는 그 동네가 원래 없는 줄 안다.

### 3. '추천'·'가기 좋은 곳' 은 데이터 문턱을 넘은 칸에만

라벨은 권역 × 종류 칸이 [19 §4](../todo/19-area-cards.md) 의 문턱(소형견 숙소·카페 12칸 중 '갈 수 있어요(+야외)' ≥3곳 칸 10 · 다견 8 · 대형견 숙소 ≥2곳 권역 4/6)을
넘을 때만 단다. 문턱 판정은 `pnpm data coverage` 출력이 정본이고, 넘기 전엔 라벨 태스크를 대기열에 올리지 않는다.

### 4. 식당은 머리 숫자에 넣지 않는다

대부분 '확인이 필요해요' 인데 전화번호가 없다. 세면 보증처럼 읽힌다. 둘러보기 식당 탭은 그대로다.

### 5. 권역은 비퍼시스트 조건이다

읍면(퍼시스트)이 홈에서 걸려 카페 탭·다음 방문까지 새던 문제 때문에 홈은 퍼시스트 필터를 걸지 않는다(18 T2). 권역도 검색어처럼 그 방문에만 산다.

### 버린 것

| 안 | 버린 이유 |
|---|---|
| 가는 길 경유 카페 | 준비 때 '이동 거리' 를 고려하는 반려 여행자 11.7%(지역 중 최저) · 경로 API 를 안 들인다(ADR-026) · 대형견이 갈 수 있는 카페는 권역마다 0~1곳 |
| 일자별 자동 추천 | 저장하지 않은 곳은 일정에 넣지 않는다(ADR-026 결정 1) · 숙소 0 권역을 고른 날은 시작점이 없다. 일자는 사용자가 하루 동선(16)에서 단다 |
| 새 「동네」 화면(권역끼리 나란히) | 둘러보기와 겹친다. 홈 안의 카드 여섯 장이면 나란히 비교가 된다. 권역별 정적 페이지는 정량 go(19 §4) 뒤 — 검색 유입 입구로서 값이 있을 때 |
| 관광지 칩 그대로(27개) | 칩 하나씩으론 권역끼리 비교가 안 되고, 11개는 세 종류 모두 0곳이었다(빈 상태가 "띄어쓰기를 바꿔 보세요" 를 말했다) |
| 0곳 카드 숨기기 | 0이 '모른다' 인 칸을 '없다' 로 만든다 |

## 결과

- 얻은 것: 홈에서 "이 아이랑 어느 동네" 에 답이 생겼다. 셈 함수가 그대로 **검수 순서표**(`pnpm data coverage` — 숙소 0 권역 먼저)이자 나중의 공백 표다.
- 잃은 것: '추천' 이 주는 확신의 말투. 문턱 전까지 카드는 숫자만 말한다.
- 되돌리는 조건(19 §4): 출하 뒤 주간 평가 두 회차에서 카드에서 막힌 평가자 ≥2, 또는 0칸을 "제주엔 갈 곳이 없다" 로 읽은 평가자 ≥2/6 이면 관광지 칩으로 되돌린다.
  정량 go/kill 은 애널리틱스를 들였을 때만(19 §5 🙋).
